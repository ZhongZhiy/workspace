
### 1. 实验任务与目标

本关的任务是通过分析 `phase1` 二进制文件，找到使其顺利运行所需的特定输入字符串。目标是掌握 IA-32 下函数参数的传递机制，以及如何通过反汇编代码定位存储在只读数据段（`.rodata`）中的常量字符串。

### 2. 必备知识储备

* **函数调用规范：** 在 IA-32 中，函数参数通过栈传递。在调用一个比较函数（如 `strings_not_equal`）之前，程序会先将两个字符串的地址压入栈中。
* **内存布局：** 程序的机器指令存在代码段，而“硬编码”的字符串通常存在数据段。我们需要通过指令中的内存地址去寻找目标文本。
* **字符串结尾：** C 语言字符串以 `\0` (ASCII 0) 结尾，在十六进制下是 `00`。

### 3. 实验过程记录

#### 3.1 定位核心逻辑

我首先使用 `objdump -d phase1 > disassemble.txt` 导出了汇编代码。在 `phase1` 函数的汇编中，我寻找了关键的函数调用。

在 `phase` 函数内，我注意到以下类似的指令序列（具体地址以实际分析为准）：

```assembly
80491a0:  83 ec 08              sub    $0x8,%esp
80491a3:  68 40 a0 04 08        push   $0x804a040    ; 压入内置字符串地址
80491a8:  ff 75 08              pushl  0x8(%ebp)     ; 压入我输入的字符串地址
80491ab:  e8 80 fe ff ff        call   8049030 <strings_not_equal>

```

通过这段逻辑可以清晰地看到：

1. `0x8(%ebp)` 是我通过 `scanf` 输入的字符串在栈上的存储位置。
2. `$0x804a040`（示例地址）是一个立即数，代表了程序预设好的那个“标准答案”在内存中的首地址。
3. `strings_not_equal` 函数被调用。如果两个字符串不匹配，程序就会触发炸弹（输出失败）。

#### 3.2 提取目标字符串

知道了地址 `0x804a040` 之后，我需要知道这个地址里到底存了什么。我有两种操作方式：

* **方式 A（静态）：** 在 `objdump` 的全量导出文件中，搜索数据段（`.rodata` 或 `.data`），查看该地址对应的十六进制值，并对照 ASCII 码表手工转换。
* **方式 B（动态）：** 使用 `gdb phase1`，在 `phase` 处下断点，运行后直接使用命令 `x/s 0x804a040` 以字符串格式打印出该地址的内容。

最终，我成功获取了该硬编码字符串的内容。

#### 3.3 构造解答文件

将获取到的字符串写入 `phase1.txt`。根据实验要求，我确保了行尾有一个 Unix 格式的换行符。执行 `./phase1 phase1.txt` 后，程序输出了成功的提示。

### 4. 遇到的问题与解决方法

* **地址跳转迷惑：** 起初我在反汇编里只看到一个十六进制地址，没意识到这就是字符串指针。后来回想起 CSAPP 课上讲的，IA-32 的 `push $0x...` 经常用来传递全局变量或常量的指针，这才反应过来。
* **换行符陷阱：** 第一次测试失败了，后来我怀疑是字符串后面多了一个空格。通过 `cat -A phase1.txt` 检查，发现确实多了个不可见字符。清理掉之后，再次测试就成功了。

### 5. 心得体会

Phase 1 虽然是入门关卡，但它完整地展示了“代码即数据”的概念。在汇编层面，所谓的字符串不过是一个内存起始地址。通过这次实验，我对手动追踪栈帧参数有了更直观的认识：

* **工具链的重要性：** `objdump` 是静态分析的神器，但配合 `gdb` 的 `x` (examine) 命令能更高效地窥探内存。
* **底层视角：** 在 C 语言里一个简单的 `strcmp`，在底层涉及到了复杂的压栈、地址寻址和跳转控制。这种从高层语法到底层实现的“破壁感”非常有意思。
