这份日志非常关键，直接抓到了你电脑在底层卡死的**真凶**！

诊断结论非常明确：**这是你笔记本电脑 BIOS 的 ACPI 固件代码存在 Bug，导致合盖/开盖时 Embedded Controller（嵌入式控制器）崩溃，从而锁死显卡与显示器上电。**

## 核心日志解读（抓住抓贼的现行）

关键看这两行报错：

Plaintext

```
ACPI Error: Aborting method \_SB.ALIB due to previous error (AE_AML_BUFFER_LIMIT)
ACPI Error: Aborting method \_SB.PCI0.LPC0.EC0._Q93 due to previous error (AE_AML_BUFFER_LIMIT)
```

1. **`EC0._Q93`**：在笔记本中，`EC0`（Embedded Controller）负责管理物理硬件信号，而 `_Q93` 是厂商写的 **“合盖/开盖” 或 “电源插拔”** 的硬件中断处理函数。
    
2. **`ALIB`**：这是 **AMD 官方的 ACPI 接口库**，负责在硬件层面协调 AMD 核显与 CPU 的功耗与显示切换。
    
3. **`AE_AML_BUFFER_LIMIT`**：Linux 内核执行 BIOS 里的脚本时，发现 BIOS 写的代码企图读取超出范围的内存数据（`Index 0x12 is beyond end of object`），**直接触发越界错误导致脚本中断**。
    

**发生了什么：**

当你合盖或开盖时，硬件触发了 `_Q93` 函数，但因为 BIOS 写的代码有 Bug，Linux 内核在解析它时直接中断退出了。**这导致 AMD 核显没能接收到完整的“重新上电/唤醒”指令**，处于一种“半死不活”的状态（主板和键盘灯在通电，但显示接口无输出，内核死锁导致切 TTY 也失效）。

至于日志里的其他几行（如 `nvidia_uvm` 找不着、蓝牙 `Host is down`、`Portal` 启动失败），都是无关紧要的次要报错或噪声，不用理会。

## 解决方案

既然确定了是 BIOS 的 ACPI 固件缺陷，请按照以下方案修复：

### 方案一：更新笔记本 BIOS（最根本的解决方法）

厂商通常会在后续的 BIOS 更新中修复 Linux/Windows 下的 ACPI AML 越界 Bug。

- 去你的笔记本品牌官网（如联想、华硕、ThinkPad 等），下载并**升级到最新的 BIOS 版本**。
    

### 方案二：欺骗 BIOS（伪装 Windows 环境）

BIOS 里的很多 ACPI 代码是厂商专为 Windows 写的，在 Linux 下可能会走入有 Bug 的分支。我们可以向内核传递参数，让 BIOS 以为当前运行的是 Windows 11：

1. 编辑你的 Bootloader 配置（以 GRUB 为例，如果是 systemd-boot 请修改 `/boot/loader/entries/arch.conf` 的 `options`）：
    
    Bash
    
    ```
    sudo nano /etc/default/grub
    ```
    
2. 在 `GRUB_CMDLINE_LINUX_DEFAULT="..."` 中加入：
    
    Plaintext
    
    ```
    acpi_osi="Windows 2021"
    ```
    
    _(如果无效，也可以尝试 `acpi_osi=Linux`)_
    
3. 更新 GRUB 配置并重启：
    
    Bash
    
    ```
    sudo grub-mkconfig -o /boot/grub/grub.cfg
    sudo reboot
    ```
    

### 方案三：完全绕过 ACPI 合盖唤醒事件（救急避坑）

如果你不方便升级 BIOS，可以让 Linux 彻底忽略 BIOS 送来的这个坏掉的合盖信号，改由软件逻辑接管：

1. 修改 systemd 的 logind 配置：
    
    Bash
    
    ```
    sudo nano /etc/systemd/logind.conf
    ```
    
2. 确保将合盖行为全部忽略（防止触发 BIOS 中坏掉的 `_Q93` 挂起逻辑）：
    
    Ini, TOML
    
    ```
    HandleLidSwitch=ignore
    HandleLidSwitchExternalPower=ignore
    HandleLidSwitchDocked=ignore
    ```
    
3. 重启 logind 或直接 reboot：
    
    Bash
    
    ```
    sudo systemctl restart systemd-logind
    ```
    

设置好后，合盖将不会强制触发底层的 ACPI 挂起，屏幕会交给 `hypridle` 正常熄灭/锁屏，彻底避免触发那个会崩溃的 BIOS 函数。
既然厂商没有修复这个硬件脚本，我们直接在 Linux 软件层面**彻底绕过这个有 Bug 的 BIOS 脚本**即可。

### 解决方案：屏蔽底层的 ACPI 合盖事件（30秒完成）

只要阻止系统在合盖时调用主板上那个坏掉的 `_Q93` 处理函数，电脑就再也不会发生黑屏卡死。

#### 操作步骤：

1. 打开终端，修改 systemd 的电源管理配置文件：
    
    Bash
    
    ```
    sudo nano /etc/systemd/logind.conf
    ```
    
2. 在文件中找到以下几行（如果是 `#` 开头的说明被注释了），将其修改或直接在文件末尾追加：
    
    Ini, TOML
    
    ```
    HandleLidSwitch=ignore
    HandleLidSwitchExternalPower=ignore
    HandleLidSwitchDocked=ignore
    ```
    
3. 按 `Ctrl + O` 保存，按回车确认，再按 `Ctrl + X` 退出编辑器。
    
4. 运行以下命令让配置立即生效：
    
    Bash
    
    ```
    sudo systemctl restart systemd-logind
    ```
    

### 修改后的实际效果：

- **合盖时**：系统不会再触发底层崩溃的 ACPI 休眠，而是交由 Hyprland 的 `hypridle` 自动锁屏和关屏（没有任何驱动或物理卡死风险）。
    
- **开盖时**：屏幕迅速点亮，直接显示锁屏界面，键盘打字解锁即可，**彻底解决卡死黑屏问题**。
