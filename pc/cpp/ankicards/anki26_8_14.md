## [E - Unbalanced ABC Substrings](https://atcoder.jp/contests/abc455/tasks/abc455_e)

### 题目描述  

给定一个长度为 $N$ 的字符串 $S$，仅由字符 `A`、`B` 和 `C` 构成。  
$S$ 共有 $\frac{N(N+1)} {2}$ 个非空子串；请计算其中满足以下条件的子串数量：

-   子串中 `A`、`B`、`C` 的出现次数两两互不相同。

即使两个子串作为字符串内容相同，只要它们在 $S$ 中的位置不同，就视为不同的子串分别计数。

什么是子串？$S$ 的一个**子串**是指通过从 $S$ 开头删除零个或多个字符、从结尾删除零个或多个字符得到的字符串。例如，`AB` 是 `ABC` 的子串，但 `AC` 不是 `ABC` 的子串。

### Constraints

-   $1 \leq N \leq 2 \times 10^5$
-   $|S|=N$
-   $N$ is an integer.
-   $S$ is a string consisting of the three characters `A`, `B`, and `C`.

---
这是一道极其优美且经典的“正难则反” + 容斥原理（PIE）的字符串计数问题。

如果在考场上，你的第一反应是尝试用双指针或者滑动窗口去直接寻找“满足三个数量互不相同”的区间，你会发现窗口没有任何单调性（字符出现次数是交替上升的），几乎无法维护。


___

### 🧠 核心降维推导：容斥原理与前缀和差分

题目要求：子串中 `A`、`B`、`C` 的数量互不相同。即：


$$\text{Count}(A) \neq \text{Count}(B) \land \text{Count}(B) \neq \text{Count}(C) \land \text{Count}(C) \neq \text{Count}(A)$$

**破局点 1：正难则反（容斥原理）**
直接求“三者互不相等”非常困难，但求“某两者相等”却很容易。我们把问题反转，用总子串数减去“不合法”的子串数。
根据容斥原理，所有合法的子串数等于：


$$\text{Total} - (\text{A=B}) - (\text{B=C}) - (\text{C=A}) + 2 \times (\text{A=B=C})$$


*注：当 A=B 且 B=C 时，C=A 必然成立。所以在减去前三个集合时，A=B=C 的情况被减去了 3 次，我们要把它加 2 次补回来。*

**破局点 2：隐蔽的陷阱（0 也是数量）**
很多选手会漏算一种情况：比如子串 `"A"`，它的统计是 `A=1, B=0, C=0`。此时 B 和 C 的数量都是 0，属于 $\text{B=C}$ 的不合法情况！这套容斥模型完美且无差别地处理了 0 的情况。

**破局点 3：用前缀和差分把 $O(N^2)$ 降维到 $O(N)$**
怎么快速求有多少个子串满足 $\text{Count}(A) = \text{Count}(B)$？
我们维护 $A$ 和 $B$ 的前缀和数组 $P_A$ 和 $P_B$。
对于子串 $S[l \dots r]$，如果 $\text{Count}(A) = \text{Count}(B)$，意味着：


$$P_A[r] - P_A[l-1] = P_B[r] - P_B[l-1]$$


移项后得到绝对真理：


$$P_A[r] - P_B[r] = P_A[l-1] - P_B[l-1]$$


这意味着，我们只需要记录每一位的“前缀差值”，如果某两个位置（$l-1$ 和 $r$）的**前缀差值完全相同**，它们就能构成一个合法的子串！

---

### 💻 工业级 $O(N \log N)$ 满分代码

我们将 `A-B`, `B-C`, `C-A` 的差值转化为数组，统计相同差值出现的频次，利用排列组合 $\binom{k}{2}$ 瞬间求出答案。其中 `A=B=C` 的情况只需要统计二元组 `(A-B, B-C)` 的出现频次即可。

```cpp
void solve(){
    int n; cin >> n;
    string s; cin >> s;
    s = "a"+ s;

    vector<vi> p(3, vi(n + 1));

    fi(n){
        int ch = s[i] - 'A';
        for(int j = 0;j < 3; ++j) p[j][i] = p[j][i-1] + (ch == j);
    }

    vector<vi> d(3, vi(n + 1));

    for(int j = 0;j < 3; ++j){
        for(int k = j+1;k < 3; ++k){
            for(int i = 0;i <= n; ++i){
                d[k+j-1][i] = p[j][i]-p[k][i];
            }
        }
    }

    int cnt = n*(n+1)/2;
    for(int j = 0;j < 3; ++j){
        for(int k = j + 1; k < 3; ++k){
            map<int, int> mp;
            for(int i = 0;i <= n; ++i){
                cnt -= mp[d[k+j-1][i]];
                mp[d[k+j-1][i]]++;
            }
        }
    }

    map<pii, int> mp;
    for(int i = 0;i <= n; ++i){
        cnt += 2 * mp[{d[0][i], d[2][i]}];
        mp[{d[0][i], d[2][i]}]++;
    }
    cout << cnt << endl;
}
```






## [前缀表] 
### 变形 1：区间和等于特定值 $K$（基础变形）

**题目特征**：求有多少个子区间的和恰好为 $K$。

---
**降维推导**：

* 区间和公式：$P[R] - P[L-1] = K$
* **状态分离（移项）**：$P[L-1] = P[R] - K$
**工业解法**：
从左到右遍历数组，用一个 Hash 表记录每个前缀和出现的次数。当遍历到 $R$ 时，直接去 Hash 表里查：**过去有多少个前缀和等于 $P[R] - K$？** 查到的数量直接累加到答案里。

## [前缀表] 
### 变形 2：两种元素数量相等（权重映射法）

**题目特征**：一个数组只有 0 和 1（或男和女），求 0 和 1 数量相等的子区间个数。

---
**降维推导**：

* 如果你直接分别维护 0 的前缀和 1 的前缀，就会变成刚才那道题（解方程求差值）。
* **更高级的魔法（权重映射）**：把所有的 0 强行视为 **-1**，把所有的 1 视为 **1**。
* “0 和 1 数量相等” 瞬间等价于 **“区间和等于 0”**！
* 状态分离：$P[R] - P[L-1] = 0 \implies P[R] = P[L-1]$。
**工业解法**：
直接维护新数组的前缀和，如果当前前缀和的值在以前出现过，出现的次数就是合法的区间个数。


## [前缀表] 
### 变形 3：区间和是 $K$ 的倍数（同余定理映射）

**题目特征**：求有多少个子区间的和，能被 $K$ 整除。

---
**降维推导**：

* 数学表达：$(P[R] - P[L-1]) \pmod K = 0$
* **状态分离（同余性质）**：$P[R] \pmod K = P[L-1] \pmod K$
**工业解法**：
维护前缀和时，每次对 $K$ 取模（注意 C++ 中负数取模的坑，通常写成 `(P % K + K) % K`）。如果两个位置的前缀和取模后余数相同，它们中间的这一段区间和必然是 $K$ 的倍数！直接用一个大小为 $K$ 的数组统计每种余数出现的频次即可。

## [前缀表] 
### 变形 4：异或和等于 $K$（位运算映射）

**题目特征**：求有多少个子区间的异或和（XOR）等于 $K$。

---
**降维推导**：

* 异或的前缀和性质：$XorP[R] \oplus XorP[L-1] = K$
* **状态分离（异或的逆运算就是它自己）**：两边同时异或 $XorP[R]$，得到 $XorP[L-1] = K \oplus XorP[R]$
**工业解法**：
完全等同于变形 1，只是把普通的加减法换成了异或。用 Hash 表记录前缀异或和的频次，每次查询 $K \oplus XorP[R]$ 的出现次数。

## [前缀表] 
### 变形 5：重排后能否形成回文串（状态压缩极致）

**题目特征**：给定一个只包含小写字母的字符串，求有多少个子串，其字符重新排列后可以形成一个回文串。

---
**降维推导**：

* “能形成回文串”的物理意义：最多只有一种字符出现了奇数次，其余所有字符都必须出现偶数次。
* 只有 26 个字母，我们用一个 26 位的二进制数（整型）作为 **Mask（掩码）**。第 $i$ 位为 1 表示第 $i$ 个字母出现了奇数次，为 0 表示偶数次。
* 区间掩码公式：$Mask[R] \oplus Mask[L-1] = \text{Target}$
* 要形成回文串，Target 必须是 0（所有字母都是偶数次）或者 $2^k$（只有第 $k$ 个字母是奇数次，二进制只有一位是 1）。
**工业解法**：
遍历字符串，不断更新当前的前缀 Mask。
当处于 $R$ 时，答案加上历史中 $Mask[L-1] == Mask[R]$ 的次数，然后再枚举 26 个字母，加上历史中 $Mask[L-1] == Mask[R] \oplus (1 \ll k)$ 的次数。

当你以后在题目中看到以下几个关键字组合：

1. **“求子区间 / 子串个数”**
2. **“满足某种代数关系（相等、倍数、异或、计数等）”**

立刻在脑海中执行这两步：

---

* **第一步：写出 $P[R]$ 和 $P[L-1]$ 混合的等式。**
* **第二步：利用移项、同余、或异或，强行把等式变成 `P[L-1] = f(P[R])` 的形式。**
只要能分离，这道题的复杂度就一定能被你用“前缀 Hash 查表法”从 $O(N^2)$ 锤到 $O(N)$。

## [石子合并]

$n$ 个石子排成一行, 每次合并相邻的石子的代价为 $x \times y + x + y$ , 合并后石子大小为 $x+y$ 求最小合并代价?

---

## [D - Concat Power of 2](https://atcoder.jp/contests/abc451/tasks/abc451_d)

### 题目描述

我们称一个正整数为**好整数**，当它满足以下条件：

-   条件：可以通过选取一个或多个 $2$ 的幂（$1, 2, 4, 8, 16, \dots$）（允许重复和重新排列），将它们作为字符串拼接起来，并将结果解释为一个整数而得到。

请找出第 $N$ 小的好整数。保证第 $N$ 小的好整数不超过 $10^9$。

### Constraints

-   $N$ is a positive integer.
-   The $N$\-th smallest good integer is at most $10^9$.

---
这道题有个限制, 答案不超过 $10^9$, 那么字符串最长为 $9$, 

估算暴力枚举的时间复杂度:



### 第一步：清点我们的“积木”库存

我们要拼凑数字，首先得盘点我们手里有哪些“积木”（不超过 9 位的 $2$ 的幂），以及它们各自的**字符串长度**：

* **长度 1：** 1, 2, 4, 8（共 **4** 个）
* **长度 2：** 16, 32, 64（共 **3** 个）
* **长度 3：** 128, 256, 512（共 **3** 个）
* **长度 4：** 1024, 2048, 4096, 8192（共 **4** 个）
* **长度 5：** 16384, 32768, 65536（共 **3** 个）
* **长度 6：** 131072, 262144, 524288（共 **3** 个）
* **长度 7：** 1048576, 2097152, 4194304, 8388608（共 **4** 个）
* **长度 8：** 16777216, 33554432, 67108864（共 **3** 个）
* **长度 9：** 134217728, 268435456, 536870912（共 **3** 个）

（共计 30 个“积木”）

___

### 第二步：建立递推模型（状态树展开）

我们设 $dp[i]$ 表示：**拼凑出长度刚好为 $i$ 的字符串，有多少种不同的拼法。**
*注：这里的 $dp$ 只是为了我们在草稿纸上估算数量，不代表我们要用它写代码。*

显然，初始状态 $dp[0] = 1$（空字符串，只有 1 种情况，作为起步地基）。

接下来，长度为 $i$ 的字符串怎么拼出来？它可以由“长度为 $i-1$ 的串加上一个长度为 1 的积木”、“长度为 $i-2$ 的串加上一个长度为 2 的积木”……以此类推组合而成。

我们直接在草稿纸上列出硬核的计算过程：

* **长度 1：** $dp[1] = dp[0] \times 4 = 1 \times 4 =$ **4** 种
* **长度 2：** $dp[2] = dp[1] \times 4 + dp[0] \times 3 = 4 \times 4 + 1 \times 3 =$ **19** 种
* **长度 3：** $dp[3] = dp[2] \times 4 + dp[1] \times 3 + dp[0] \times 3 = 19 \times 4 + 4 \times 3 + 1 \times 3 =$ **91** 种
* **长度 4：** $dp[4] = dp[3] \times 4 + dp[2] \times 3 + dp[1] \times 3 + dp[0] \times 4 = 91 \times 4 + \dots =$ **437** 种
* **长度 5：** $dp[5] = dp[4] \times 4 + dp[3] \times 3 + \dots =$ **2097** 种
* **长度 6：** $dp[6] = dp[5] \times 4 + dp[4] \times 3 + \dots =$ **10063** 种
* **长度 7：** $dp[7] = dp[6] \times 4 + dp[5] \times 3 + \dots =$ **48291** 种
* **长度 8：** $dp[8] = dp[7] \times 4 + dp[6] \times 3 + \dots =$ **231741** 种
* **长度 9：** $dp[9] = dp[8] \times 4 + dp[7] \times 3 + \dots =$ **1112089** 种

___

### 第三步：得出最终结论

DFS 在执行时，会完整遍历上述所有的有效组合。因此，状态树上**生成的所有答案数量**，就是拼凑出长度从 1 到 9 的所有方案数的总和：

$$Sum = dp[1] + dp[2] + dp[3] + \dots + dp[9]$$

$$Sum = 4 + 19 + 91 + 437 + 2097 + 10063 + 48291 + 231741 + 1112089 = 1404832$$

**结论：** 无论 DFS 怎么满负荷跑，它最多只会生成 **1,404,832** 个数字。

在现代 C++ 编译器（如 GCC）中，基本的算术和字符串拼接操作，1 秒钟可以轻松处理一亿次（$10^8$）。区区 140 万次操作，耗时大约在 **0.05 秒** 左右，即使加上后面的 `sort` 排序时间，也绝对在一瞬间就能秒杀，根本连时间限制（Time Limit）的边都摸不到。

正是因为我们在脑子里或者草稿纸上快速完成了这套“递推估算”，我们才敢在考场上无比自信地放弃复杂的 DP 或二分，直接敲下 DFS 暴力的代码


## [M. KV Cache](https://ac.nowcoder.com/acm/contest/133883/E)

大豆正在运营一项大语言模型服务。为了避免为不同请求重复计算相同的前缀，该服务维护了一个持久化 $KV$ 缓存。

每个请求均由一个小写拉丁字母串表示，其中每个字母代表一个词元。具有公共前缀的请求可以共享 $KV$ 缓存项。我们将缓存中的当前内容建模为一棵字典树。

最初，字典树中只有根节点，没有任何边。

处理请求字符串 $s$ 时，会依次执行以下操作：

1. 大豆从字典树的根节点开始，自左向右处理整个字符串。
2. 如果对应于下一个词元的边已经存在，则可以零代价复用其缓存结果。
3. 否则，大豆必须计算对应的 $KV$ 状态。这会消耗 $1$ 单位计算量，同时字典树中会加入缺失的边。
在移除任何缓存项之前，会先处理完整个请求。特别地，请求中所有缺失的边都会先被加入，即使这会使字典树中的边数暂时超过 $m$。

处理完整个请求后，大豆会应用持久化缓存的容量限制。如果字典树中的边数超过 $m$，他必须反复删除 一个叶节点以及连接该节点与其父节点的边，直到恰好剩下 $m$ 条边。叶节点是当前字典树中没有子节点 的节点。处理当前请求时加入的边也可能在此步骤中被删除。

大豆预先知道由全部 $n$ 个请求构成的序列。每次进行删减时，他都可以自行选择要删除哪些与叶节点相连的边。

请确定处理所有 $n$ 个请求所需的最小总计算代价。

字典树是一种以有根树形式存储字符串集合的数据结构。这棵树具有如下结构：树的每条边都标有一个
字母，从同一节点出发的任意两条边所标的字母均不相同。沿着从根节点到某个节点的一条路径行走，即
可读出一个字符串。

**Input**

每个测试的第一行包含两个整数 $n$ 和 $m$ $(1 ≤ n ≤ 10^6 ，1 ≤ m ≤ 10^9)$。

每个测试接下来的各行依次编号；其中第 $i$ 行（共 $n$ 行）包含一个字符串 $s_i$ ”— 第 $i$ 个请求中的词元序列。保证 $s_i$ 仅由小写拉丁字母组成。保证所有 $|s_i|$ 之和不超过 $10^6$ 。

**Output**

输出一个整数”— 处理所有 $n$ 个请求所需的最小总计算代价。

**Example**

**standard input**
```
4 4
mini
trie
task
min
```

**standard output**
```
11
```

---

这是一道非常精彩的**贪心策略与数据结构结合**的题目。初看时，你可能会觉得在字典树上做缓存替换非常复杂，因为似乎需要时刻维护树的连通性（即不能出现“子节点保留在缓存中，但父节点被踢出”的非法情况）。但只要看透其本质，这其实是一个经典的**离线缓存淘汰模型**。

以下是为你拆解的详细解法与核心思路：

### 1. 核心洞察：转化为“页面置换算法”

题目要求我们在已知所有未来请求 $s_i$ 的前提下，利用容量上限为 **m** 的缓存（也就是最多保留 **m** 条边），求出最小的计算总代价。每次遇到不在缓存中的边，代价加 **1**。

由于我们具备“预知未来”的能力，这完全对应了操作系统中经典的**离线缓存淘汰问题**。对于这类问题，理论上已被证明的最优策略是**Belady的OPT算法（最佳置换算法）**：

> **核心原则**：当缓存满时，永远优先淘汰**在未来最晚被访问到**的那个元素。

### 2. 关键疑问：Belady算法会破坏树结构吗？

在普通数组上做缓存淘汰很简单，但在树结构上，如果优先淘汰的边是一个父节点，那不就出现断层了吗？

**答案是：绝对不会，只要配合正确的“平局打破机制”。**

* **天然的时间约束**：在访问任何一个子节点对应的边之前，必然会先经过它的父节点。因此，父节点的“下一次访问时间”永远 **小于等于** 子节点的“下一次访问时间”。
* **关键的平局打破（Tie-breaking）**：当两个节点的下一次访问时间相同时（比如两者以后再也不会被访问了，下一次时间都是 $\infty$；或者它们将在同一个未来的字符串 $s_k$ 中被访问），我们**必须优先淘汰深度（Depth）更大的节点**。

因为子节点的深度永远大于父节点，加入这个规则后，最先被淘汰的永远是当前缓存树中的**叶子节点**，这完美符合题目要求的“每次只能删掉叶子边”的规则！

___

### 3. 算法具体流程

基于以上推导，我们可以将算法拆分为以下清晰的步骤：

### 第一步：构建全局字典树与预处理

1. 将所有的 **n** 个字符串插入到一棵全局字典树（Trie）中。
2. 为除根节点外的每个节点（代表连向它父节点的那条边）分配唯一的 `node_id`，并记录它的**深度（Depth）**。
3. 模拟一次完整遍历，记录每个 `node_id` 被访问的请求次序。你可以用一个列表 `access_times[node_id]` 来按顺序存储该节点在哪些请求中被访问到了。

### 第二步：利用优先队列模拟缓存

1. 准备一个大根堆（优先队列 Max-Heap），用于挑选要淘汰的节点。堆中存储的三元组格式为：`(下一次访问时间, 节点深度, node_id)`。
2. 准备一个布尔数组 `in_cache[]`，用于标记某个节点当前是否在缓存中。
3. 维护当前的缓存边数 `cache_size`。

### 第三步：按顺序处理所有请求

对于每一个请求 $s_i$：

1. **加载所需节点**：顺着字典树往下走，遍历该请求对应的所有边（节点）。
* 如果边不在缓存中（`in_cache` 为假）：计算代价 `cost++`，将其标记为加入缓存，并让 `cache_size++`。
* **更新未来预期**：将该节点在 `access_times` 里的指针向后移动一位，获取它未来的**下一次访问时间**（如果没有下一次了，设为 $\infty$）。
* 将更新后的三元组 `(下一次访问时间, 节点深度, node_id)` 推入大根堆中。


2. **执行容量淘汰**：整个 $s_i$ 加载完毕后，如果当前 `cache_size` 大于 **m**，则需要淘汰多余的边直到刚好等于 **m**。
* 不断从大根堆中弹出顶部元素（即未来最晚被访问、深度最大的节点）。
* **注意延迟删除（Lazy Deletion）**：由于同一个节点在被多次访问时会被多次推入堆中，弹出的记录可能是过期的。你需要核对该弹出的记录是否等于该节点真实的“下一次访问时间”。如果是过期数据则直接丢弃；如果是有效数据，将其 `in_cache` 置为假，并 `cache_size--`。



___

### 4. 复杂度分析

* **时间复杂度**：构建字典树和预处理访问列表的时间为 $O(L)$，其中 $L$ 为所有请求字符串长度的总和（$L \le$ **10^6**）。在模拟过程中，每条边最多被推入和弹出优先队列 $O(L)$ 次。单次堆操作的时间复杂度为 $O(\log L)$。因此，总时间复杂度为 $O(L \log L)$，在百万级别的数据规模下可以轻松通过测试。
* **空间复杂度**：全局字典树最多有 $L$ 个节点，维护的访问时间列表总长度也为 $L$，优先队列的最大规模不会超过 $L$。总空间复杂度为 $O(L)$，非常高效。

通过这种将“树上动态修建”转化为“带特定排序规则的页面淘汰”的视角，这道看似繁琐的题目就变成了一道逻辑非常严密、代码实现也极其标准的经典算法题。
```cpp
constexpr int N = 1e6+10;
int trie[N][26], tot = 1;

void insert(const string &s){
    int len = s.size(), p = 1;
    for(int k = 0; k < len; ++k){
        int ch = s[k] - 'a';
        if(trie[p][ch] == 0) trie[p][ch] = ++tot;
        p = trie[p][ch];
    }
}

void solve(){
    int n, m; cin >> n >> m;
    vector<string> a(n);
    fi0(n){
        cin >> a[i];
        insert(a[i]); //给每个节点一个 id
    }

    vector<vi> access_time(tot+10);
    vector<int> dep(tot+10);
    //给每个节点一个访问时间列表, 同时记录深度
    auto get_acc = [&](const string &s, int i)->void{
        int len = s.size(), p = 1;
        for(int k = 0;k < len; ++k){
            int ch = s[k]-'a';
            p = trie[p][ch];
            access_time[p].push_back(i);
            dep[p] = k;
        }
    };

    fi0(n){ //给每个节点一个访问时间列表, 同时记录深度
        get_acc(a[i], i);
    }

    vector<bool> in_cache(tot+10); //记录在树上
    struct Node{
        int nx, id, dep;
        Node(){}
        Node(int nx, int id, int dep):nx(nx), id(id), dep(dep){}
        bool operator < (const Node& a)const{ //注意深度
            if(nx == a.nx) return dep < a.dep;
            return nx < a.nx;
        }
    };
    vector<int> ex_time(tot+10); //记录存在时间, 否则弹出的点可能早就更新了
    priority_queue<Node> pq;
    int cur_sz = 0;
    int cost = 0;
    fi0(n){

        int len = a[i].size(), p = 1;
        for(int k = 0;k < len; ++k){
            p = trie[p][a[i][k]-'a']; //下个节点编号
            if(!in_cache[p]) cost++, in_cache[p] = 1, cur_sz++; //建立新边
            auto it = upper_bound(all(access_time[p]), i);  //找节点下个出现时间
            int nx_time = 0;
            if(it == access_time[p].end()) nx_time = LLONG_MAX;
            else nx_time = *it;
            ex_time[p] = nx_time;
            pq.push({nx_time, p, dep[p]});
        }

        while(cur_sz > m){
            auto [nx, id, dp] = pq.top(); pq.pop();
            if(in_cache[id] && ex_time[id] == nx) cur_sz--, in_cache[id] = 0;
        }
    }
    cout << cost << endl;
}
```
