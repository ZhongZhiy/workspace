# 基本原则

- 读题的成果通常是纯数学模型。如果背景故事有助于正确理解，可以保留，但仍要尽可能剔除不必要的细节。
- 设想你要向他人解释题目。你会重点介绍哪些部分？（根据我的项目经理经验，这条规则对你没用）。
- 越简短越好。
- 越简单越好。
- 数据限制是题面的一部分。尤其是小数据限制，因为小数据可以尝试所有可能性。
- 样例是题面的一部分。建立数学模型后，需验证模型在样例上运行正确，至少能在小样例上快速验证。
- 备注是题面的一部分。
- 尝试寻找熟悉模式，或许是你已知的对象。比如给定连通图且每对顶点间只有一条简单路径，这就是树。用4个字母代替12个词，明白吗？
- 更要努力发现异常之处，那些出乎意料的内容。这往往是题目的关键。
- 如果题面有你不喜欢的部分，尝试将其替换为喜欢的表述。先理解对象，再简化。有些问题可以完全用此技巧解决。
- 若得到的模型很庞大，尝试拆分成若干模块。如果模块能独立运作（如先解问题1，将其答案作为问题2的输入，依此类推）就更好了。
- 初期阶段手写新题面于纸上会很有帮助。
- 出题人不会在题面写无意义内容。但我是个糟糕的出题人，你凭什么相信我？不知道，或许你不该信。

[GOV实习2](http://acm.timus.ru/problem.aspx?space=1&num=1879)

**题面**

等等什么？距离之和？环形字符串？很难？但其实环形字符串更简单。尝试将距离之和转化为更优形式。我们比较字符对，不同时对和加1。哪些字符对？所有字符对。所有对仅一次。  
给定含空白的字符串，需填充空白使不同字符对数量最小。

**解法**

我们已基本解决。显然若仅一个字符串含空白，应全部填充为另一字符串的最频字符。推广到任意解：每个字符串的空白填充相同字符。若两字符串填充字符不同，应独立选择为对方字符串（除空白外）的最频字符；若相同，需枚举所有可能。

**题面**

现在可以讨论了。设第_i_个可访问环的完整旋转数为_x__i_（可负可非整）。设第_i_个受保护环的完整旋转数为_y__i_。![](https://espresso.codeforces.com/8b1f84c479797a57f18926685f82917987b06fd4.png)（或许是_A__ji_，不重要）。这就是矩阵乘向量。我们希望_x_非整数而_y_为整数。现在回去重读题面。

给定树，所有顶点初始白色。红蓝两方轮流将白顶点染为红/蓝色。无白顶点时游戏结束。分数为_C__R_ - _C__B_，其中_C__R_为红色连通分量数，_C__B_为蓝色连通分量数。红方最大化分数，蓝方最小化分数。求双方最优策略下的分数。_n_ ≤ 2·105。

**解法**

题面清晰，但不喜欢该公式。尤其不喜欢_C__i_，因其变化不可预测。删除树中部分顶点后的连通分量？它们自身是树。树的性质？顶点数比边数恰多1。故森林的连通分量数等于顶点数减边数。重写公式：_C__R_ - _C__B_ = (_V__R_ - _E__R_) - (_V__B_ - _E__B_) = _E__B_ - _E__R_ + (_V__R_ - _V__B_)。括号内为常数![](https://espresso.codeforces.com/5fe314a952f62e95cdcf9e105b83d9ef34efd6e6.png)。现在争夺目标从分量转为边。有改进但仍不显然。  
我们控制顶点，能否仅用顶点表示_E__i_？有通过顶点表示边数的等式吗？有。![](https://espresso.codeforces.com/ee4a81399d1595c183ee87ed37f65f27428a9b10.png)。但计算_E__R_只需累加红色邻边数_deg__R_(_v_)。这不好，但仍尝试。  
![](https://espresso.codeforces.com/bc8936d51dad876c65370d9348b5776152019a70.png)。成立，因所有红蓝边相互抵消。  
得分公式为![](https://espresso.codeforces.com/6238cd17e2d73d5e0ec2ed4af7348904c6485fa9.png)。  
易见每方应总选择当前可用度数最小的顶点。
