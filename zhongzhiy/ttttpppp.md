这道题是一道非常经典的**数据结构优化模拟题**。它表面上是在考矩阵操作，实际上考察的是**时序（时间戳）转化**与**动态维护区间计数**的能力。

下面我将为你全方位、一步一步地拆解这道题。

### 一、 这道题需要哪些知识点？

#### 核心知识点

- **树状数组 (Binary Indexed Tree / Fenwick Tree) 或 线段树 (Segment Tree)**：用于在 $O(\log Q)$ 的时间内完成“单点修改”和“区间和查询”。
    
- **时间戳思想 (Timestamping)**：将“覆盖操作”转化为“比较最后一次操作的时间先后”。
    
- **贡献法/增量思维 (Delta/Contribution Method)**：不盲目维护整个大矩阵，而是精准计算每一次操作带来的“黑色方块数量的变化量（$\Delta$）”。
    

#### 前置知识点

- 基本的数组操作与模拟。
    
- 树状数组的基础原理（能熟练写出 `add` 和 `query`）。
    
- **大整数存储**：网格最大为 $3 \times 10^5 \times 3 \times 10^5 = 9 \times 10^{10}$，答案会爆 `int`，必须用 `long long`。
    

### 二、 思路演进：怎么自然而然想出来的？

我们来还原一下在赛时拿到这道题的真实心路历程，拒绝“马后炮”：

#### Step 1: 暴力模拟（发现瓶颈）

最直观的想法：开一个 $N \times N$ 的二维数组。每次行变黑，就用循环把这一行全改成 1；列变白，就全改成 0。最后统计 1 的个数。

- **时间复杂度**：每次操作 $O(N)$，总共 $Q$ 次，总复杂度 $O(Q \times N)$。
    
- **带入数据**：$3 \times 10^5 \times 3 \times 10^5 = 9 \times 10^{10}$，直接超时（TLE）加爆内存（MLE）。**此路不通，必须优化。**
    

#### Step 2: 寻找决定颜色的“终极因素”

既然不能真的去涂色，那我们盯着某一个具体的方格 $(i, j)$ 看。它最后到底是黑是白，取决于什么？

显然，取决于**第 $i$ 行最后一次变黑的时间**和**第 $j$ 列最后一次变白的时间**，谁更靠后（谁更晚发生）！

- 如果第 $i$ 行变黑发生在第 $j$ 列变白**之后**，那它现在就是**黑色**。
    
- 反之，就是**白色**。
    

我们可以给每一行、每一列记录一个**时间戳**。设 $T_{row}[i]$ 为第 $i$ 行最后一次被操作的时间，$T_{col}[j]$ 为第 $j$ 列最后一次被操作的时间（初始时间都为 1）。

那么，方格 $(i, j)$ 是黑色的充要条件就是：

$$T_{row}[i] > T_{col}[j]$$

#### Step 3: 从全局统计转向“增量贡献”

如果每一步都去扫一遍所有的 $i$ 和 $j$ 来判断 $T_{row}[i] > T_{col}[j]$，那复杂度还是 $O(N^2)$。

所以我们要用**增量思维**：当前这次操作，会让黑色方块的数量**增加多少**或**减少多少**？

- **情况 1：当前在时刻 $t$，把第 $R$ 行涂黑。**
    
    - 第 $R$ 行原先的时间戳是 $old\_v = T_{row}[R]$。
        
    - 对于某一列 $j$，如果原先 $T_{col}[j] < old\_v$，说明它本来就是黑的，现在依然是黑的，**无影响**。
        
    - 如果原先 $T_{col}[j] \ge old\_v$，说明它本来是白的。现在这一行的时间戳变成了 $t$，因为 $t$ 是当前最新时间，必定大于 $T_{col}[j]$，所以这些原本是白的格子**全都变黑了**！
        
    - **结论**：增加的黑色格子数量 = 满足 $old\_v \le T_{col}[j] < t$ 的列 $j$ 的数量。
        
- **情况 2：当前在时刻 $t$，把第 $C$ 列涂白。**
    
    - 同理，第 $C$ 列原先的时间戳是 $old\_v = T_{col}[C]$。
        
    - 原本是黑色的格子（满足 $old\_v < T_{row}[i] < t$ 的行 $i$），在这一列上的交叉点会被无情地抹成白色。
        
    - **结论**：减少的黑色格子数量 = 满足 $old\_v < T_{row}[i] < t$ 的行 $i$ 的数量。
        

#### Step 4: 转化为经典数据结构问题

问题变成了：我们需要维护一个列的时间戳数组 $T_{col}$，每次操作会修改其中一个值（单点修改），并且我们需要快速知道“有多少个元素的值在区间 $[old\_v, t-1]$ 之间”（区间查询）。

这不就是标准的**树状数组/线段树**的看家本领吗？我们只需要用树状数组维护每个“时间戳”出现的频次即可！

### 三、 母题、核心思想与结论

#### 1. 母题（类似题）

这类题在各大平台上屡见不鲜，如：

- **AtCoder ABC 244 E / 类似网格染色问题**
    
- **Codeforces 经典的 Matrix Query 系列**
    
- **特征**：对矩阵的整行/整列进行覆盖式操作，询问最终状态或动态维护某种状态的数量。
    

#### 2. 核心思想：时序覆盖的独立性拆分

- **怎么理解**：二维网格看似错综复杂，行和列相互交织。但由于“覆盖”的特性，任意一个格子的状态只取决于其所在行和所在列的“独立时间戳的相对大小”。这种将二维交织问题拆解为两个一维时间轴对比的思想，就是**时序独立性拆分**。
    

#### 3. 结论性公式

对于所有“行覆盖、列覆盖”的逻辑动态维护题，均可维护行时间戳数组 $T_r$ 和列时间戳数组 $T_c$。

最终满足某种颜色条件的格子总数，可以用值域树状数组（以时间戳为下标）通过增量法在 $O(Q \log Q)$ 内解决。

### 四、 提炼套路：下次怎么一眼看破？

当你看到题目同时满足以下特征时，直接套用本题模板：

1. **数据范围大**（$N, Q \ge 10^5$），不允许显式建图或矩阵。
    
2. **操作为“整行”或“整列”的覆盖**（后面做的操作会完全覆盖前面的操作）。
    
3. **询问与全局计数相关**。
    

**秒杀公式**：**“覆盖看时序，计数求增量，动态用树状（数组）”**。

### 五、 完整的 C++ 代码解答

以下是经过极致优化且附带超详细注释的代码：

C++

```
#include <iostream>
#include <vector>

using namespace std;

// 树状数组（Fenwick Tree）模板
struct Fenwick {
    int n;
    vector<int> tree;
    Fenwick(int n) : n(n), tree(n + 1, 0) {}

    // 单点增加：在位置 i 加上 delta
    void add(int i, int delta) {
        for (; i <= n; i += i & -i) {
            tree[i] += delta;
        }
    }

    // 前缀和查询：查询 [1, i] 的总和
    int query(int i) {
        int sum = 0;
        for (; i > 0; i -= i & -i) {
            sum += tree[i];
        }
        return sum;
    }

    // 区间查询：查询 [l, r] 的总和
    int query_range(int l, int r) {
        if (l > r) return 0;
        return query(r) - query(l - 1);
    }
};

int main() {
    // 优化输入输出流，加速执行
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int n, q;
    if (!(cin >> n >> q)) return 0;

    // 时间戳从 1 开始初始化。Q 次询问后，最大时间戳为 Q + 1
    int max_t = q + 1;
    Fenwick bit_row(max_t), bit_col(max_t);

    // T_row[i] 表示第 i 行最后一次操作的时间戳
    // T_col[j] 表示第 j 列最后一次操作的时间戳
    // 初始时（时刻 1），所有行列都未被操作，时间戳默认为 1
    vector<int> T_row(n + 1, 1);
    vector<int> T_col(n + 1, 1);

    // 初始时刻 1，有 n 个行的最新时间戳是 1，n 个列的最新时间戳是 1
    bit_row.add(1, n);
    bit_col.add(1, n);

    // 初始全白，黑色格子数量为 0
    // 注意：最大可能达到 N * N = 9 * 10^10，必须用 long long
    long long black_cells = 0;

    // 从时刻 2 开始处理 Q 次询问
    for (int t = 2; t <= q + 1; ++t) {
        int type, idx;
        cin >> type >> idx;

        if (type == 1) {
            // 类型 1：把第 idx 行涂黑
            int old_v = T_row[idx]; // 该行上一次被操作的时间

            // 寻找有多少个列，它们在 [old_v, t - 1] 期间被涂白了。
            // 这些交叉点原本是白色的，现在由于整行变黑，它们都会变成黑色！
            int changed_cols = bit_col.query_range(old_v, t - 1);
            black_cells += changed_cols;

            // 更新当前行的时间戳
            T_row[idx] = t;
            bit_row.add(old_v, -1); // 旧时间戳频次减 1
            bit_row.add(t, 1);      // 新时间戳频次加 1

        } else {
            // 类型 2：把第 idx 列涂白
            int old_v = T_col[idx]; // 该列上一次被操作的时间

            // 寻找有多少个行，它们在 [old_v + 1, t - 1] 期间被涂黑了。
            // 这些交叉点原本是黑色的，现在由于整列被抹白，它们会变成白色！
            // 为什么是 old_v + 1？因为如果行的时间戳恰好等于 old_v 是不可能的（时序唯一）
            int changed_rows = bit_row.query_range(old_v + 1, t - 1);
            black_cells -= changed_rows;

            // 更新当前列的时间戳
            T_col[idx] = t;
            bit_col.add(old_v, -1); // 旧时间戳频次减 1
            bit_col.add(t, 1);      // 新时间戳频次加 1
        }

        // 输出当前时刻的黑色格子总量
        cout << black_cells << "\n";
    }

    return 0;
}
```
