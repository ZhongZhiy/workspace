这是因为在 **Arch Linux** 中，虽然你设置了语言环境变量（如 `en_US.UTF-8`），但系统还没有正式“生成”对应的本地化文件。`cowsay` 是用 Perl 语言写的，而 Perl 对本地化设置非常敏感，如果它找不到对应的配置，就会疯狂刷屏报警。

作为 Arch 用户，手动生成 **Locale**（本地化设置）是必经之路。请按照以下步骤操作：

---

### 第一步：编辑 Locale 生成列表

你需要告诉系统你需要哪些语言支持。

1. 使用 root 权限打开配置文件：
    
    Bash
    
    ```
    sudo nvim /etc/locale.gen
    ```
    
2. 在文件中找到以下两行（你可以用 `/` 进行搜索），**删掉它们前面的注释符号 `#`**：
    
    Plaintext
    
    ```
    en_US.UTF-8 UTF-8
    zh_CN.UTF-8 UTF-8
    ```
    
    _注：建议把中文和英文的都开了，因为你刚才安装了中文语录库。_
    
3. 保存并退出（`:wq`）。
    

---

### 第二步：生成本地化文件

运行 Arch 提供的生成工具：

Bash

```
sudo locale-gen
```

你会看到终端输出 `Generating locales...`，并列出刚才你取消注释的那几项。如果看到 `Generation complete`，说明已经成功。

---

### 第三步：配置系统默认语言（可选）

如果你希望系统默认使用英文（避免某些命令行输出变成中文乱码），可以创建一个配置文件：

Bash

```
echo "LANG=en_US.UTF-8" | sudo tee /etc/locale.conf
```

---

### 第四步：立即消除当前警告

虽然生成了文件，但你当前的终端会话可能还没反应过来。你可以运行以下命令刷新当前环境：

Bash

```
export LC_ALL=en_US.UTF-8
```

---

### 验证成果

现在再次运行：

Bash

```
cowsay "Hello"
```

那个长长的报错应该消失了，剩下的只有那只可爱的牛。

---

### 💡 为什么会出现这个问题？

Arch Linux 遵循 **KISS (Keep It Simple, Stupid)** 原则，它默认不预装任何多余的东西。比起 Ubuntu 这种帮你自动生成好几百种语言文件的系统，Arch 觉得“你需要什么语言，你自己去 `/etc/locale.gen` 里选”。

**现在你的 `fortune-zh` 应该也能完美显示中文诗词而不报错了。要不要试试看把 `fortune` 的输出传给不同形状的“牛”？你可以输入 `cowsay -l` 看看你现在拥有哪些动物形象。**
