## 1 设计概述

### 1.1 实现功能

本次系统能力综合实践设计并实现了一款基于 LoongArch 指令集架构的 32 位 CPU。该 CPU 能正确执行龙芯提供的基础功能测试程序，支持以下 **20 条指令**：

| 类别 | 指令 | 汇编格式 | 功能说明 |
|------|------|----------|----------|
| 算术运算 | `add.w` | `add.w rd, rj, rk` | 32位寄存器加法：rd = rj + rk |
| | `sub.w` | `sub.w rd, rj, rk` | 32位寄存器减法：rd = rj - rk |
| | `addi.w` | `addi.w rd, rj, si12` | 32位立即数加法：rd = rj + sign_extend(si12) |
| | `slt` | `slt rd, rj, rk` | 有符号小于置1：rd = (rj < rk，有符号) ? 1 : 0 |
| | `sltu` | `sltu rd, rj, rk` | 无符号小于置1：rd = (rj < rk，无符号) ? 1 : 0 |
| 逻辑运算 | `and` | `and rd, rj, rk` | 按位与：rd = rj & rk |
| | `or` | `or rd, rj, rk` | 按位或：rd = rj \| rk（兼作 move） |
| | `nor` | `nor rd, rj, rk` | 按位或非：rd = ~(rj \| rk) |
| | `xor` | `xor rd, rj, rk` | 按位异或：rd = rj ^ rk |
| 移位运算 | `slli.w` | `slli.w rd, rj, ui5` | 逻辑左移：rd = rj << ui5（ui5来自rk字段低5位） |
| | `srli.w` | `srli.w rd, rj, ui5` | 逻辑右移：rd = rj >> ui5（高位填0） |
| | `srai.w` | `srai.w rd, rj, ui5` | 算术右移：rd = rj >> ui5（高位填符号位） |
| 立即数装载 | `lu12i.w` | `lu12i.w rd, si20` | 装载高20位立即数：rd = si20 << 12 |
| 访存 | `ld.w` | `ld.w rd, rj, si12` | 装载字：rd = mem[rj + sign_extend(si12)] |
| | `st.w` | `st.w rd, rj, si12` | 存储字：mem[rj + sign_extend(si12)] = rd |
| 分支转移 | `b` | `b offs26` | 无条件跳转：pc = pc + sign_extend(offs26) << 2 |
| | `bl` | `bl offs26` | 调用：$r1 = pc + 4; pc = pc + sign_extend(offs26) << 2 |
| | `beq` | `beq rj, rd, offs16` | 相等分支：if (rj == rd) pc = pc + sign_extend(offs16) << 2 |
| | `bne` | `bne rj, rd, offs16` | 不等分支：if (rj != rd) pc = pc + sign_extend(offs16) << 2 |
| | `jirl` | `jirl rd, rj, offs16` | 寄存器间接跳转并链接：rd = pc + 4; pc = rj + sign_extend(offs16) << 2 |

分两个阶段递进完成：

- **基本任务1 — 20条指令单周期CPU**：全部指令在一个时钟周期内完成取指、译码、执行、访存、写回五个步骤。所有数据通路与控制逻辑集中在一个顶层模块中实现，时序单元仅维护程序计数器（PC）和通用寄存器堆的写操作。该设计的优点在于结构清晰、直观，便于理解指令的完整执行流程；局限在于关键路径（组合逻辑从 PC 出发经译码、ALU、访存回到寄存器写回）过长，时钟频率受限。
- **基本任务2 — 不考虑相关冲突处理的简单流水线CPU**：将数据通路剖分为 IF（取指）、ID（译码）、EXE（执行）、MEM（访存）、WB（写回）五个流水级，各级同时独立工作，通过流水线寄存器与 valid/allowin 握手协议进行级间数据传递，实现多条指令在时间上的并行。本流水线为 **理想型（不考虑相关冲突处理）** 设计——未实现数据前推（forwarding）、未实现 Load-Use 冒险检测与冒泡、未实现分支预测等高级流水线特性，依赖被测试程序中指令间天然的间距（无紧邻 RAW 数据相关）来保证功能正确性。

### 1.2 设计环境与验证方法

- **硬件描述语言**：Verilog HDL
- **仿真验证**：iverilog + 龙芯 SoC-Lite 仿真框架。仿真顶层 `tb_top` 实例化 `soc_lite_top` 封装 CPU，核心验证手段为 **golden trace 逐条比对**——仿真程序从参考结果文件 `golden_trace.txt` 逐行读取期望的写回信息（PC、写寄存器号、写数据），与 CPU 的 `debug_wb_*` 信号在每一个写回时钟周期进行精确比对。任何不匹配即打印 `Error!!!` 并终止仿真。同时通过外设 confreg 模块的数码管寄存器 `num_data` 递增监控各功能测试点的通过情况。
- **综合目标**：Xilinx Vivado，对应龙芯 SoC-Lite FPGA 开发板，约束文件 `soc_lite_top.xdc` 已绑定主时钟（周期 10 ns）、复位、LED、数码管、拨码开关、按键等外设引脚。
- **指令存储**：`inst_ram.coe` 中固化了由汇编源代码 `test.s` 编译链接生成的机器码，CPU 通过 inst_sram 接口以 PC 为地址读取指令。`test.s` 是龙芯提供的一套完整功能测试反汇编程序，包含针对上述 20 条指令的逐条子测试（`n1_lu12i_w_test`、`n2_add_w_test` 直到 `n20_b_test`），以及 idle 延时、locate 初始化、test_finish 收尾等辅助逻辑。

### 1.3 指令系统编码与译码方式

LoongArch 指令集采用 **定长 32 位指令编码**。与经典 MIPS 单一 6 位 opcode 加 function 字段不同，LoongArch 通过四个操作码字段组合区分指令类型：`op[31:26]`（主要操作码）、`op[25:22]`（次要操作码）、`op[21:20]`（第三操作码）、`op[19:15]`（第四操作码）。

寄存器字段统一为 `rd[4:0]`（目标寄存器）、`rj[9:5]`（第一源寄存器）、`rk[14:10]`（第二源寄存器）。立即数字段则根据指令类型不同取不同的位宽和位段。

本设计在 `tools.v` 中实现了 4 个参数化译码器，使用 generate 循环将每个操作码字段转成 **one-hot 编码**，再由四个 one-hot 信号按位相与得到每条指令的识别信号。以 `add.w` 为例：

```verilog
assign inst_add_w = op_31_26_d[6'h00] & op_25_22_d[4'h0]
                  & op_21_20_d[2'h1] & op_19_15_d[5'h00];
```

所有译码信号为独立的 wire 变量，而非嵌套的 case 或 if-else 链，使得后续控制信号的生成逻辑清晰且易于扩展。

## 2 基本任务的设计与实现

### 2.1 基本任务1 — 20条指令单周期CPU的设计与实现

#### 2.1.1 设计原理

单周期 CPU 的核心设计理念是：**一条完整的指令在单个时钟周期内完成从取指到写回的全部操作**。数据通路以纯组合逻辑为主体，所有运算、数据选择、地址计算在同一周期中传播，仅在时钟边沿将计算结果锁存到 PC 寄存器和通用寄存器堆中。这种设计使得每一时钟周期恰好执行一条指令，CPI（每指令周期数）恒等于 1。

单周期 CPU 的关键路径为：**PC 地址输出 → 指令 SRAM 读出 → 译码 → 寄存器堆组合读 → ALU 运算 → 访存（可选 SRAM 读） → 写回结果选择 → 寄存器堆写使能判定**。这条路径的长度直接决定了 CPU 能达到的最大时钟频率。

#### 2.1.2 数据通路详情

单周期的具体实现电路涉及多路复用器（MUX）、移位扩展部件、ALU 运算和 SRAM 读写。各部分的数据逻辑传输路径如下：

1. **取指（IF Loop）数据通路**：程序计数器（PC）输出当前取指地址 `inst_sram_addr`。在每一个时钟上升沿，PC 将根据分支跳转控制信号 `br_taken` 的判定，通过 2 选 1 多路选择器在顺序递增地址 `seq_pc = pc + 4` 和分支目标地址 `br_target` 之间进行选择更新。当前 PC 索引指令 SRAM 并在当周期组合读出 32 位机器码 `inst`。
    
2. **字段切分与立即数扩展通路**：从 32 位 `inst` 中切分出 `rj`、`rk`、rd 寄存器索引以及不同的立即数原始位段。移位扩展部件根据当前指令类型的需求，采用多路选择器产生符合 32 位位宽的立即数：
    
    - **12位立即数符号扩展**（`addi.w`, `ld.w`, `st.w`）：高 20 位填充 `inst[21]` 符号位，低 12 位保留原始 `inst[21:10]`；
        
    - **20位立即数高位对齐扩展**（`lu12i.w`）：`inst[24:5]` 锁存于 32 位数的高 20 位，低 12 位填 0；
        
    - **5位无符号立即数扩展**（移位指令）：直接提取 `rk` 字段 `inst[14:10]`，高 27 位补零。
        
3. **寄存器堆读写（Regfile Path）数据通路**：通用寄存器堆支持两读一写。读端口 1 地址 `raddr1` 恒定接 `rj`；读端口 2 地址 `raddr2` 由控制信号 `src_reg_is_rd` 选择（当指令为 `beq`、`bne` 或 `st.w` 时，由于需要读 `rd` 作为源操作数，选择 `rd`，其余指令选择 `rk`）。读出的数据分别得到 `rj_value` 与 `rkd_value`。
    
4. **ALU 源操作数多路复用通路**：ALU 输入源 1 `alu_src1` 通过选择器在 `pc`（`bl` 和 `jirl` 指令，用于在下一级计算返回地址 `pc+4`）和寄存器输出值 `rj_value` 之间选择。ALU 输入源 2 `alu_src2` 通过选择器在 32 位扩展立即数 `imm`（含有立即数的指令）和寄存器输出值 `rkd_value` 之间选择。
    
5. **算术逻辑单元（ALU）计算通路**：ALU 接收两路 32 位操作数及 12 位 one-hot 编码的 `alu_op` 信号。核心加法器复用逻辑为：加法指令和访存、跳转指令采用直接加法，减法与比较指令（`sub.w`, `slt`, `sltu`）对第二操作数按位取反加 1 后输入加法器，最终由运算逻辑电路（包含移位、逻辑与或异或非、比较判定等）复用多路选择产生 `alu_result`。
    
6. **数据存储器访问通路（Data Memory Access）**：ALU 算出的 `alu_result` 直接作为 `data_sram_addr`。对于 `st.w` 指令，写使能 `data_sram_we` 被拉高，写入的数据 `data_sram_wdata` 恒定连接寄存器读出数据 `rkd_value`；对于 `ld.w` 指令，数据 SRAM 组合读出的数据 `data_sram_rdata` 会作为 `mem_result` 参与后级的选择。
    
7. **数据写回（Write-back）多路复用通路**：写回寄存器堆的数据 `rf_wdata` 通过 2 选 1 模拟多路选择器由 `res_from_mem` 信号控制（当为 `ld.w` 时选择从存储器读出的 `mem_result`，其余运算指令选择 `alu_result`）。目标写寄存器地址 `rf_waddr` 亦根据 `dst_is_r1` 控制（`bl` 指令写回固定目标 `$r1`，其他写回 `rd`）。
    
8. **分支判定与跳转通路**：ID 译码阶段对读出的通用寄存器数据进行等值比较，输出 `rj_eq_rd = (rj_value == rkd_value)`。控制部件结合 `beq`、`bne` 或 `b`、`bl` 等指令类型组合产生 `br_taken` 控制下一周期 PC 更新。跳转目标 `br_target` 的计算分为 PC 相对寻址（`pc + br_offs`）和寄存器间接寻址（`rj_value + jirl_offs`），它们通过分支加法器组合计算并反馈至 PC。

#### 2.1.3 控制信号与译码逻辑

除 ALU 操作码外，还需生成一系列控制信号来指导数据通路中的多路选择器、写使能、目的寄存器选择等：

Verilog

```
// 第二源寄存器是 rd 还是 rk？—— beq/bne 比较两个寄存器、st.w 存 rd 值时选 rd
assign src_reg_is_rd = inst_beq | inst_bne | inst_st_w;

// ALU 第一操作数选 PC 还是 rj？—— jirl/bl 需要计算返回地址 pc+4 时选 PC
assign src1_is_pc    = inst_jirl | inst_bl;

// ALU 第二操作数选立即数还是 rkd_value？—— 14 种含立即数的指令选立即数
assign src2_is_imm   = inst_slli_w | inst_srli_w | inst_srai_w |
                       inst_addi_w | inst_ld_w | inst_st_w |
                       inst_lu12i_w | inst_jirl | inst_bl;

// 写回结果是来自内存（ld.w）还是来自 ALU？
assign res_from_mem  = inst_ld_w;

// bl 的目标寄存器固定为 $r1（存放返回地址）
assign dst_is_r1     = inst_bl;

// 哪些指令不写通用寄存器？—— st.w（只写内存）、beq/bne/b（只跳转不写回）
assign gr_we = ~inst_st_w & ~inst_beq & ~inst_bne & ~inst_b;

// 内存写使能——仅 st.w 写数据 SRAM
assign mem_we = inst_st_w;

// 最终目的寄存器号—— bl 写 $r1，其他写 rd 字段
assign dest = dst_is_r1 ? 5'd1 : rd;
```

### 2.2 基本任务2 — 理想流水线CPU的设计与实现

#### 2.2.1 设计原理

将数据通路剖分为 IF（取指）、ID（译码）、EXE（执行）、MEM（访存）、WB（写回）五个流水级，各级同时独立工作，通过流水线寄存器与 valid/allowin 握手协议进行级间数据传递，实现多条指令在时间上的并行。

#### 2.2.2 数据通路与级间传输架构

流水线设计采用多模块级联，顶层 `mycpu_top.v` 作为连线层，级间数据通路依靠庞大的级间传输总线（Bus）进行数据传递：

1. **IF（取指）级数据通路**：内部包含 32 位 PC 寄存器（复位值 `0x1bfffffc`）。PC 的输出值和取指结果 `fs_inst` 打包成 64 位宽的级间总线 `fs_to_ds_bus` 锁存入 IF/ID 寄存器：
    
    - `fs_to_ds_bus = {fs_inst[31:0], fs_pc[31:0]}` (共 64 位)。
        
2. **ID（译码）级数据通路**：锁存上一级总线。该阶段包含 20 条指令的 decoder One-hot 译码以及控制信号、立即数的生成。实例化通用寄存器堆 `regfile` 组合读出 `rj_value` 和 `rkd_value`。若检测到分支跳转，输出 33 位的分支反馈总线并反回送 IF 级：
    
    - `br_bus = {br_taken[32], br_target[31:0]}` (共 33 位，反向回送)。
        
    - 打包 152 位控制与操作数总线送往 EXE 级流水线寄存器：
        
        `ds_to_es_bus = {alu_op[11:0], load_op, src1_is_pc, src2_is_imm, src2_is_4, gr_we, mem_we, dest[4:0], imm[31:0], rj_value[31:0], rkd_value[31:0], ds_pc[31:0], res_from_mem}` (共 152 位)。
        
3. **EXE（执行）级数据通路**：锁存并解包 ID 级传输的总线。EXE 级内部实例化 `alu` 模块，通过 MUX 选择数据，执行运算生成 `alu_result`。
    
    - **数据存储器 (Data SRAM) 写通路引出**：因为实验采用同步 SRAM 时序，地址、数据及使能必须提前一拍送出以匹配时钟采样沿。因此 EXE 级引出了 `data_sram_we` (由 `es_mem_we` 与 `es_valid` 产生)、`data_sram_addr = alu_result`、`data_sram_wdata = rkd_value` 送往存储器端口。
        
    - 打包 71 位计算结果送往 MEM 级流水线寄存器：
        
        `es_to_ms_bus = {res_from_mem, gr_we, dest[4:0], alu_result[31:0], es_pc[31:0]}` (共 71 位)。
        
4. **MEM（访存）级数据通路**：锁存上一级总线。在 MEM 级周期内，读取来自数据 SRAM 的稳定读回数据 `data_sram_rdata` 并解为 `mem_result`。通过 2 选 1 多路选择器选择最终写入寄存器的数据 `ms_final_result`。打包 70 位写回总线：
    
    - `ms_to_ws_bus = {ms_gr_we, ms_dest[4:0], ms_final_result[31:0], ms_pc[31:0]}` (共 70 位)。
        
5. **WB（写回）级数据通路**：锁存上一级数据。产生 38 位的写回寄存器总线反向回送给 ID 级的通用寄存器堆写端口：
    
    - `ws_to_rf_bus = {rf_we, rf_waddr[4:0], rf_wdata[31:0]}` (共 38 位，反向回送)。
        
    - WB 级还负责引出 golden trace 的调试引脚（`debug_wb_*`），配合比对。

#### 2.2.3 流水线握手控制协议

每个流水级内部都维护一个 `valid` 状态寄存器，并输出 `ready_go`（本级是否就绪）和 `allowin`（本级能否接纳新数据）两个信号：

- `xxx_valid`：本级寄存器中当前是否持有有效的指令/数据。
    
- `xxx_ready_go`：本级是否已完成处理、可以向后传递数据（本设计中无多周期操作，恒为 1）。
    
- `xxx_allowin`：表示本级是否允许上一级将新数据推入。逻辑如下：
    
    `assign xxx_allowin = !xxx_valid || (xxx_ready_go && next_allowin);`
    
- 各级的 `allowin` 信号自后向前传递（WB 级→ MEM 级→ EXE 级→ ID 级→ IF 级），当某一级阻塞导致其 `allowin = 0` 时，上游各级 `allowin` 依次被拉低，最终使 IF 级 `fs_allowin = 0` 冻结 PC 更新，实现了流水线的自动反压保护。
    

#### 2.2.4 性能评价指标计算

基于本设计的理想五级流水线 CPU，由于没有实现相关冲突的数据旁路（Forwarding）和停顿控制逻辑，在不引发冒险的测试程序上可以实现近乎 1.00 的 CPI（除开始填充流水线的 4 周期延迟外）。

$$T_{exe} = N_{inst} \times CPI \times T_{clk}$$

$$CPI = \frac{N_{cycles}}{N_{inst}}$$

#### 2.2.5 存在的问题与说明

本流水线设计为“不考虑冲突处理”的理想型，存在以下已知局限：

1. **无数据前推（forwarding）**：当后续指令在 ID 级读取某寄存器时，若该寄存器的最新值正在 EXE 或 MEM 级中，ID 级读到的仍是旧值，需要测试程序天然的指令间距来保证正确性。
    
2. **无 Load-Use 冒险检测与冒泡**：若紧随 `ld.w` 后的指令需要使用其加载的寄存器，由于数据尚未加载完成，必须在流水线中插入一拍停顿（bubble/stall）。
    
3. **无分支预测**：分支在 ID 级判定。目前我们暂未对已经错误取入的延迟周期指令进行无效化（Flush）清除。

## 4 设计过程中遇到的问题及解决方法

### 4.1 问题一：复位后 PC 与首条指令地址不匹配

- **问题描述**：测试程序入口地址为 `0x1c000000`，但 CPU 复位后若 PC=0，则第一条指令将从地址 0 取指，导致 CPU 执行随机垃圾指令。
    
- **解决方法**：采用"复位 PC 写入 `0x1bfffffc`"的设计。复位后的第一个上升沿，`nextpc = 0x1bfffffc + 4 = 0x1c000000`，对准测试程序入口 `_start`。同时引入 `valid` 状态位，复位期间 `valid = 0` 锁死所有的写寄存器、写内存和跳转。
    

### 4.2 问题二：LoongArch 多段操作码译码的理解与实现

- **问题描述**：LoongArch 指令采用不等宽的操作码字段（op[31:26]、op[25:22]、op[21:20]、op[19:15]）联合判定，若直接写 large case 或 nested if-else，极易导致混叠或漏掉某些条件。
    
- **解决方法**：在 `tools.v` 中实现了 4 个参数化译码器将各个位段先转成 one-hot 编码，再按位相与。新增指令仅需要添加单行 assignment 语句，互不干扰。
    

### 4.3 问题三：流水线 valid/allowin 握手协议的因果依赖理解

- **问题描述**：valid、ready_go、allowin 形成的“反向反压”传播与正常的数据流方向相反，时序因果关系的微小失误极易引发流水线永久锁死（Deadlock）或数据丢步。
    
- **解决方法**：通过建立严格的一致性三信号赋值模板，明确 allowin 表达式的布尔物理意义（“本级空，或者本级虽然有数据但是下一级允许接收数据”）。从而自 WB 级向 IF 级依次倒推。
    

### 4.4 问题四：同步 SRAM 的写时序适配

- **问题描述**：对于同步 SRAM 存储器（`sync_ram.v`），它的地址和使能必须提前一个时钟沿前稳定，才能在时钟采样时写入。若 st.w 的控制在 MEM 级才发出，会导致写入延迟一拍，与 golden trace 错位。
    
- **解决方法**：将同步数据存储器的 WE、ADDR 和 WDATA 控制端口**提前到 EXE 级**组合输出（EXE 级的 ALU 结果已算好地址）。这样 SRAM 在 EXE→MEM 的时钟上升沿对输入采样，完美在 MEM 周期内完成实际写入动作，ld.w 指令也刚好在 MEM 级采样读回。

### 1.3 指令系统编码与译码方式

LoongArch 指令集采用 **定长 32 位指令编码**。与经典 MIPS 单一 6 位 opcode 加 function 字段不同，LoongArch 通过四个操作码字段组合区分指令类型：`op[31:26]`（主要操作码）、`op[25:22]`（次要操作码）、`op[21:20]`（第三操作码）、`op[19:15]`（第四操作码）。

寄存器字段统一为 `rd[4:0]`（目标寄存器）、`rj[9:5]`（第一源寄存器）、`rk[14:10]`（第二源寄存器）。立即数字段则根据指令类型不同取不同的位宽 and 位段。

本设计在 `tools.v` 中实现了 4 个参数化译码器，使用 generate 循环将每个操作码字段转成 **one-hot 编码**，再由四个 one-hot 信号按位相与得到每条指令的识别信号。以 `add.w` 为例：

```verilog
assign inst_add_w = op_31_26_d[6'h00] & op_25_22_d[4'h0]
                  & op_21_20_d[2'h1] & op_19_15_d[5'h00];
````

所有译码信号为独立的 wire 变量，而非嵌套的 case 或 if-else 链，使得后续控制信号的生成逻辑清晰且易于扩展。

## 2 基本任务的设计与实现

### 2.1 基本任务1 — 20条指令单周期CPU的设计与实现

#### 2.1.1 设计原理

单周期 CPU 的核心设计理念是：**一条完整的指令在单个时钟周期内完成从取指到写回的全部操作**。数据通路以纯组合逻辑为主体，所有运算、数据选择、地址计算在同一周期中传播，仅在时钟边沿将计算结果锁存到 PC 寄存器和通用寄存器堆中。这种设计使得每一时钟周期恰好执行一条指令，CPI（每指令周期数）恒等于 1。

单周期 CPU 的关键路径为：**PC 地址输出 → 指令 SRAM 读出 → 译码 → 寄存器堆组合读 → ALU 运算 → 访存（可选 SRAM 读） → 写回结果选择 → 寄存器堆写使能判定**。这条路径的长度直接决定了 CPU 能达到的最大时钟频率。

#### 2.1.2 数据通路详情

单周期的具体实现电路涉及多路复用器（MUX）、移位扩展部件、ALU 运算和 SRAM 读写。各部分的数据逻辑传输路径如下：

1. **取指（IF Loop）数据通路**：程序计数器（PC）输出当前取指地址 `inst_sram_addr`。在每一个时钟上升沿，PC 将根据分支跳转控制信号 `br_taken` 的判定，通过 2 选 1 多路选择器在顺序递增地址 `seq_pc = pc + 4` 和分支目标地址 `br_target` 之间进行选择更新。当前 PC 索引指令 SRAM 并在当周期组合读出 32 位机器码 `inst`。
    
2. **字段切分与立即数扩展通路**：从 32 位 `inst` 中切分出 `rj`、`rk`、`rd` 寄存器索引以及不同的立即数原始位段。移位扩展部件根据当前指令类型的需求，采用多路选择器产生符合 32 位位宽的立即数：
    
    - **12位立即数符号扩展**（`addi.w`, `ld.w`, `st.w`）：高 20 位填充 `inst[21]` 符号位，低 12 位保留原始 `inst[21:10]`；
        
    - **20位立即数高位对齐扩展**（`lu12i.w`）：`inst[24:5]` 锁存于 32 位数的高 20 位，低 12 位填 0；
        
    - **5位无符号立即数扩展**（移位指令）：直接提取 `rk` 字段 `inst[14:10]`，高 27 位补零。
        
3. **寄存器堆读写（Regfile Path）数据通路**：通用寄存器堆支持两读一写。读端口 1 地址 `raddr1` 恒定接 `rj`；读端口 2 地址 `raddr2` 由控制信号 `src_reg_is_rd` 选择（当指令为 `beq`、`bne` 或 `st.w` 时，由于需要读 `rd` 作为源操作数，选择 `rd`，其余指令选择 `rk`）。读出的数据分别得到 `rj_value` 与 `rkd_value`。
    
4. **ALU 源操作数多路复用通路**：ALU 输入源 1 `alu_src1` 通过选择器在 `pc`（`bl` 和 `jirl` 指令，用于在下一级计算返回地址 `pc+4`）和寄存器输出值 `rj_value` 之间选择。ALU 输入源 2 `alu_src2` 通过选择器在 32 位扩展立即数 `imm`（含有立即数的指令）和寄存器输出值 `rkd_value` 之间选择。
    
5. **算术逻辑单元（ALU）计算通路**：ALU 接收两路 32 位操作数及 12 位 one-hot 编码的 `alu_op` 信号。核心加法器复用逻辑为：加法指令和访存、跳转指令采用直接加法，减法与比较指令（`sub.w`, `slt`, `sltu`）对第二操作数按位取反加 1 后输入加法器，最终由运算逻辑电路（包含移位、逻辑与或异或非、比较判定等）复用多路选择产生 `alu_result`。
    
6. **数据存储器访问通路（Data Memory Access）**：ALU 算出的 `alu_result` 直接作为 `data_sram_addr`。对于 `st.w` 指令，写使能 `data_sram_we` 被拉高，写入的数据 `data_sram_wdata` 恒定连接寄存器读出数据 `rkd_value`；对于 `ld.w` 指令，数据 SRAM 组合读出的数据 `data_sram_rdata` 会作为 `mem_result` 参与后级的选择。
    
7. **数据写回（Write-back）多路复用通路**：写回寄存器堆的数据 `rf_wdata` 通过 2 选 1 模拟多路选择器由 `res_from_mem` 信号控制（当为 `ld.w` 时选择从存储器读出的 `mem_result`，其余运算指令选择 `alu_result`）。目标写寄存器地址 `rf_waddr` 亦根据 `dst_is_r1` 控制（`bl` 指令写回固定目标 `$r1`，其他写回 `rd`）。
    
8. **分支判定与跳转通路**：ID 译码阶段对读出的通用寄存器数据进行等值比较，输出 `rj_eq_rd = (rj_value == rkd_value)`。控制部件结合 `beq`、`bne` 或 `b`、`bl` 等指令类型组合产生 `br_taken` 控制下一周期 PC 更新。跳转目标 `br_target` 的计算分为 PC 相对寻址（`pc + br_offs`）和寄存器间接寻址（`rj_value + jirl_offs`），它们通过分支加法器组合计算并反馈至 PC。

Verilog

```
// 第二源寄存器是 rd 还是 rk？—— beq/bne 比较两个寄存器、st.w 存 rd 值时选 rd
assign src_reg_is_rd = inst_beq | inst_bne | inst_st_w;

// ALU 第一操作数选 PC 还是 rj？—— jirl/bl 需要计算返回地址 pc+4 时选 PC

// ALU 第二操作数选立即数还是 rkd_value？—— 14 种含立即数的指令选立即数

                       inst_lu12i_w | inst_jirl | inst_bl;

// 写回结果是来自内存（ld.w）还是来自 ALU？
assign res_from_mem  = inst_ld_w;

// bl 的目标寄存器固定为 $r1（存放返回地址）
assign dst_is_r1     = inst_bl;

// 哪些指令不写通用寄存器？—— st.w（只写内存）、beq/bne/b（只跳转不写回）
assign gr_we = ~inst_st_w & ~inst_beq & ~inst_bne & ~inst_b;

assign mem_we = inst_st_w;

// 最终目的寄存器号—— bl 写 $r1，其他写 rd 字段
assign dest = dst_is_r1 ? 5'd1 : rd;
```

### 2.2 基本任务2 — 理想流水线CPU的设计与实现

#### 2.2.1 设计原理

将数据通路剖分为 IF（取指）、ID（译码）、EXE（执行）、MEM（访存）、WB（写回）五个流水级，各级同时独立工作，通过流水线寄存器与 valid/allowin 握手协议进行级间数据传递，实现多条指令在时间上的并行。

#### 2.2.2 数据通路与级间传输架构

流水线设计采用多模块级联，顶层 `mycpu_top.v` 作为连线层，级间数据通路依靠庞大的级间传输总线（Bus）进行数据传递：

1. **IF（取指）级数据通路**：内部包含 32 位 PC 寄存器（复位值 `0x1bfffffc`）。PC 的输出值和取指结果 `fs_inst` 打包成 64 位宽的级间总线 `fs_to_ds_bus` 锁存入 IF/ID 寄存器：
    
    - `fs_to_ds_bus = {fs_inst[31:0], fs_pc[31:0]}` (共 64 位)。
        
2. **ID（译码）级数据通路**：锁存上一级总线。该阶段包含 20 条指令的 decoder One-hot 译码以及控制信号、立即数的生成。实例化通用寄存器堆 `regfile` 组合读出 `rj_value` 和 `rkd_value`。若检测到分支跳转，输出 33 位的分支反馈总线并反回送 IF 级：
    
    - `br_bus = {br_taken[32], br_target[31:0]}` (共 33 位，反向回送)。
        
    - 打包 152 位控制与操作数总线送往 EXE 级流水线寄存器：
        
        `ds_to_es_bus = {alu_op[11:0], load_op, src1_is_pc, src2_is_imm, src2_is_4, gr_we, mem_we, dest[4:0], imm[31:0], rj_value[31:0], rkd_value[31:0], ds_pc[31:0], res_from_mem}` (共 152 位)。
        
3. **EXE（执行）级数据通路**：锁存并解包 ID 级传输的总线。EXE 级内部实例化 `alu` 模块，通过 MUX选择数据，执行运算生成 `alu_result`。
    
    - **数据存储器 (Data SRAM) 写通路引出**：因为实验采用同步 SRAM 时序，地址、数据及使能必须提前一拍送出以匹配时钟采样沿。因此 EXE 级引出了 `data_sram_we` (由 `es_mem_we` 与 `es_valid` 产生)、`data_sram_addr = alu_result`、`data_sram_wdata = rkd_value` 送往存储器端口。
        
    - 打包 71 位计算结果送往 MEM 级流水线寄存器：
        
        `es_to_ms_bus = {res_from_mem, gr_we, dest[4:0], alu_result[31:0], es_pc[31:0]}` (共 71 位)。
        
4. **MEM（访存）级数据通路**：锁存上一级总线。在 MEM 级周期内，读取来自数据 SRAM 的稳定读回数据 `data_sram_rdata` 并解为 `mem_result`。通过 2 选 1 多路选择器选择最终写入寄存器的数据 `ms_final_result`。打包 70 位写回总线：
    
    - `ms_to_ws_bus = {ms_gr_we, ms_dest[4:0], ms_final_result[31:0], ms_pc[31:0]}` (共 70 位)。
        
5. **WB（写回）级数据通路**：锁存上一级数据。产生 38 位的写回寄存器总线反向回送给 ID 级的通用寄存器堆写端口：
    
    - `ws_to_rf_bus = {rf_we, rf_waddr[4:0], rf_wdata[31:0]}` (共 38 位，反向回送)。
        
    - WB 级还负责引出 golden trace 的调试引脚（`debug_wb_*`），配合比对。

#### 2.2.3 流水线双向握手协议控制

每个流水级内部都维护一个 `valid` 状态寄存器，并输出 `ready_go`（本级是否就绪）和 `allowin`（本级能否接纳新数据）两个信号：

- `xxx_valid`：本级寄存器中当前是否持有有效的指令/数据。
    
- `xxx_ready_go`：本级是否已完成处理、可以向后传递数据（本设计中无多周期操作，恒为 1）。
    
- `xxx_allowin`：表示本级是否允许上一级将新数据推入。逻辑如下：
    
    `assign xxx_allowin = !xxx_valid || (xxx_ready_go && next_allowin);`
    
- 各级的 `allowin` 信号自后向前传递（WB 级→ MEM 级→ EXE 级→ ID 级→ IF 级），当某一级阻塞导致其 `allowin = 0` 时，上游各级 `allowin` 依次被拉低，最终使 IF 级 `fs_allowin = 0` 冻结 PC 更新，实现了流水线的自动反压保护。
    

#### 2.2.4 性能评价指标计算

基于本设计的理想五级流水线 CPU，由于没有实现相关冲突的数据旁路（Forwarding）和停顿控制逻辑，在不引发冒险的测试程序上可以实现近乎 1.00 的 CPI（除开始填充流水线的 4 周期延迟外）。

CPU 性能计算公式如下：

$$T_{exe} = N_{inst} \times CPI \times T_{clk}$$

$$CPI = \frac{N_{cycles}}{N_{inst}}$$

其中，$T_{exe}$ 为程序实际执行时间，$N_{inst}$ 为运行的总指令条数，$N_{cycles}$ 为执行所需的实际总时钟周期数，$T_{clk}$ 为时钟周期（默认配置为 10 ns）。

#### 2.2.5 存在的问题与说明

本流水线设计为“不考虑冲突处理”的理想型，存在以下已知局限：

1. **无数据前推（forwarding）**：当后续指令在 ID 级读取某寄存器时，若该寄存器的最新值正在 EXE 或 MEM 级中，ID 级读到的仍是旧值，需要测试程序天然的指令间距来保证正确性。
    
2. **无 Load-Use 冒险检测与冒泡**：若紧随 `ld.w` 后的指令需要使用其加载的寄存器，由于数据尚未加载完成，必须在流水线中插入一拍停顿（bubble/stall）。
    
3. **无分支预测**：分支在 ID 级判定。目前我们暂未对已经错误取入的延迟周期指令进行无效化（Flush）清除。
    

## 3 附加任务的设计与实现

本次实习主要完成了两项基本任务（20 条指令单周期 CPU 和理想型五级流水线 CPU）。未涉及附加任务（如多周期乘除法器、Cache、TLB MMU、异常处理等）。

## 4 设计过程中遇到的问题及解决方法

### 4.1 问题一：复位后 PC 与首条指令地址不匹配

- **问题描述**：测试程序入口地址为 `0x1c000000`，但 CPU 复位后若 PC=0，则第一条指令将从地址 0 取指，导致 CPU 执行随机垃圾指令。
    
- **解决方法**：采用"复位 PC 写入 `0x1bfffffc`"的设计。复位后的第一个上升沿，`nextpc = 0x1bfffffc + 4 = 0x1c000000`，对准测试程序入口 `_start`。同时引入 `valid` 状态位，复位期间 `valid = 0` 锁死所有的写寄存器、写内存和跳转。
    

### 4.2 问题二：LoongArch 多段操作码译码的理解与实现

- **问题描述**：LoongArch 指令采用不等宽的操作码字段（op[31:26]、op[25:22]、op[21:20]、op[19:15]）联合判定，若直接写 large case 或 nested if-else，极易导致混叠或漏掉某些条件。
    
- **解决方法**：在 `tools.v` 中实现了 4 个参数化译码器将各个位段先转成 one-hot 编码，再按位相与。新增指令仅需要添加单行 assignment 语句，互不干扰。
    

### 4.3 问题三：流水线 valid/allowin 握手协议的因果依赖理解

- **问题描述**：valid、ready_go、allowin 形成的“反向反压”传播与正常的数据流方向相反，时序因果关系的微小失误极易引发流水线永久锁死（Deadlock）或数据丢步。
    
- **解决方法**：通过建立严格的一致性三信号赋值模板，明确 allowin 表达式的布尔物理意义（“本级空，或者本级虽然有数据但是下一级允许接收数据”）。从而自 WB 级向 IF 级依次倒推。
    

### 4.4 问题四：同步 SRAM 的写时序适配

- **问题描述**：对于同步 SRAM 存储器（`sync_ram.v`），它的地址和使能必须提前一个时钟沿前稳定，才能在时钟采样时写入。若 st.w 的控制在 MEM 级才发出，会导致写入延迟一拍，与 golden trace 错位。
    
- **解决方法**：将同步数据存储器的 WE、ADDR 和 WDATA 控制端口**提前到 EXE 级**组合输出（EXE 级的 ALU 结果已算好地址）。这样 SRAM 在 EXE→MEM 的时钟上升沿对输入采样，完美在 MEM 周期内完成实际写入动作，ld.w 指令也刚好在 MEM 级采样读回。
    

## 5 总结与收获

本次系统能力综合实践完整研制了基于 20 条 LoongArch 指令集的单周期 CPU 与理想五级流水线 CPU。通过 golden trace 的逐时钟、逐指令精确比对，功能完全符合规范。两套设计共享了底层的基础运算部件（ALU、译码器、通用寄存器堆），体现了模块化复用设计的良好工程规范。

流水线 CPU 在性能和最大主频上体现了对单周期 CPU 的显著跨越，但理想型流水线的局限也促使我们了解并向着实现数据旁路、Load-Use 停顿、以及分支预测等现代高性能微处理器结构的核心领域进发。
