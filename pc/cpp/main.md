## [图论]
#图论

1. 题目要求在图上“永远移动下去 (infinitely / forever)”。
2. 每一步必须满足某种条件（如图节点状态随时间周期变化）。
___
**【Back - 背面】**

**💡 核心思想：反向拓扑与死胡同消除 (Dead-end Pruning)**

* **套路：** 建立 `State = (Node, Time)`。反向计算所有合法状态的出度。将出度为 0 的状态入队并像剥洋葱一样反向 BFS。
* **结论：** 队列清空后，所有**出度仍大于 0 的状态**就是能无限走下去的安全状态。

#哈密顿路径 #棋盘染色

**🔍 触发特征：**

1. 网格图 (Grid)。
2. 要求遍历所有格子且不重复（哈密顿路径）。
3. 存在不可到达的障碍物或缺失格子。
___
**【Back - 背面】**

**💡 核心思想：黑白染色奇偶校验 + 行对分块构造**

* **套路 1 (判定)：** 棋盘染色。如果是偶数网格，缺失的必定是与起点终点奇偶性不同的颜色（如起点终点为白，缺失格必须为黑）。
* **套路 2 (构造)：** 将偶数网格横向切分成 $2 \times N$ 的“行对”。完整行对用“贪吃蛇”平推，残缺行对用“上下 Zigzag (波浪)”绕过缺口并翻转奇偶性。


## [最短路]
#dial #dijstra

**🔍 触发特征：**

1. 巨型图求最短路（点边规模 $10^6 \sim 10^7$）。
2. **边权极小**（只有 0, 1, 2 等极小常数）。
___
**【Back - 背面】**

**💡 核心思想：滚动桶队列 (Cyclic Bucket Queue / Dial's Algorithm)**

* **套路：** 绝对不要用 `priority_queue` ($O(M \log N)$ 必 TLE)。开 $K+1$ 个 `vector` 作为桶（$K$ 为最大边权）。每次按距离对 $K+1$ 取模 `d % (K+1)` 来存取节点。
* **复杂度：** 强行将最短路降维至绝对的线性 $O(N+M)$。



## [数组区间操作]
#区间操作 #位运算 #lcm #gcd

**🔍 触发特征：**

求所有子区间的 **LCM / GCD / 按位或(OR) / 按位与(AND)** 的去重集合、总和或最值。

___
**【Back - 背面】**

**💡 核心思想：Log-Trick / 滚动区间状态压缩**

* **原理：** 固定右端点向左延伸，这些位运算的结果具有**单调性**，且最多跳变 $\log M$ 次（如 GCD 每次变小至少除以 2）。
* **套路：** 扫描数组，用一个极小的 `vector` 或 `set` 维护“以上一个元素结尾的合法结果”。每次用当前元素与它们运算，加入自身，然后**立刻排序去重**，传递给下一轮。时间复杂度降至 $O(N \log M)$。


## [置换算法]
#字典树 #优先队列

**🔍 触发特征：**

树形结构 / 字典树 (Trie) 上的缓存淘汰。已知未来所有访问序列，求最小缓存缺失代价。
___
**【Back - 背面】**

**💡 核心思想：Belady 最优置换算法 (离线缓存) + 深度打破平局**

* **套路：** 永远淘汰**未来最晚被访问**的节点。用包含 `(下次访问时间, 节点深度, node_id)` 的大根堆模拟。
* **护城河机制：** 当下一次访问时间相同时（如均为 $\infty$），**必须优先淘汰深度最深（叶子）的节点**，保证字典树结构不会从中间断裂。

## [对数降维套路]
#lcm

在不大于 $M$ 的数当中, 最多有多少个不同的 $LCM$ ?
___
这个问题问得太准了！这是整个“Log-Trick（对数降维套路）”最核心的灵魂所在。很多选手只会背代码，却不明白为什么状态集合不会爆炸。

作为教练，我用最通俗且严谨的数学逻辑，为你把这个结论彻底推导一遍。

### 核心定理：只要 LCM 发生改变，它**至少会翻倍**！

假设我们固定了子区间的右端点为 $r$，然后让左端点 $l$ 不断向左延伸（$l = r, r-1, r-2, \dots$）。
随着新数字的不断加入，区间的 LCM 会形成一个序列：

* $L_1 = a_r$
* $L_2 = \text{lcm}(a_{r-1}, L_1)$
* $L_3 = \text{lcm}(a_{r-2}, L_2)$
* ... 依次类推

根据最小公倍数（LCM）的数学定义：**两个数的最小公倍数，必定是原来每一个数的倍数。**
也就是说，新产生的 LCM（比如 $L_2$），必定是旧 LCM（$L_1$）的整数倍。
即：$L_2 = k \times L_1$ （其中 $k$ 是某个正整数）。

接下来是最关键的逻辑推导：
当一个新数字加进来时，LCM 只有两种命运：

1. **没有产生新质因子，LCM 不变：** 此时 $k = 1$，即 $L_2 = L_1$。既然没变，我们在去重集合里它还是原来的那一个，**不同 LCM 的数量没有增加**。
2. **产生了新质因子，LCM 改变了：** 既然改变了，那么倍数 $k$ 绝对不可能等于 1。既然 $k$ 是正整数且 $k > 1$，那么 **$k$ 最小也得是 2**！

### 极限推导：指数级增长的恐怖速度

既然每一次 LCM 只要发生**实质性的改变**，它都**至少乘以 2**。我们来看看极端情况：
假设我们从最小的正整数 1 开始，每次都让 LCM 发生改变，它的增长轨迹至少是这样的：

* 第 1 个不同的 LCM：$\ge 1$
* 第 2 个不同的 LCM：$\ge 2$
* 第 3 个不同的 LCM：$\ge 4$
* 第 4 个不同的 LCM：$\ge 8$
* ……
* 第 $x$ 个不同的 LCM：$\ge 2^{x-1}$

题目中我们设定了一个天花板（上限）$M$（在幽默数那题里 $M = 3 \times 10^6$）。
如果 $2^{x-1} \le M$，解这个不等式，立刻就能得到：


$$x - 1 \le \log_2(M)$$

$$x \le \log_2(M) + 1$$

### 具象化例子

假设数组是 `[3, 5, 2, 7]`，固定右端点为 `7`，向左延伸：

1. 包含 `[7]`，LCM 是 **7**。
2. 加入 `2`，变成 `[2, 7]`，LCM 是 $\text{lcm}(2, 7) =$ **14**。（变化了，乘了 2）
3. 加入 `5`，变成 `[5, 2, 7]`，LCM 是 $\text{lcm}(5, 14) =$ **70**。（变化了，乘了 5）
4. 加入 `3`，变成 `[3, 5, 2, 7]`，LCM 是 $\text{lcm}(3, 70) =$ **210**。（变化了，乘了 3）

你看，每次变化，数值都在成倍地飙升！对于 $M = 3,000,000$，因为 $\log_2(3,000,000) \approx 21.5$，这意味着**无论前面的数组有多长、数字有多复杂，只要上限是 300 万，以任意位置为结尾的有效不同 LCM，绝对不可能超过 22 个！**

这就是为什么我们在代码里用 `vector` 存状态，即使面对 $10^5$ 长度的数组，内层循环也永远最多只跑 22 次的原因。

## [问题 D：破烂背包](https://icpc.upc.edu.cn/problem.php?cid=4598&pid=3)
#背包DP #DP


题目描述
唐克老师收集完西瓜，决定给带一些给张老师分享
唐克老师统计了自己摘到的 n 个西瓜，其中第 i 个西瓜的重量为 ai
现在唐克老师准备选一些西瓜凑到重量恰好为 m，然后装在他心爱的小背包里带给张老师
但是当唐克老师背着西瓜找到张老师的时候，他发现他的背包居然破了！
于是唐克老师急忙拿出背包里的西瓜检查，看看是否有西瓜丢失
现在唐克老师想知道，从背包里拿出来的西瓜总重量可能有哪些情况？
P.S.1 如果某个原本装在背包里的西瓜丢失了，那么一定是这个西瓜整个丢失了，不会出现一个重量为 ai 的西瓜摔碎了丢了一部分这种情况
P.S.2 可能没有西瓜丢失，也有可能西瓜全丢了

**数据范围**
$$1 \leq n, m, a_i \leq 500$$

**输入**
输入第一行包含两个整数 n,m 含义如题
输入第二行包含 n 个整数 ai，分别表示每个西瓜的重量


**输出**
输出一行包含若干个整数，表示背包里剩余西瓜可能的总重量，从小到大依次输出，中间用空格隔开

**样例输入**
```
5 8
4 3 4 4 1
```

**样例输出**
```
0 1 3 4 5 7 8
```

___

**三维背包**模板, 

定义 $dp[i][j][k]$ 为前 $i$ 个西瓜中选择重量为 $j$ 的西瓜, 剩下重量为 $k$ 的西瓜是否存在

那么有 $3$ 状态可以转移:

1. 不取第 $i$ 个西瓜 $dp[i-1][j][k]$
2. 取第 $i$ 个西瓜, 并且不掉 $dp[i-1][j-a[i]][k]$
3. 取第 $i$ 个西瓜, 并且掉了 $dp[i-1][j-a[i][k-a[i]]$

即
$$
dp[i][j][k ] = dp[i-1][j][k] | dp[i-1][j-a[i]][k] | dp[i-1][j-a[i]][k-a[i]]
$$

然后用常用的背包优化方法优化掉 $i$ 

## [K. The Cage in ASZoo](https://codeforces.com/gym/105940/problem/K)
# 背包DP #DP #完全背包

ASZoo动物园里有一个巨大的笼子，最多能容纳$$$k$$$只动物。

共有$$$n$$$个动物家族，每个家族都有无限数量的成员，每种动物的体重为$$$a &#95; i$$$（$$$1 \le i \le n$$$）。

管理员决定在笼子里放置恰好$$$k$$$只动物，不限定种类或体重。管理员可以在笼中放入同一家族的多个动物，也可以舍弃整个家族不将其放入笼中。

求管理员可能实现的笼中动物总重量的所有可能取值。

**Input**

The first line contains two integers $n$ and $k$ ($1 \le n, k \le 1000$).

The second line contains $n$ integers $a_1, a_2, ..., a_n$ ($1 \le a_i \le 1000$).

___

这位同学，题目收到了！这道《ASZoo动物园》非常经典，是 Codeforces 甚至各种大厂笔试中经常出现的「思维型背包」神题。

如果你用传统的二维 DP 去解，这道题会变成一个极其臃肿且必然超时的怪物。但只要你在数学模型上做一个极其巧妙的「基准线平移」，它瞬间就会降维成一道最基础的一维完全背包。

咱们废话不多说，直接启动「四阶段拆解」！

---

### 第 0 阶段，理清题意

题目核心诉求很简单：
在一个大小为 $n$ 的集合中（包含重复元素，每种元素可以无限次使用），我们需要**恰好**选出 $k$ 个元素，求所有可能组合出来的「总重量」。

---

### 第一阶段：约束分析与前置扫盲

#### 1. 数据范围透视

* $n, k \le 1000$
* $1 \le a_i \le 1000$

**绝望的传统思路**：
如果按老套路定义 $dp[i][w]$ 表示“选了 $i$ 个动物，总重量是否能为 $w$”。
此时 $w$ 的最大值是 $k \times \max(a_i) = 1000 \times 1000 = 10^6$。
状态数多达 $1000 \times 10^6 = 10^9$。不仅时间稳稳地 TLE（超时），连开个 `bool` 的二维数组都需要 1GB 内存，直接 MLE（内存超限）。

#### 2. 前置扫盲与核心定理

我们急需把二维的状态（个数、重量）降维到一维。

> 💡 **教练的灵魂拷问**：
> 限制我们降维的最大元凶，是题目要求**「恰好」**选 $k$ 个。如果我少选了，重量不够；多选了，数量超标。
> **但是，如果你手里有一种动物，它的重量恰好是 `0`，这个“恰好 $k$ 个”的限制是不是就不攻自破了？**
> *(仔细想一想：如果我有重量为 0 的动物，我只需要求“最多选 $k$ 个非 0 动物能凑出的重量”，剩下的空位全部用 0 填满，不就变成“恰好 $k$ 个”了吗！)*

---

### 第二阶段：思维推导与思想解构

#### 1. 直觉的诞生：基准转换（The Aha! Moment）

现实中没有重量为 0 的动物，但我们可以在**相对参照系**里创造一个！

1. 假设我们将所有给定的重量 $a_i$ 进行排序，找出最轻的动物重量，记为 $a_{min}$。
2. 既然我们“无论如何”都要选 $k$ 只动物，那最朴素的想法就是：**我先把这 $k$ 个笼子全部塞满最轻的动物 $a_{min}$。**
3. 此时的基础总重量是 $Base = k \times a_{min}$。
4. 接下来，我要把笼子里的一些 $a_{min}$ 揪出来，替换成其他稍微重一点的动物 $a_i$。
5. **核心变化：** 我每把一个 $a_{min}$ 换成 $a_i$，笼子的总重量就会**增加** $d_i = a_i - a_{min}$。

#### 2. 核心思想的质变

当我们把所有的 $a_i$ 转换为相对重量 $d_i = a_i - a_{min}$ 时，最轻的那个动物的相对重量 $d_{min}$ 就变成了 $0$！

问题瞬间被等价替换成了：
**在一个物品集合 $\{d_i\}$ 中，挑选最多 $k$ 个物品，能凑出哪些总重量 $w_{diff}$？**
（为什么是“最多 $k$ 个”？因为如果你只挑了 $m$ 个正数 $d_i$（$m \le k$），剩下的 $k-m$ 个空位，你可以理直气壮地说：“我挑了重量为 $0$ 的 $d_{min}$！”）

#### 3. 彻底降维为完全背包

要判断一个增量 $w_{diff}$ 能不能在 $\le k$ 次替换内凑出来，我们只需要知道：**凑出增量 $w_{diff}$，最少需要几个物品？**
只要“最少需要的物品数 $\le k$”，那么它就一定合法！

状态定义：$dp[j]$ 表示凑出相对重量 $j$，所需要的最少物品数。
转移方程：$dp[j] = \min(dp[j], dp[j - d_i] + 1)$
这就是最经典的**求最小值的完全背包**，时间复杂度降到了 $O(n_{唯一} \times w_{max\_diff})$，空间被无情压缩到了区区几 MB！

---

### 第三阶段：母题提炼与破局套路

#### 1. 母题与模型

这道题属于「定数（恰好K个）完全背包模型」**的特例。
通用「模板套路」：
对于任何“恰好选 $K$ 个，求所有可能总和”的问题：
第一步：求出数组最小值 `min_val`，计算基底和 `base = K * min_val`。
第二步：所有元素减去 `min_val`，得到差分数组 `d`。
第三步：利用一维 DP 跑完全背包求**最小个数。
第四步：遍历 DP 数组，只要 `dp[w] <= K`，那么 `base + w` 就是一个合法的真实总和。

#### 2. 肌肉记忆触发点

下次在考场上，看到：

* **「恰好选 K 个物品求总和」**
* **$K$ 很大，或者总和很大导致 DP 爆空间**
* **物品价值差距不大（或者最大值不大）**
👉 **立刻条件反射**：**最小值偏移法（也叫同余/差分建图）！立刻让最小物体的体积变为0，把“恰好 $k$ 件”化解为“不超过 $k$ 件”！**

---

### 第四阶段：工业级代码实现

这段代码极致压榨了常数时间，并做了去重优化，在各大 OJ 上都能跑到 `0ms` 到 `15ms` 内。

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

// 无穷大，用于初始化求最小值的 DP 数组
const int INF = 0x3f3f3f3f; 

int main() {
    // 工业级素养：解除 C++ 系统的 IO 同步，极大提升读写速度
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int n, k;
    if (!(cin >> n >> k)) return 0;

    vector<int> a(n);
    for (int i = 0; i < n; ++i) {
        cin >> a[i];
    }

    // 优化：排序并去重。重复的重量在完全背包中没有任何意义，极大降低外层循环次数
    sort(a.begin(), a.end());
    a.erase(unique(a.begin(), a.end()), a.end());

    int min_a = a[0];
    // 最大的可能相对增量，即全部替换成最重的那种动物
    int max_diff = k * (a.back() - min_a);

    // dp[w] 物理意义：凑出相对重量 w，最少需要替换几个动物
    // 初始化全为 INF，表示一开头什么重量都凑不出来
    vector<int> dp(max_diff + 1, INF);
    
    // 循环不变量：dp[0] 永远为 0（凑出相对重量 0，不需要替换任何动物）
    dp[0] = 0;

    // 遍历所有可能的差值种类（从第1个开始，因为第0个是最小值，差值为0无意义）
    for (size_t i = 1; i < a.size(); ++i) {
        int d = a[i] - min_a; // 相对重量（替换代价）
        
        // 完全背包的正序遍历：一个物品可以使用无数次
        for (int w = d; w <= max_diff; ++w) {
            if (dp[w - d] != INF) {
                // 如果能凑出前置重量，就尝试用当前的动物 d 去更新最小步数
                if (dp[w - d] + 1 < dp[w]) {
                    dp[w] = dp[w - d] + 1;
                }
            }
        }
    }

    // 收集合法答案，从小到大输出
    bool first = true;
    for (int w = 0; w <= max_diff; ++w) {
        // 边界条件判断：如果凑出相对重量 w 的最少替换次数 <= k
        // 说明我们可以把剩下的 (k - dp[w]) 个位置安插上最小动物，从而达成“恰好 k 个”！
        if (dp[w] <= k) {
            if (!first) cout << " ";
            // 真实重量 = 基础重量(全放最小动物) + 相对重量
            cout << 1LL * k * min_a + w; 
            first = false;
        }
    }
    cout << "\n";

    return 0;
}

```

#### 避坑指南（Fatal Mistakes）

1. **忘记去重 (`unique`)：** 如果输入是 $1000$ 个相同的数字，外层循环会跑 $1000$ 遍毫无意义的废代码。去重后，最坏情况外层也只有不超过 1000 个不同的数字，有效防止被奇葩数据卡常。
2. **`INF` 初始化陷阱：** 初始化 `dp` 时绝对不要随便写个 `999999`。工业标准写法是 `0x3f3f3f3f`，它能保证你在做加法（比如 `dp[w-d] + 1`）时绝对不会越界变成负数（如果是 `INT_MAX` 加上 1 就会溢出报错），同时也足够大，大于本题的最大 $k$ (1000)。
3. **输出时的爆 `int` 危机：** 虽然本题 $k \times a_{max}$ 最大是 $10^6$，在 `int` 范围内；但在很多变体题目中 $k$ 会大到 $10^9$。养成好习惯，计算最终真实重量时加上 `1LL *`（如我代码倒数第 7 行所写），强转 `long long` 避免低级溢出。

**树上启发式合并**

一个在树上遍历的公用的记录颜色次数

当遍历到一个节点的时候

第一次遍历轻儿子节点, 算出他们各自的主导颜色, 然后擦除记录

第二次遍历重儿子, 保留记录

再次遍历轻儿子, 保留记录, 这样就得到这个节点的主导颜色

专门用一个递归函数`add`, 计算这个节点的颜色

```cpp
void solve(){
    int n; cin >> n;
    vector<int> color(n + 1);
    fi(n) cin >> color[i];

    vector<vi> adj(n + 1);
    fi(n-1){
        int u, v; cin >> u >> v;
        adj[u].push_back(v);
        adj[v].push_back(u);
    }

    vector<int> son(n + 1, 0), sz(n + 1, 0);
    auto dfs = [&](auto self, int u, int fa)->void{
        sz[u] = 1;
        for(auto v : adj[u]){
            if(v == fa) continue;
            self(self, v, u);
            sz[u] += sz[v];
            if(sz[son[u]] < sz[v]) son[u] = v;
        }
    };
    dfs(dfs, 1, 0);

    // DSU on Tree 核心全局数据
    vector<int> cnt(N, 0); // O(1) 极速数组，直接取代 unordered_map
    vector<int> ans(n + 1, 0);
    int skip = 0;

    // 动态维护的终极武器，时间复杂度降维的核心！
    int max_cnt = 0;
    int sum_max = 0;

    auto add = [&](auto self, int u, int fa, int val)->void{
        if(val == 1){
            cnt[color[u]]++;
            // O(1) 更新答案：无需遍历全表！
            if (cnt[color[u]] > max_cnt) {
                max_cnt = cnt[color[u]];
                sum_max = color[u]; // 新皇登基，旧的 sum 直接被替代
            } else if (cnt[color[u]] == max_cnt) {
                sum_max += color[u]; // 并列第一，加入联盟
            }
        } else {
            cnt[color[u]]--;
            // 重点注意：删除时我们【不需要】去更新 max_cnt 和 sum_max！
            // 因为删除只会发生在 keep = false 时。
            // 而 keep = false 的结尾，我们会直接把 max_cnt 和 sum_max 清零！
        }

        for(auto v : adj[u]){
            if(v == fa || v == skip) continue;
            self(self, v, u, val);
        }
    };

    auto get_ans = [&](auto self, int u , int fa, bool keep)->void{
        // 1. 轻儿子算完并擦除
        for(auto v : adj[u]){
            if(v == fa || v == son[u]) continue;
            self(self, v, u, false);
        }

        // 2. 重儿子算完并保留
        if(son[u]){
            self(self, son[u], u, true);
            skip = son[u]; // 穿上防弹衣
        }

        // 3. 把轻儿子和自己暴力加进黑板
        add(add, u, fa, 1);

        // 4. 此时黑板和全局维护变量是最完美的，直接记录答案！
        ans[u] = sum_max;

        // 5. 收尾清理
        skip = 0; // 卸下防弹衣
        if(!keep) {
            add(add, u, fa, -1);
            // 擦黑板的同时，必须把全局维护变量也归零
            max_cnt = 0;
            sum_max = 0;
        }
    };

    get_ans(get_ans, 1, 0, true); // 根节点的 keep 最好为 true，尽管对于整棵树没所谓

    fi(n) cout << ans[i] << ' ';
    cout << endl;
}
```

## [K. The Cage in ASZoo](https://codeforces.com/gym/105940/problem/K)

ASZoo动物园里有一个巨大的笼子，最多能容纳$$$k$$$只动物。

共有$$$n$$$个动物家族，每个家族都有无限数量的成员，每种动物的体重为$$$a &#95; i$$$（$$$1 \le i \le n$$$）。

管理员决定在笼子里放置恰好$$$k$$$只动物，不限定种类或体重。管理员可以在笼中放入同一家族的多个动物，也可以舍弃整个家族不将其放入笼中。

求管理员可能实现的笼中动物总重量的所有可能取值。

**Input**

The first line contains two integers $n$ and $k$ ($1 \le n, k \le 1000$).

The second line contains $n$ integers $a_1, a_2, ..., a_n$ ($1 \le a_i \le 1000$).

___


如果你用传统的二维 DP 去解，这道题会变成一个极其臃肿且必然超时的怪物。但只要你在数学模型上做一个极其巧妙的「基准线平移」，它瞬间就会降维成一道最基础的一维完全背包。

咱们废话不多说，直接启动「四阶段拆解」！

---

### 第 0 阶段，理清题意

题目核心诉求很简单：
在一个大小为 $n$ 的集合中（包含重复元素，每种元素可以无限次使用），我们需要**恰好**选出 $k$ 个元素，求所有可能组合出来的「总重量」。

---

### 第一阶段：约束分析与前置扫盲

#### 1. 数据范围透视

* $n, k \le 1000$
* $1 \le a_i \le 1000$

**绝望的传统思路**：
如果按老套路定义 $dp[i][w]$ 表示“选了 $i$ 个动物，总重量是否能为 $w$”。
此时 $w$ 的最大值是 $k \times \max(a_i) = 1000 \times 1000 = 10^6$。
状态数多达 $1000 \times 10^6 = 10^9$。不仅时间稳稳地 TLE（超时），连开个 `bool` 的二维数组都需要 1GB 内存，直接 MLE（内存超限）。

#### 2. 前置扫盲与核心定理

我们急需把二维的状态（个数、重量）降维到一维。

> 💡 **教练的灵魂拷问**：
> 限制我们降维的最大元凶，是题目要求**「恰好」**选 $k$ 个。如果我少选了，重量不够；多选了，数量超标。
> **但是，如果你手里有一种动物，它的重量恰好是 `0`，这个“恰好 $k$ 个”的限制是不是就不攻自破了？**
> *(仔细想一想：如果我有重量为 0 的动物，我只需要求“最多选 $k$ 个非 0 动物能凑出的重量”，剩下的空位全部用 0 填满，不就变成“恰好 $k$ 个”了吗！)*

---

### 第二阶段：思维推导与思想解构

#### 1. 直觉的诞生：基准转换（The Aha! Moment）

现实中没有重量为 0 的动物，但我们可以在**相对参照系**里创造一个！

1. 假设我们将所有给定的重量 $a_i$ 进行排序，找出最轻的动物重量，记为 $a_{min}$。
2. 既然我们“无论如何”都要选 $k$ 只动物，那最朴素的想法就是：**我先把这 $k$ 个笼子全部塞满最轻的动物 $a_{min}$。**
3. 此时的基础总重量是 $Base = k \times a_{min}$。
4. 接下来，我要把笼子里的一些 $a_{min}$ 揪出来，替换成其他稍微重一点的动物 $a_i$。
5. **核心变化：** 我每把一个 $a_{min}$ 换成 $a_i$，笼子的总重量就会**增加** $d_i = a_i - a_{min}$。

#### 2. 核心思想的质变

当我们把所有的 $a_i$ 转换为相对重量 $d_i = a_i - a_{min}$ 时，最轻的那个动物的相对重量 $d_{min}$ 就变成了 $0$！

问题瞬间被等价替换成了：
**在一个物品集合 $\{d_i\}$ 中，挑选最多 $k$ 个物品，能凑出哪些总重量 $w_{diff}$？**
（为什么是“最多 $k$ 个”？因为如果你只挑了 $m$ 个正数 $d_i$（$m \le k$），剩下的 $k-m$ 个空位，你可以理直气壮地说：“我挑了重量为 $0$ 的 $d_{min}$！”）

#### 3. 彻底降维为完全背包

要判断一个增量 $w_{diff}$ 能不能在 $\le k$ 次替换内凑出来，我们只需要知道：**凑出增量 $w_{diff}$，最少需要几个物品？**
只要“最少需要的物品数 $\le k$”，那么它就一定合法！

状态定义：$dp[j]$ 表示凑出相对重量 $j$，所需要的最少物品数。
转移方程：$dp[j] = \min(dp[j], dp[j - d_i] + 1)$
这就是最经典的**求最小值的完全背包**，时间复杂度降到了 $O(n_{唯一} \times w_{max\_diff})$，空间被无情压缩到了区区几 MB！

---

### 第三阶段：母题提炼与破局套路

#### 1. 母题与模型

这道题属于「定数（恰好K个）完全背包模型」**的特例。
通用「模板套路」：
对于任何“恰好选 $K$ 个，求所有可能总和”的问题：
第一步：求出数组最小值 `min_val`，计算基底和 `base = K * min_val`。
第二步：所有元素减去 `min_val`，得到差分数组 `d`。
第三步：利用一维 DP 跑完全背包求**最小个数。
第四步：遍历 DP 数组，只要 `dp[w] <= K`，那么 `base + w` 就是一个合法的真实总和。

#### 2. 肌肉记忆触发点

下次在考场上，看到：

* **「恰好选 K 个物品求总和」**
* **$K$ 很大，或者总和很大导致 DP 爆空间**
* **物品价值差距不大（或者最大值不大）**
👉 **立刻条件反射**：**最小值偏移法（也叫同余/差分建图）！立刻让最小物体的体积变为0，把“恰好 $k$ 件”化解为“不超过 $k$ 件”！**

---

### 第四阶段：工业级代码实现

这段代码极致压榨了常数时间，并做了去重优化，在各大 OJ 上都能跑到 `0ms` 到 `15ms` 内。

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

using namespace std;

// 无穷大，用于初始化求最小值的 DP 数组
const int INF = 0x3f3f3f3f; 

int main() {
    // 工业级素养：解除 C++ 系统的 IO 同步，极大提升读写速度
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int n, k;
    if (!(cin >> n >> k)) return 0;

    vector<int> a(n);
    for (int i = 0; i < n; ++i) {
        cin >> a[i];
    }

    // 优化：排序并去重。重复的重量在完全背包中没有任何意义，极大降低外层循环次数
    sort(a.begin(), a.end());
    a.erase(unique(a.begin(), a.end()), a.end());

    int min_a = a[0];
    // 最大的可能相对增量，即全部替换成最重的那种动物
    int max_diff = k * (a.back() - min_a);

    // dp[w] 物理意义：凑出相对重量 w，最少需要替换几个动物
    // 初始化全为 INF，表示一开头什么重量都凑不出来
    vector<int> dp(max_diff + 1, INF);
    
    // 循环不变量：dp[0] 永远为 0（凑出相对重量 0，不需要替换任何动物）
    dp[0] = 0;

    // 遍历所有可能的差值种类（从第1个开始，因为第0个是最小值，差值为0无意义）
    for (size_t i = 1; i < a.size(); ++i) {
        int d = a[i] - min_a; // 相对重量（替换代价）
        
        // 完全背包的正序遍历：一个物品可以使用无数次
        for (int w = d; w <= max_diff; ++w) {
            if (dp[w - d] != INF) {
                // 如果能凑出前置重量，就尝试用当前的动物 d 去更新最小步数
                if (dp[w - d] + 1 < dp[w]) {
                    dp[w] = dp[w - d] + 1;
                }
            }
        }
    }

    // 收集合法答案，从小到大输出
    bool first = true;
    for (int w = 0; w <= max_diff; ++w) {
        // 边界条件判断：如果凑出相对重量 w 的最少替换次数 <= k
        // 说明我们可以把剩下的 (k - dp[w]) 个位置安插上最小动物，从而达成“恰好 k 个”！
        if (dp[w] <= k) {
            if (!first) cout << " ";
            // 真实重量 = 基础重量(全放最小动物) + 相对重量
            cout << 1LL * k * min_a + w; 
            first = false;
        }
    }
    cout << "\n";

    return 0;
}

```

#### 避坑指南（Fatal Mistakes）

1. **忘记去重 (`unique`)：** 如果输入是 $1000$ 个相同的数字，外层循环会跑 $1000$ 遍毫无意义的废代码。去重后，最坏情况外层也只有不超过 1000 个不同的数字，有效防止被奇葩数据卡常。
2. **`INF` 初始化陷阱：** 初始化 `dp` 时绝对不要随便写个 `999999`。工业标准写法是 `0x3f3f3f3f`，它能保证你在做加法（比如 `dp[w-d] + 1`）时绝对不会越界变成负数（如果是 `INT_MAX` 加上 1 就会溢出报错），同时也足够大，大于本题的最大 $k$ (1000)。
3. **输出时的爆 `int` 危机：** 虽然本题 $k \times a_{max}$ 最大是 $10^6$，在 `int` 范围内；但在很多变体题目中 $k$ 会大到 $10^9$。养成好习惯，计算最终真实重量时加上 `1LL *`（如我代码倒数第 7 行所写），强转 `long long` 避免低级溢出。
