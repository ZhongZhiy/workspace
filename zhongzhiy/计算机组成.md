### 第 1 章：中央处理器 (Central Processing Unit)

#### 1. 核心考点与题型

- **单周期与多周期处理器的本质区别（高频判断/选择题）**：
    
    - 单周期处理器：每条指令在一个时钟周期内完成，其 $CPI = 1$。但时钟周期会很长，通常取决于**最复杂、最慢的那条指令**（如 `lw` 或分支指令）。
        
    - 多周期处理器：一条指令分成多个时钟周期完成，不同的指令周期数不同，其 $CPI > 1$。
        
- **控制器的实现**：硬连线控制器与微程序控制器。微程序控制器的设计思想是通过执行一段微程序来实现一条指令的功能，结构规整、灵活性高，但速度较慢。
    
- **数据通路基本组件**：状态元件（PC、寄存器组、存储器）和组合逻辑元件（ALU、加法器、多路选择器Mux）。**注意**：ALU 和加法器等组合逻辑也需要控制信号来决定其运算功能。
    

#### 2. 核心大题突破：MIPS 指令数据通路与控制信号分析

试卷中连续两年作为高分大题出现，通常以 `beq rs, rt, 100` 或 `bne rs, rt, 100` 指令为例：

- **基本连线技能**：要求在 MIPS 单周期处理器结构图上用箭头画出某一指令执行时的数据通路（画出除控制信号外所有数据经过的部件及路径）。如果是多路选择器（Mux），需要将箭头穿过对应的数值路径（如 $0$ 或 $1$）。
    
- **控制信号取值填空**：
    
    - 对于分支指令（如 `beq`/`bne`）：不写寄存器（$RegWr=0$），不写存储器（$MemWr=0$），是分支指令（$Branch=1$），不是跳转指令（$Jump=0$）。
        
    - $Zero$ 状态取决于寄存器比较结果：若两寄存器内容相等，ALU 做减法后 $Zero=1$；若不相等，则 $Zero=0$。
        
- **目标地址与 PC 计算（极易错点）**：
    
    - 汇编指令中的立即数（如 100）代表的是**存储单元个数**（或指令条数）。
        
    - 在机器指令的 16 位立即数字段（`immediate`）中，该值表示的是**指令条数**。因为 MIPS 每条指令占 4 个字节，所以机器码中的立即数通常需要通过计算得出（即汇编中的字节偏移量除以 4）。
        
    - **PC 值的计算公式**：
        
        - 若分支条件**不满足**（如 `beq` 时不相等）：$PC = PC_{current} + 4$。
            
        - 若分支条件**满足**（如 `beq` 时相等）：$PC = PC_{current} + 4 + \text{立即数} \times 4$。_(注意：试卷中地址常用十六进制和十六进制加法表示，如 $2000H + 4 + 100 = 2000H + 4 + 64H = 2068H$)_。
            

### 第 2 章：指令流水线 (Instruction Pipelining)

#### 1. 核心考点与题型

- **流水线性能原理（高频判断题）**：
    
    - 流水线方式执行指令能提高整体的**吞吐率**，但**不能**使单条指令的执行时间变短。相反，由于增加了段寄存器（Pipeline Registers）的延迟，单条指令的延迟可能略微增加。
        
    - 段寄存器属于内部寄存器，对程序员来说是**透明**的（不可见），其主要作用是在时钟边界保存前一级流水线的结果，而不需要作为进程上下文在异常发生时进行现场保存。
        
- **流水线三大冒险（Hazards）**：结构冒险（硬件资源竞争）、数据冒险（指令间数据相关）、控制冒险（分支/跳转引起）。
    

#### 2. 核心大题突破：流水线数据冒险与转发（旁路）技术

结合 5 段流水线（IF、ID、EX、MEM、WB），试卷中常给出一系列寄存器操作代码片段（如 `add`, `sub`, `lw`, `or`）：

- **找出数据相关（RAW 冲突）**：分析后一条指令的源寄存器是否依赖前一条（或前两条）指令的目的寄存器。答题时需要指明冲突发生在哪两条指令之间、哪个寄存器、以及它们各自的流水线阶段（如：发生在指令 1 的 WB 段和指令 2 的 ID 段）。
    
- **设计转发（Forwarding/旁路）路径**：通过转发可以解决绝大部分 RAW 冒险。需要给出具体的旁路路径名称，例如：
    
    - `EX -> EX 旁路`：指令 $i$ 的 EX 段输出 $\rightarrow$ 指令 $j$ 的 EX 段输入。
        
    - `MEM -> EX 旁路`：指令 $i$ 的 MEM 段输出 $\rightarrow$ 指令 $j$ 的 EX 段输入。
        
- **Load-Use 冒险及其解决**：当前一条指令是加载指令（`lw`），而后一条指令立即需要使用该加载的数据时，单靠转发是无法在同一个时钟周期内解决的。**解决办法**：必须通过硬件阻塞（Stall）固定插入 1 个时钟周期，然后再配合转发技术解决。
    

### 第 3 章：存储器分层体系结构 (Memory Hierarchy)

#### 1. 核心考点与题型

- **存储芯片扩展设计（高频大题）**：
    
    - 要求利用较小容量的芯片（如 $1K \times 4$ 位芯片）组成较大容量的存储器（如 $8K \times 8$ 位）。
        
    - **连线图绘制**：位扩展（两片并联共同连接 $D_{0 \sim 3}$ 和 $D_{4 \sim 7}$）与字扩展（利用高位地址线通过译码器生成片选信号 $\overline{CS}$）。
        
    - **地址范围编写**：写出各芯片组对应的二进制和十六进制地址范围。
        
    - **DRAM 刷新**：若芯片是 DRAM，其刷新计数器的位数取决于**芯片的行数**（如 $1K$ 行需要 10 位计数器）。
        
- **存储器总线带宽计算**：
    
    - 公式：$\text{总带宽} = \text{通道数} \times \text{工作频率} \times (\text{总线宽度} / 8)$。
        
    - _例题：3 通道、工作频率 $2133\text{MHz}$、宽度 64 位，则带宽约为 $3 \times 2133\text{MHz} \times (64/8) \approx 51\text{GB/s}$_。
        
- **程序局部性与 Cache 命中率分析**：
    
    - 试卷中通过数组按行遍历（Program A）和按列遍历（Program B）来考查。
        
    - 行优先遍历由于与主存中数组的存放顺序相同，具有优秀的空间局部性。通常一个 Cache 块内的第 1 次访问缺失，后续的访问全部命中（命中率高，如 93.75%）。
        
    - 列优先遍历导致每次访问的步长远大于主存块大小，若 Cache 行数较少，会导致 Cache 行不断被写回和替换，命中率通常为 0。
        

#### 2. 核心大题突破：虚存、TLB 与 Cache 联合地址翻译

这是全卷分值最高、最综合、最考验基本功的大题。

- **基本字段切分技能**：必须在做题前将虚拟地址和物理地址的位数根据题意切分得非常精准：
    
    - $\text{虚拟地址} = \text{虚拟页号 (VPN)} + \text{页内偏移量 (VPO)}$
        
    - $\text{虚拟页号 (VPN)} = \text{TLB 标记 (TLB Tag)} + \text{TLB 组索引 (TLB Index)}$
        
    - $\text{物理地址} = \text{物理页号 (PPN)} + \text{页内偏移量 (PPO)}$ _(注意：$VPO = PPO$)_
        
    - $\text{物理地址} = \text{Cache 标记 (Cache Tag)} + \text{Cache 行索引 (Index)} + \text{块内地址 (Offset)}$
        
- **联合查询流程跟踪**：
    
    1. 拿到十六进制逻辑地址后，**先转换为二进制**。
        
    2. 根据字段宽度截取出 VPN 和 TLB Index。
        
    3. 查 TLB 表：看对应组里有没有匹配的 Tag 且有效位（Valid）为 1。
        
        - 若 **TLB 命中**：直接获取对应的物理页号（PPN）。
            
        - 若 **TLB 缺失**：必须去访问主存中的**页表**，查看对应虚拟页号（VPN）的表项，如果有效位为 1，取出 PPN（同时把该页表项调入 TLB）；如果有效位为 0，则触发**缺页故障**。
            
    4. 得到 PPN 后，与页内偏移拼接组合成完整的**物理地址**。
        
    5. 将物理地址重新按照 Cache 的映射规则（直接映射或组相联）切分为 Cache Tag、Index 和 Offset。
        
    6. 查 Cache 表：看对应行/组的 Tag 是否匹配且有效位为 1。如果命中，根据 Offset 从对应字节中取出数据。
        
- **Cache 总容量计算公式（不考虑一致性控制位）**：
    
    - $\text{总容量} = \text{行数} \times (\text{1位有效位} + \text{[1位脏位]} + \text{Tag位数} + \text{块大小} \times 8\text{位})$。
        
    - _注意：如果题目明确写着是“回写（Write back）”方式，必须额外加 1 位脏位；如果是“直写（Write through）”，则不需要脏位。_
        

### 第 4 章：异常控制流 (Exceptional Control Flow)

#### 1. 核心考点与题型

- **异常与中断的分类及判断**：
    
    - **中断（Interrupt）**：来自 CPU 外部外设的异步事件（如打印机缺纸、DMA 请求、时钟中断）。
        
    - **陷阱（Trap）/系统调用**：用户程序故意触发的同步事件（如调用内核的 `write` 函数，汇编指令为 `int $0x80`）。
        
    - **故障（Fault）**：潜在可恢复的同步错误（如**缺页故障**、**TLB 缺失**）。**核心特征**：异常处理程序执行完后，会**重新执行**触发异常的那条指令。
        
    - **终止（Abort）**：不可恢复的致命错误（如段错误 `segmentation fault`、硬件电平错误）。处理后直接终止用户进程。
        
- **系统调用执行机制（高频简答题）**：
    
    - 用户程序在执行系统调用前处于**用户态**（特权级 $CPL=3$）。
        
    - 执行软中断指令（如 `int $0x80`）后，通过**系统门**（或中断门描述符）切入内核，CPU 特权级切换为**内核态**（$CPL=0$）。对应的中断类型号一般为 `0x80`。
        

#### 2. 核心大题突破：多级中断与中断屏蔽字设计

- **两个优先级的区别**：
    
    - **响应优先级**：由硬件排队回路决定，代表 CPU 同时收到多个中断请求时，**先响应谁**的请求。
        
    - **处理优先级**：由硬件屏蔽字（Mask）决定，代表在处理某一级中断时，**谁能打断我**（实现中断嵌套）。
        
- **中断屏蔽字的设计准则**：
    
    - 处理优先级高的中断，在执行其处理程序时，应当能够屏蔽比它优先级低的中断。
        
    - 试卷中通常规定：`1` 表示屏蔽，`0` 表示开放（允许被打断）。
        
    - **公式**：某级中断处理程序的屏蔽字中，所有**处理优先级低于或等于它自身**的中断位，全部设为 `1`；所有**处理优先级高于它**的中断位，设为 `0`。
        
- **中断嵌套示意图**：要求根据同时发生或嵌套发生的中断请求，画出 CPU 随时间轴在各个中断服务程序之间切换跳转的阶梯型路线图。
    

### 第 5 章：互联及输入输出组织 (Interconnection and I/O Organization)

#### 1. 核心考点与题型

- **I/O 端口编址（高频选择题）**：
    
    - 统一编址（存储器映射编址）：I/O 端口和主存共享同一个地址空间，可以使用通用的访存指令（如 `mov`、`lw`）访问 I/O 端口。
        
    - 独立编址：I/O 端口拥有独立的地址空间，必须使用专门的 I/O 指令（如 `in`、`out`）进行访问。
        
- **连接通路顺序**：$\text{CPU/主存} \rightarrow \text{I/O总线} \rightarrow \text{I/O接口（外设控制器）} \rightarrow \text{设备通信电缆} \rightarrow \text{外设}$。
    
- **DMA 方式与中断方式的核心区别（高频多选/简答题）**：
    
    - **数据传送流向**：DMA 完全由硬件（DMA 控制器）控制总线完成数据在接口和主存间的传送；中断方式需要 CPU 执行软件程序来搬运数据。
        
    - **响应时机**：DMA 请求在**总线周期**（或时钟周期）结束后即可响应；中断请求必须在当前**指令周期**结束后才能响应。
        
    - **现场保存**：DMA 只是窃取总线控制权，不中止现行程序，不需要保存现场和断点；中断处理必须先暂停现行程序，保护断点和 CPU 状态（PC、PSW等入栈）。
        
    - **适用设备**：DMA 适用于高速设备的数据块传送；中断适用于低速、慢速设备，且中断还可以处理内部异常事件，DMA 则不行。
        

#### 2. 核心大题突破：三种 I/O 方式（查询、中断、DMA）的 CPU 开销计算

两年的考卷里都出现了这道涉及设备 A、B 吞吐率与 CPU 开销的计算大题：

- **定时查询方式计算**：
    
    - 根据外设传输速率（如 $2\text{MB/s}$）和接口寄存器大小（如 32位=4B），算出外设准备好一个数据所需的时间（$4\text{B}/2\text{MB/s} = 2\mu s$）。为了不丢数据，**最多每隔 $2\mu s$ 必须查询一次**。
        
    - 根据查询频率和每次查询执行的指令数（如 10条），结合主频和 CPI，即可算出每秒查询消耗的系统时钟周期数，进而求出占 CPU 总时间的百分比。
        
- **中断 I/O 方式适用性判定（重要考点）**：
    
    - 题目通常会给出高速设备（如 $40\text{MB/s}$），同样传输 32 位（4B）数据，外设准备好一个数据仅需 $4\text{B}/40\text{MB/s} = 0.1\mu s$。
        
    - 如果题目给出每次中断响应+处理的总周期换算成时间后（如 $400 \times (1/500\text{MHz}) = 0.8\mu s$）**大于**外设准备数据的时间（$0.8\mu s > 0.1\mu s$），说明在上一次中断还没处理完时，新数据就已经把旧数据覆盖刷新了，**因此该高速设备绝对不适合采用中断 I/O 方式**。
        
- **DMA 方式开销计算**：
    
    - DMA 是一次搬运一个大**数据块**（如 1000B）。
        
    - 计算出每秒发生 DMA 的次数（$\text{外设速率} / \text{数据块大小}$）。
        
    - 每次 DMA 预处理和后处理消耗 CPU 一定的时钟周期（如 500 个），乘以每秒 DMA 次数，即可得到 DMA 占用 CPU 时间的百分比（由于是一块搬运一次，这个百分比通常很小，体现了 DMA 的高效性）。
