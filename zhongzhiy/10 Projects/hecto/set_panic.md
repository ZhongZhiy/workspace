# 🦀 Rust Panic 核心指南卡片

### 1. 触发与本质 (Trigger)

`panic!` 用于处理**不可恢复**的错误。它会立即中断当前执行流。

- **显式触发**：`panic!("error message")`
    
- **隐式触发**：索引越界 `v[99]`、整数除以零、`unwrap()` 或 `expect()` 失败。
    
- **本质**：一种特殊的退出机制，默认会进行**栈展开 (Unwinding)**。
    

---

### 2. 处理机制 (Recovery)

虽然 Panic 意味着不可恢复，但在某些边界（如线程池、Web 网关）可以被拦截：

- **`catch_unwind`**：捕获栈展开，返回 `Result<T, Box<dyn Any>>`。
    
- **限制**：如果 `Cargo.toml` 配置了 `panic = 'abort'`，则无法捕获。
    

---

### 3. 自定义 Hook (`set_hook`)

允许在程序崩溃前执行自定义逻辑（如写日志、上报错误）。

- **函数签名**：`fn set_hook(hook: Box<dyn Fn(&PanicInfo<'_>) + Sync + Send + 'static>)`
    
- **关键约束**：
    
    - **`move` 关键字**：强制闭包获取捕获变量的所有权，以满足 `'static` 生命周期。
        
    - **`Sync + Send`**：确保钩子在多线程环境下是安全的。
        
    - **全局性**：它是全局资源，通常仅在 `main` 函数中设置一次。
        

---

### 4. 深度底层：核心概念对比

| **概念**       | **深度解读**                        | **作用**                    |
| ------------ | ------------------------------- | ------------------------- |
| **Unwind**   | 逐层调用析构函数（Drop）清理内存。             | 保证资源释放，支持 `catch_unwind`。 |
| **Abort**    | 立即终止进程，由 OS 回收内存。               | 减小二进制体积，提升性能。             |
| **`dyn Fn`** | **动态分发**，通过 **vtable (虚表)** 查找。 | 允许在运行时存储不同类型的闭包。          |
| **vtable**   | 存储函数指针、对象大小、对齐信息的表。             | 实现多态，让编译器知道该调用哪个具体函数。     |
| **`move`**   | 改变变量捕获方式：从“借用”变为“移动”。           | 解决生存期冲突，让闭包拥有变量并独立存在。     |

---

### 5. 最佳实践建议

> [!IMPORTANT]
> 
> **何时 Panic？**
> 
> 1. **不可恢复的逻辑故障**：如核心配置文件损坏。
>     
> 2. **契约违背**：调用者传入了绝对非法的参数（且无法通过 `Result` 优雅处理）。
>     
> 3. **测试代码**：断言失败必须 panic。
>     
> 4. **快速原型**：临时占位。
>     
> 
> **避坑指南：**
> 
> 不要频繁使用 `unwrap`，在库（Library）代码中优先返回 `Result`，将 Panic 的权力交给终端用户（Binary）。
