# 计网
## [Web 基础概念：URL 结构规范]
#计算机网络 #HTTP #URL
在标准统一资源定位符（URL）格式 `prot://user:psw@host:port/path` 中，各字段分别对应：协议名、==用户名与口令==、==主机域名（或 IP）==、==端口号==及目标资源的==路径文件名==。
___
* **省略规则**：匿名访问时可省略 `user:psw`；若使用默认协议端口（如 HTTP 的 80 端口），可省略 `:port`。

## [HTTP 协议特性：无状态性 (Statelessness)]
#计算机网络 #HTTP #协议原理
为什么 HTTP 协议被设计为“无状态（Stateless）”协议？它有什么核心优势？
___
**核心优势**：
1. **提升服务器并发容量**：服务器无需为成千上万个客户端维护交互历史状态表，释放了大量内存与计算资源。
2. **容错与恢复简单**：若服务器或网络发生故障中断，重启后不会因状态数据不一致而导致协议崩溃或需要复杂的会话同步。

## [Web 服务器架构：并发套接字模型]
#计算机网络 #HTTP #Socket
（在多客户端并发访问的 Web 服务器中）“监听套接字（Listening Socket）”与“已连接套接字（Connected Socket）”的分工是怎样的？
___
* **监听套接字**：持续守候在 80 端口，专门负责被动**接收新的 TCP 连接建立请求**。
* **已连接套接字**：每当完成一次三次握手，操作系统即创建一个专用的连接套接字，负责与**特定客户端进行后续的 HTTP 报文收发**。

## [HTTP 连接模式：非持久 vs 持久]
#计算机网络 #HTTP #连接管理
HTTP/1.0 默认采用==非持久连接（Non-persistent Connection）==，即每个 TCP 连接最多传输一个对象；而 HTTP/1.1 默认采用==持久连接（Persistent Connection）==，允许单个 TCP 连接传输多个对象。
___
* **非持久连接的代价**：每次获取新对象都需要重新经历 TCP 握手并分配系统套接字资源。

## [HTTP 性能评估：非持久连接响应时间]
#计算机网络 #HTTP #RTT
（在忽略排队与并发连接的前提下）使用非持久 HTTP 获取一个包含 $1$ 个基础 HTML 和 $N$ 个图片引用的网页，客户端总共需要经历多少个 RTT（往返时延）？
___
总共需要 **$2(N + 1)$ 个 RTT**（加上文件本身的传输时间）。

* **单对象分解**：
  * 获取基础 HTML 需要：$1\text{ RTT (TCP握手)} + 1\text{ RTT (HTTP请求/响应)}$；
  * 每个引用对象同样需要：$1\text{ RTT (TCP握手)} + 1\text{ RTT (HTTP请求/响应)}$。

## [持久 HTTP 机制：非流水线 vs 流水线]
#计算机网络 #HTTP #传输优化
（在 HTTP/1.1 的持久连接中）非流水线方式（Non-pipelining）与流水线方式（Pipelining）的根本区别是什么？
___
* **非流水线方式**：客户端必须在**收到前一个对象的响应之后**，才能发出下一个对象的请求（串行等待，每个对象耗时 1 RTT）。
* **流水线方式**：客户端一旦解析出对象引用即可**连续并行发送多个请求**，无需等待前序响应返回，使所有引用小对象在理想情况下可在 1 个 RTT 内集中返回。

## [HTTP 报文格式：请求行结构]
#计算机网络 #HTTP #报文结构
HTTP 请求报文的第一行称为**请求行（Request Line）**，由三个关键字段组成：==方法（Method）==、==URL 路径==和==协议版本号（HTTP Version）==。
___
* **典型示例**：`GET /somedir/page.html HTTP/1.1`

## [HTTP 请求方法：GET 与 POST 表单提交对比]
#计算机网络 #HTTP #请求方法
（在 HTML 表单提交数据时）使用 GET 方法与 POST 方法传递参数的位置有何不同？
___
* **GET 方法**：将表单数据以键值对参数的形式直接附加在**请求行的 URL 末尾**（例如 `?wd=test&cl=3`）。
* **POST 方法**：将表单数据封装在 HTTP 报文的**实体主体（Entity Body）**中传输。

## [HTTP 请求方法：HEAD 方法的核心用途]
#计算机网络 #HTTP #请求方法
HTTP 的 `HEAD` 方法要求服务器执行何种动作？它常用于哪些实际网络场景？
___
**行为**：服务器对请求做出响应，但**只返回 HTTP 首部，不传输实体主体对象**。

**典型用途**：
1. **故障诊断与链路探测**：检查资源是否存在、有效性及服务器健康状态；
2. **搜索引擎索引抓取**：仅提取首部的修改日期、内容类型等元数据，大幅节约爬虫带宽。

## [HTTP 协议演进：HTTP/1.1 新增方法]
#计算机网络 #HTTP #协议演进
相较于 HTTP/1.0，HTTP/1.1 新增了用于网页维护修改的两个典型方法：==PUT 方法==（将主体文件上传至指定 URL 路径）与==DELETE 方法==（删除指定 URL 路径的文件）。
___
* **HTTP/1.0 基础方法**：`GET`、`POST`、`HEAD`。

## [HTTP 状态码：301 永久重定向]
#计算机网络 #HTTP #状态码
HTTP 响应状态码 `301 Moved Permanently` 表示目标资源已被永久转移，客户端应当从响应首部的 ==`Location:`== 字段中提取新 URL 并自动发起重新获取。
___
* **缓存特性**：浏览器和搜索引擎通常会永久缓存 301 重定向结果，并在后续访问中直接定向到新地址。

## [HTTP 状态码：400 vs 404]
#计算机网络 #HTTP #状态码
（在 HTTP 响应状态码中）`400 Bad Request` 与 `404 Not Found` 分别代表什么含义？
___
* **400 Bad Request**：客户端发送的请求报文存在**语法错误**，服务器无法解析解读。
* **404 Not Found**：请求格式完全合法，但服务器上**无法找到**所请求路径对应的文档资源。

## [Cookie 状态管理：四大核心组件]
#计算机网络 #HTTP #Cookie
通过 Cookie 在无状态 HTTP 上实现有状态交互依赖哪四个组成部分？
___
1. 服务器响应报文中的首部行：**`Set-Cookie:`**；
2. 客户端请求报文中的首部行：**`Cookie:`**；
3. **客户端本地管理的 Cookie 文件**（由浏览器存储）；
4. **服务器端的后端数据库**（以 Cookie ID 为索引存储会话数据）。

## [Web 缓存与代理：双重角色机制]
#计算机网络 #HTTP #Web缓存
为什么说 Web 缓存器（代理服务器 Proxy）“既是服务器又是客户端”？
___
* **作为服务器**：它被动监听并接收来自**最终用户浏览器**的 HTTP 请求，并将缓存的对象直接响应给用户。
* **作为客户端**：当本地未命中请求对象时，它代表最终用户主动向**源 Web 服务器**发起 TCP 连接与 HTTP 请求。

## [Web 缓存一致性：条件 GET (Conditional-GET)]
#计算机网络 #HTTP #Web缓存
（在 Web 缓存向源服务器验证资源最新状态时）条件 GET 请求依赖请求首部 ==`If-modified-since:`==；若资源未被修改，服务器将返回状态码 ==`304 Not Modified`== 且不携带实体数据。
___
* **目的**：避免重复下载未发生变化的完整文件，节约接入网链路带宽。

## [FTP 架构：双连接模式]
#计算机网络 #FTP #体系结构
FTP 协议在客户端与服务器之间同时运行两个并行的 TCP 连接：负责传输认证与指令的==控制连接（端口 21）==，以及负责传输文件内容的==数据连接（端口 20）==。
___
* **连接生命周期**：控制连接贯穿整个会话全过程；数据连接则是“按需创建、传输完毕即关闭”。

## [FTP 架构：带外控制 (Out-of-band)]
#计算机网络 #FTP #体系结构
为什么称 FTP 的控制连接是“带外（Out-of-band）”传输？与 HTTP 相比有何区别？
___
* **FTP 带外控制**：控制命令（如认证、路径切换）走独立的端口 21 连接，而实际文件数据走端口 20 的独立连接，两者链路分离。
* **HTTP 带内控制**：HTTP 的控制元信息（请求/响应首部行）与实体文件数据紧密贴合在同一个 TCP 连接的数据流中混合传输。

## [应用层状态对比：FTP vs HTTP]
#计算机网络 #应用层 #协议对比
为什么说 FTP 是“有状态（Stateful）”的协议，而 HTTP 是“无状态（Stateless）”的？
___
* **FTP 有状态**：服务器必须实时绑定并追踪控制连接对应的当前远程目录工作路径、用户登录凭证等上下文。
* **HTTP 无状态**：服务器不记忆同一个客户端在此前事务中的任何上下文，每个请求处理相互独立，必须通过 Cookie 等上层机制打补丁维护状态。

## [FTP 核心命令：文件上传与下载]
#计算机网络 #FTP #协议指令
在 FTP 控制连接所使用的 ASCII 文本指令中，向远程服务器存放/上传文件的命令是 ==`STOR`==，从远程服务器检索/下载文件的命令是 ==`RETR`==。
___
* **用户认证指令**：`USER`（用户名）、`PASS`（口令）。
* **目录查看指令**：`LIST`（列出当前目录文件）。
