## [linux] 

`/etc/passwd`中写的 `laugh:x:1000:1000::/home/laugh:/bin/fish` 是什么含义
---
`用户名 : 密码占位符 : UID : GID : 用户描述信息 : 家目录 : 默认Shell`
我们拿你输出里最核心的普通用户 laugh 来作为例子拆解：

`laugh : x : 1000 : 1000 : : /home/laugh : /bin/fish`

- laugh（用户名）：你登录系统时输入的账号名。

- `x`（密码占位符）：以前 Linux 确实把加密后的密码存在这里，但因为这个文件所有程序都能读，太不安全了。现在真正的加密密码都移到了 `/etc/shadow`（只有 root 能读）。这里的 x 仅仅代表“该用户有密码，请去 shadow 文件里验货”。

- `1000`（UID - 用户ID）：Linux 内部其实不认识 laugh 这个字符串，它只认数字。`1000` 是 Linux 里第一个普通用户的通用起始 ID。

- `1000`（GID - 组ID）：该用户所属主用户组的数字 ID。

- （用户描述）：这里是空的（冒号连续出现了两次 ::）。如果写了，通常是你的真实姓名或备注。

- `/home/laugh`（家目录）：当你登录这个账号时，系统默认带你去的“主场”目录（即 ~）。

- `/bin/fish（默认Shell）`：非常亮眼。说明你一登录进去，系统为你召唤的命令解析器是 Fish Shell，而不是传统的 Bash。

    
## [linux] 

`UID`分类含义`0`, `1-999`, `1000-60000`, `65534`
---
|UID |区间,身份类型,典型代表,含义与权限特点|
|---|---|
|0,超级管理员 (Root),root,全系统至高无上。| 内核对 `UID 0` 特别放行，它可以无视任何文件权限权限（rwx），甚至可以直接擦除整个系统。|
|`1 – 999`(或 1–499),系统特殊用户 (System Users),"bin, daemon, mysql, postgres",系统服务的“提线木偶”。| 这类用户不能登录，专门用来运行后台服务。比如 mysql 服务只拥有读写数据目录的权限，即使被黑客攻破，也无法危害到 root 的核心文件。|
|`1000 – 60000`,普通大活人 (Regular Users),laugh,系统真正的使用者。| 你创建的第一个普通用户默认就是 1000，再创建第二个就是 1001。这些用户只能在自己的家目录（如 /home/laugh）里为所欲为，访问系统文件需要通过 sudo 临时提权。|
|`65534`,无名之辈 (Nobody),nobody,全系统权限最小的边缘人。 |它没有任何特权，甚至不属于任何常规组。通常用于一些极度不安全、需要完全隔离的外部服务（比如未认证的 NFS 网络文件共享）。|

## [sql]

```sh
Weather
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| id            | int     |
| recordDate    | date    |
| temperature   | int     |
+---------------+---------+
```
`id` 是该表具有唯一值的列。

没有具有相同 `recordDate` 的不同行。

该表包含 **特定日期** 的 **温度** 信息

求 **今天** 比 **昨天** 温度更高的日期的 `id`
---
首先, 一个表需要自连接, 且日期 今天比昨天多一天, 用`datediff()` 函数
```sql
select today.id
from Weather today join Weather yestoday
on datediff(today.recordDate, yesdoday.recordDate) = 1
where today.temperature > yesterday.temperature;
```

## [sql] 

```sh
表: Activity

+----------------+---------+
| Column Name    | Type    |
+----------------+---------+
| machine_id     | int     |
| process_id     | int     |
| activity_type  | enum    |
| timestamp      | float   |
+----------------+---------+
```
该表展示了一家工厂网站的用户活动。

(machine_id, process_id, activity_type) 是当前表的主键（具有唯一值的列的组合）。

machine_id 是一台机器的ID号。

process_id 是运行在各机器上的进程ID号。

activity_type 是枚举类型 ('start', 'end')。

timestamp 是浮点类型,代表当前时间(以秒为单位)。

'start' 代表该进程在这台机器上的开始运行时间戳 , 'end' 代表该进程在这台机器上的终止运行时间戳。

同一台机器，同一个进程都有一对开始时间戳和结束时间戳，而且开始时间戳永远在结束时间戳前面。

计算每个 `process_id`所有机器运行的平均时间
---
1. 首先, 先自连接把每个 `machine_id` 和 `process_id` 的 `start`和`end`连接成一个元组
2. 用`group by` 聚合 `process_id`, 用 `avg()`计算平均值, 用 `round(num, 3)` 四舍五入, 保留 3 位小数

```sql
select process_id, round(avg(a2.timestamp - a1.timestamp), 3)
from Activity a1 join Activity a2
on a1.machine_id = a2.machine_id
and a1.process_id = a2.process_id
and a1.activity_type='start'
and a2.activity_type='end'
group by process_id;
```
