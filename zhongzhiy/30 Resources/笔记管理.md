
## 1. 基础结构：经典的 P.A.R.A 目录法（改）

完全不建文件夹会导致强迫症崩溃，但文件夹太深会让人找不到地方放。推荐使用 Tiago Forte 的 **P.A.R.A** 框架，结合技术学习进行微调，只保留 **4~5 个顶级文件夹**：

Plaintext

```
📁 00_Inbox          # 收件箱：所有新笔记、临时抓取的网页、未整理的灵感先扔这里
📁 10_Projects       # 项目：有明确截止日期和目标的任务（如：物料管理系统开发、5月期末考）
📁 20_Areas          # 领域：长期需要维护的责任盘（如：算法竞赛/ICPC、后端开发、英语学习）
📁 30_Resources      # 资源：你的个人知识库、代码片段、读后感、动漫杂谈（作为 Area 的补充垫脚石）
📁 40_Archive        # 归档：已经结束的项目、不再高频查看的过期内容（不删，仅归档）
```

> **💡 核心痛点：** 绝不要在写笔记前纠结“这篇笔记该放哪个文件夹”。一律扔进 `00_Inbox`，或者直接在根目录创建，定期（比如每周）清空一次即可。

## 2. 核心灵魂：双链（Links）与 标签（Tags）的正确打开方式

Obsidian 最大的优势是**网状结构**。如果只靠文件夹，那就和 Windows 文件管理器没区别了。

### 标签（Tags）用来定义“状态”或“属性”

不要用标签做层级分类（比如不要用 `#计算机/基础/数据库`），标签会膨胀。把标签当成**筛选项**：

- **状态标签：** `#todo`（待完善）、`#wip`（正在写）、`#review`（需复习）
    
- **媒体属性：** `#paper`（论文）、`#book`（书籍）、`#anime`（动漫）
    

### 双链（`[[双链]]`）用来建立“知识网络”

双链应该像维基百科一样。当你写到某个概念时，直接用 `[[概念]]` 圈起来。

- **不仅链接具体笔记，还要链接“概念”：** 比如在写某个项目代码遇到内存问题时，顺手链接 `[[C++ 内存管理]]`。
    
- **建立“MOC”（Map of Content，内容地图）：** 比如创建一个名为 `[[后端开发 MOC]]` 的笔记，里面不放具体内容，只放各种相关双链的索引。它就像一本书的目录，但比文件夹灵活得多。
    

## 3. 推荐实践：卡片盒笔记法（Zettelkasten）的简化版

不要把一篇笔记写成长篇大论。尝试“原子化笔记”：

- **一事一记：** 一个笔记只讲一个算法（如 `[[线段树区间更新]]`）、一个配置、或者一个灵感。
    
- **用自己的话写：** 哪怕是摘抄的代码或公式，也要在开头用一两句话写下：_“这东西解决了什么问题，我下次在什么场景下会用到它。”_
    
- **渐进式总结：** 第一次记录只加粗关键词；第二次看到时换个颜色或者提炼出核心公式；第三次看到时把它连入你的 MOC 目录。
    

## 4. 保持克制：好用的核心插件与最少必要外挂

Obsidian 的生态极度繁荣，但插件装多了会导致软件卡顿、配置疲劳。这里只推荐几个真正能大幅提升效率的：

### 内置核心插件（必开）

- **出链 & 反向链接 (Backlinks)：** 放在右侧边栏，随时查看“有哪些别的笔记引用了当前内容”，这是灵感碰撞的关键。
    
- **日记 (Daily Notes)：** 开启它。每天早上自动生成一篇当天的笔记，用来记录当天的待办、临时想法、临时突发的 debug 记录。它是你整个系统的流动血液。
    

### 社区插件（按需精简安装）

- **Dataview：** 核心神器。可以用类似 SQL 的语法自动把带有特定标签（如 `#wip`）的笔记生成表格，适合用来做项目管理和主页聚合。
    
- **Mermaid（内置支持）：** 极力推荐用它来画流程图、时序图或架构图，直接写文本就能渲染出图，和 Markdown 契合度极高。
    
- **Excalidraw（可选）：** 如果你需要手绘逻辑图、架构草图，这个手绘风格的画板插件是天花板级别的存在。
    

## 💡 给你的行动建议

1. **今天：** 新建一个库，只建一个 `00_Inbox` 文件夹。
    
2. **这周：** 开启“日记”插件。每天遇到的技术坑、算法思路、或者看番的心得，直接在日记里随手写。遇到核心词就用 `[[ ]]` 括起来。
    
3. **下周：** 当你发现某个 `[[核心词]]` 被提到了好几次，点击它，进去把它变成一篇真正的“知识卡片”，并顺手归类到 P.A.R.A 的 `20_Areas` 对应领域里。
    

让你的知识库像一棵树一样**自然生长**出来，而不是先画好一个漂亮的空花盆，再逼着自己去填满它。
