
### 1. 实验任务与目标

本关的任务是分析 phase6 二进制程序，重点在于理解多维数组在 IA-32 架构下的内存布局和寻址方式。程序要求输入一组数据，通过分析，我需要确定输入数据的个数、数值范围，以及它们如何作为索引去访问一个预定义的二维数组，并最终通过逻辑校验。

### 2. 完成该实验需要掌握的知识

- 数组的线性存储：在机器级，数组不论维度，在内存中都是连续的一维空间。二维数组 A[M][N] 遵循行主序存储。
- 比例变址寻址：IA-32 的寻址公式 Base + Index * Scale + Displacement。在本实验中，Scale 对应数组元素的大小。
- 内存映射：能够通过反汇编中的立即数地址定位到数据段（.data 或 .rodata），并提取出隐藏的数组内容。
- sscanf 的多参数传递：理解如何通过栈向格式化输入函数传递多个变量地址。

### 3. 实验过程记录

#### 3.1 分析输入格式

首先查看 phase 函数（地址 0804938e）。程序在调用 __isoc99_sscanf 之前，连续 push 了 6 个内存地址（0x804c11c, 0x804c110 等）。结合后续的 cmp $0x6, %eax 指令，我判定程序要求输入 6 个整数。

#### 3.2 提取二维数组寻址逻辑

进入核心循环（080493dc 到 0804943e），我通过分析寄存器的变化还原了寻址公式：

1. 循环变量 i 从 0 增加到 2（对应 cmpl $0x2, -0xc(%ebp)），说明程序在处理 3 对数据。
2. 程序首先从 0x804c108 处取出一个值作为行索引（记为 row），并检查其是否在 0 到 3 之间。
3. 接着从 0x804c114 处取出一个值作为列索引（记为 col），检查其是否在 0 到 7 之间。
4. 关键寻址指令在 8049415：movzbl 0x804c0c0(%eax,%edx,8),%edx。
这里的基地址是 0x804c0c0，寻址方式是 Base + col + row * 8。
这证明了内存中存在一个 4 行 8 列（Row size = 8）的字节数组（Scale 为 1，即 char 类型）。

#### 3.3 匹配目标值

寻址得到的字节存入 %dl，随后程序从 0x804c0e0 取出一个目标值进行比较：
mov 0x804c0e0, %ecx
add %ecx, %eax
cmp %al, %dl
这说明我的输入（row, col）确定的数组元素，必须等于内存地址 0x804c0e0 开始的校验数组中的对应项。

#### 3.4 构造解答

我使用 gdb 挂载程序并查看了相关内存：

- 查看二维数组：x/32xb 0x804c0c0
- 查看目标校验值：x/3xb 0x804c0e0
我手动在二维数组的矩阵中寻找与目标校验值相同的元素坐标。
例如，若目标第一个值是 0x41，而 0x41 出现在矩阵的第 1 行第 2 列，则我的前两个输入整数就是 1 和 2。依此类推，找齐 3 对坐标，共 6 个整数。

### 4. 遇到的问题与解决过程

- 问题：对“6个输入”和“3次循环”的矛盾感到困惑。
起初我以为要输入一个 6 维坐标，但看到 8049415 的偏移计算只有两个维度参与。
- 解决：通过仔细观察寄存器 %edx 和 %eax 的来源，我发现程序是把 6 个输入分成了两组（前 3 个和后 3 个），每轮循环各取一个，拼成一对坐标 (row_i, col_i)。这种把一维输入映射到二维坐标的逻辑是本关的解题关键。
- 问题：行宽度的确定。
指令中使用的是 (%eax, %edx, 8)，这里的 8 是乘法因子。在二维数组寻址中，Base + col + row * RowWidth，这直接告诉我每行有 8 个元素。

### 5. 心得体会

- 内存布局的透明化：这次实验让我意识到，在汇编层面，所谓的“行”和“列”只是程序员的逻辑想象。对 CPU 来说，它只是在做一个简单的加法和乘法运算来定位某个偏移量。
- 逆向工程的套路：分析这类程序，最快的方法是先看格式化输入（确定数据类型和个数），再看循环边界（确定处理次数），最后看核心算术指令（确定算法）。
- 严谨性的锻炼：在计算 row * 8 的偏移时，如果弄反了行和列，或者数错了内存中的字节，就会导致炸弹爆炸。这种对每一个字节都要精确把控的要求，极大地锻炼了我的细心程度。
