
# work

## 为什么要在卡片中提供背景信息（Context）？
---
虽然要遵循最小化原则，但失去背景的知识会变成“孤岛”。
* **做法**：在问题部分加入简短的分类或前置条件（例如：`[生理学] 动作电位的原理是？`）。

## 应该在什么时候向 Anki 添加新卡片？
---
**规则**：先学习，后记忆。
永远不要向 Anki 添加你还没有在书本、课程或实践中完全理解的新内容。

## 优化卡片逻辑的 3 个层级
---
1.  **结构层**：确保知识框架清晰。
2.  **内容层**：遵循最小化原则。
3.  **修饰层**：添加颜色、加粗和图片辅助视觉。

## 制作卡片时应避免“词汇性堆砌”，而应关注{{c1::语义理解}}。
---
不要逐字逐句背诵课本，要用**自己的话**重新表述。

## 重复是记忆之母，但{{c1::间隔重复 (Spaced Repetition)}} 才是效率之王。
---
Anki 的核心逻辑就是利用遗忘曲线，在即将遗忘的临界点进行复习。

## 针对“集合”类知识（Sets），最佳的处理方式是使用{{c1::填空 (Cloze Deletion)}}。
---
例如：
* 欧盟的三个创始成员国包括 法国、德国 和 意大利。

## 如果一张卡片让你感到痛苦，你应该怎么做？
---
**直接放弃或重新编辑它**。
持续的痛苦意味着该卡片违反了最小化原则或你根本不理解它。

## 为什么要在卡片中加入“引用来源”？
---
为了在未来的复习中，如果对知识点产生怀疑，可以快速回溯到原始材料（如书名、页码或 URL）。

## {{c1::冗余 (Redundancy)}} 并不违背最小化原则，通过{{c2::从不同角度提问}}来加强同一个知识点是很有必要的。
---
例如：
* 卡片A：$F = m \cdot a$
* 卡片B：加速度 $a$ 的公式是？答案：$a = \frac{F}{m}$

## 知识的 20 条规则是由 {{c1::Piotr Wozniak}} 提出的，他是 {{c2::SuperMemo}} 的开发者。
---
这些规则是基于几十年的记忆科学研究总结而成的。

## 最后一规则：坚持不懈（Stick to it）
---
再完美的卡片，如果不进行复习也没有任何意义。保持复习队列清零是成功的关键。


## 学习知识前为什么要先理解？
---
* **原则**：理解是记忆的基石。
* **原因**：由于大脑依靠联想存储信息，理解能将新知识融入已有的知识网络中。试图记忆不理解的碎片（死记硬背）不仅痛苦，且极易遗忘。

## 记忆时应当遵循的“最小化原则”是什么？
---
> **Keep it simple!**

卡片应该尽可能简单。复杂的材料必须分解为最小的信息单位。
* **优点**：
    1.  复习速度快。
    2.  反馈明确（容易判断是否记住了该点）。
    3.  不容易因为其中一个小点的模糊而导致整张大卡片重排。

## 什么是卡片制作中的“类典型化”（Typification）？
---
在制作卡片时，与其记忆抽象定义，不如记忆一个**具体的、具有代表性的例子**。通过实例来推导抽象概念比直接背诵定义效率更高。

## 为什么在 Anki 中不建议记忆“列表”？
---
记忆长列表（List）是非常困难的，因为：
1.  各元素间缺乏逻辑联系。
2.  容易产生“顺序依赖”。
3.  复习时只要漏掉一个，整张卡片就算失败。

**建议**：如果必须记忆列表，请将其转化为**填空题**或使用**助记词**。

## {{c1::干扰 (Interference)}}是指相似的信息在记忆中互相混淆，解决它的办法是{{c2::建立独特的感官联系}}或{{c3::明确区分两者的差异}}。
---
例如：如果你混淆了两个相似的术语，就在卡片中明确指出它们的区别，或为其中一个添加独特的图像。

## 在制作 Anki 卡片时，{{c1::主动召回 (Active Recall)}} 优于 {{c2::被动阅读}}。
---
不要只是盯着答案看，而是在翻面之前尝试从大脑中提取信息。

## 知识的20条规则中，关于“图片”的建议是？
---
**一图胜千言**。
大脑对视觉信息的处理能力远强于文本。尽可能为卡片添加插图、简图或照片，以建立多维度的记忆挂钩。

## 什么是“自参考效应”？
---
将知识与**个人的经历、情感或日常生活**联系起来。
* **做法**：在答案区写下一段关于这个知识点如何应用在你生活中的例子。

## {{c1::助记法 (Mnemonics)}} 是将枯燥信息转化为生动图像的技术，例如使用{{c2::关键词法}}、{{c3::地点桩}}或{{c4::口诀}}。
---
即便最小化原则做得很好，对于一些没有逻辑联系的数字或外语单词，助记法依然是最高效的选择。


# 算法
## 同余方程：求 $a \cdot x \equiv 1 \pmod b$ 的最小正整数解
***
将方程转化为：$a \cdot x + b \cdot y = 1$。
1.  使用**扩展欧几里得算法 (exgcd)** 求出一组特解 $x_0, y_0$。
2.  若 $gcd(a, b) = 1$，则有解。
3.  通过取模运算将 $x_0$ 映射到最小正整数区间：
    $x = (x_0 \pmod b + b) \pmod b$

---

## 扩展中国剩余定理 (EXCRT)
求最小非负整数 $x$ 满足：$x \equiv m_i \pmod{a_i}$
***
```cpp
// 核心逻辑：合并同余方程
// x = m1 + k1 * a1
// m1 + k1 * a1 ≡ m2 (mod a2) => k1 * a1 ≡ m2 - m1 (mod a2)
// 使用 exgcd 解出 k1，更新 x 和新的模数 M = lcm(a1, a2)
int M = a[1], x = m[1];
for (int i = 2; i <= n; ++i) {
    int xx, yy;
    int d = exgcd(M, a[i], xx, yy);
    int c = (m[i] - x % a[i] + a[i]) % a[i];
    if (c % d != 0) return -1; // 无解
    xx = (__int128)xx * (c / d) % (a[i] / d);
    x += xx * M;
    M = M / d * a[i];
    x = (x % M + M) % M;
}
```

## 矩阵乘法模板：重载运算符
***
```cpp
Mat operator* (const Mat& other) const {
    Mat res(size);
    for(int i = 0; i < size; ++i)
        for(int k = 0; k < size; ++k) {
            if (mat[i][k] == 0) continue; // 优化
            for(int j = 0; j < size; ++j)
                res.mat[i][j] = (res.mat[i][j] + 1LL * mat[i][k] * other.mat[k][j]) % MOD;
        }
    return res;
}
```

## 线性异或方程组：开关问题
$N$ 个开关，触动某些开关会改变另一些的状态，求达到目标状态的方案数。
***
* **数学建模**：设 $x_i \in \{0, 1\}$ 为是否操作第 $i$ 个开关。每个开关的最终变化由其自身及受影响的开关异或决定。
* **方程形式**：$a_{i,1}x_1 \oplus a_{i,2}x_2 \oplus \dots \oplus a_{i,n}x_n = \text{initial}_i \oplus \text{target}_i$。
* **求解方法**：高斯消元。若有 $k$ 个自由元且无矛盾，方案数为 $2^k$。

---

## 二叉树遍历：根据后序 + 中序求层序
***
1.  **建树**：后序遍历的最后一个节点是当前子树的 `root`。在中序遍历中找到 `root`，左侧为左子树，右侧为右子树。
2.  **递归**：不断切分区间，构造出整棵树。
3.  **层序**：使用 `std::queue` 进行 BFS 遍历。

---

## 布布吃地瓜：网格路径 $mex$ 最小值
寻找一条从 $(1,1)$ 到 $(n,m)$ 的路径，使路径上数字集合的 $mex$ 最小。
***
* **核心思路**：若 $mex$ 为 $v$，意味着所有从起点到终点的路径都**必须**经过数字 $v$。
* **判别条件**：数字 $v$ 的位置在网格中形成了一条“拦截线”（从右上/上方连接到左下/下方），阻断了 $(1,1)$ 到 $(n,m)$ 的所有通路。
* **搜索技巧**：对每个可能的 $v$，通过 8 连通 DFS 检查其是否能从网格的右上边界连接到左下边界。

---

## 左右脑胡博：博弈与状态压缩 DP
多重集取数博弈：取走的数必须大于剩余集合的异或和。
***
* **状态定义**：`dp[mask]` 表示集合状态为 `mask` 时，当前先手是否必胜（1 为胜，0 为负）。
* **转移方程**：`dp[mask] = 1` 当且仅当存在一个 $i \in mask$，满足 $a_i > (\text{xor\_sum} \oplus a_i)$ 且 `dp[mask ^ (1<<i)] == 0`。
* **初始状态**：`dp[0] = 0`（空集无法操作，必败）。

---

## Turn Off The Lights：灯泡反转问题
$n \times n$ 灯阵，可反转行、列，或单点（单点 $\le k$ 次，$k < n$）。
***
* **关键结论**：每行每列最多操作一次。$3n$ 的限制非常宽松。
* **贪心策略**：
    1. 枚举第一行的操作状态（只有 2 种可能：反转或不反转）。
    2. 固定行操作后，列操作由该列除第一行外的灯泡状态决定（或者考虑枚举列操作，再处理行）。
    3. 剩下的无法通过行、列反转解决的“孤立”亮灯，使用 $k$ 次单点操作消除。
    4. 检查单点操作数是否 $\le k$。


# java

## （Java 并发）多任务实现方式：多线程 vs 多进程
---
Java 中的多任务主要通过 **多线程** 实现。
* **Java 进程**：启动一个 Java 程序即启动了一个 JVM 进程，`main()` 方法运行在该进程的主线程中。
* **内置支持**：Java 语言层面内置了多线程支持（如 `Thread` 类、`synchronized` 关键字等）。

---

## （进程 vs 线程）对比多进程与多线程的优缺点
---
| 维度 | 多进程 | 多线程 |
| :--- | :--- | :--- |
| **稳定性** | **更好**。一个进程崩溃不会影响其他进程。 | 较差。一个线程崩溃可能导致整个进程挂掉。 |
| **开销** | **大**。启动进程和切换上下文开销高。 | 小。线程间共享堆内存，切换速度快。 |
| **通信** | 慢。需通过 IPC（管道、Socket 等）通信。 | 快。直接共享内存变量。 |

---

## （Lambda 表达式）Java Lambda 的语法及变量捕获约束
---
**语法**：`(参数) -> { 表达式/代码块 }`
**约束条件**：
1.  **Effectively Final**：捕获的局部变量在定义后不能被重新赋值。
2.  **函数式接口**：只能用于只有一个抽象方法的接口（如 `Runnable`, `Callable`）。

```java
Runnable r = () -> {
    System.out.Println("This is a new thread");
};

Thread t = new Thread(r);
t.run();
```


## （匿名内部类）Java 匿名内部类的语法与限制
---
**语法**：
```java
Parent obj = new Parent() {
    @Override
    void method() { /* 逻辑 */ }
};
```
**限制规则**：
1.  **无构造方法**：但可以使用初始化块 `{...}`。
2.  **变量访问**：仅能访问 `final` 或 Effectively Final 的局部变量。
3.  **非静态**：不能定义静态成员或静态方法。
4.  **单一性**：只能继承一个父类或实现一个接口。

---

## （线程启动）为什么在多线程编程中应调用 `start()` 而不是 `run()`？
---
* **`run()`**：只是普通的成员方法调用，程序会在**当前线程**中同步执行代码。
* **`start()`**：会请求 JVM 启动一个**新线程**，并在新线程中异步执行 `run()` 内容。

---

## （线程生命周期）Java 线程的 6 种状态是什么？
---

1.  **`NEW`**：初始状态，线程被创建但未调用 `start()`。
2.  **`RUNNABLE`**：运行状态，包括就绪和正在运行。
3.  **`BLOCKED`**：阻塞状态，等待获取锁。
4.  **`WAITING`**：等待状态，需等待其他线程唤醒。
5.  **`TIMED_WAITING`**：超时等待，如调用 `sleep(ms)`。
6.  **`TERMINATED`**：终止状态，线程执行完毕。

---

## （volatile 关键字）`volatile` 的核心作用是什么？
---
1.  **可见性**：确保 CPU 每次修改后强制写回主存，读取时从主存获取最新值。
2.  **禁止重排序**：防止编译器对指令进行优化排序。
> 注意：`volatile` **不保证原子性**（如 `count++` 仍非线程安全），仅适用于**一写多读**场景。

---

## （线程中断）Java 中中断线程 `t` 的两种推荐方式？
---
1.  **`interrupt()` 方法**：
    * 调用 `t.interrupt()` 发送信号。
    * 线程内通过 `isInterrupted()` 判断或捕获 `InterruptedException`。
    
    
```java
Thread t = new Thread(){
    public void run() {
        while(!isInterruputed()) {
            System.out.println("running ...");
        }
    }
}

t.start();
t.interrput();
```
2.  **标志位（volatile）**：
    * 设置 `volatile boolean running = true;`。
    * 外部修改 `running = false;` 停止循环。

---

## （同步机制）`synchronized` 代码块的基本用法？
---
```java
synchronized(Counter.lock){ // 获取锁
    
}//释放锁
```
* **原理**：线程必须先获得 `lockObject` 的锁才能进入代码块。
* **作用**：保证操作的**原子性**和**可见性**。

---

## （原子操作）Java 中哪些操作是天然“线程安全”的（原子操作）？
---
1.  **基本类型赋值**：除 `long` 和 `double` 之外（在某些 JVM 中非原子）。
2.  **引用类型赋值**：指向对象的指针赋值。
3.  **局部变量**：存储在线程私有栈中，天然安全。
4.  **不可变对象**：如 `String`，读取不需要锁。

---

## （死锁）Java 中死锁产生的条件及避免方法？
---
**定义**：多个线程互相持有对方所需的锁且不释放，形成环路等待。
**避免方法**：
* **固定加锁顺序**：确保所有线程获取锁的顺序完全一致。
* **使用超时锁**：如 `tryLock(timeout)`。

---

## （等待/唤醒）`wait()` 与 `notifyAll()` 的使用规范？
---
1.  **持有锁**：必须在 `synchronized` 块内调用。
2.  **释放锁**：`wait()` 会释放当前持有的锁，线程进入等待池。
3.  **条件检查**：应始终在 `while` 循环中使用 `wait()` 以防止虚假唤醒。
    ```java
    while (conditionNotMet) { obj.wait(); }
    ```

---

## （高级并发）`ReentrantLock` 相比 `synchronized` 的优势？
---
1.  **`tryLock()`**：可以设置获取锁的超时时间。
2.  **可中断**：支持 `lockInterruptibly()`。
3.  **多条件变量**：一个锁可以关联多个 `Condition` 对象。

---

## （高级并发）`ReadWriteLock` 的读写分离策略是什么？
---
* **读锁（Shared）**：允许多个线程同时读。
* **写锁（Exclusive）**：只允许一个线程写，且写时禁止任何线程读。
> 适用于**读多写少**的场景，能显著提高并发效率。

---

## （并发工具）`Semaphore`（信号量）的主要用途？
---
用于**限制并发访问特定资源的线程数量**。
* `acquire()`：获取许可（若无许可则阻塞）。
* `release()`：释放许可。
例如：限制数据库连接池的最大并发数为 10。

---

## （线程池）Java 推荐的线程池创建方式？
---
使用 `Executors` 工厂类或直接实例化 `ThreadPoolExecutor`：
```java
// 创建固定大小为 4 的线程池
ExecutorService es = Executors.newFixedThreadPool(4);
// 提交任务
es.submit(() -> System.out.println("Task running"));
// 关闭线程池
es.shutdown();
```

# java


## （Java IO）构造一个 `File` 对象是否会触发磁盘 IO 操作？
---
**不会**。
构造 `File` 对象仅是在内存中创建一个路径的抽象表示。即使传入的路径在硬盘上不存在，代码也不会报错。只有在调用 `isFile()`、`createNewFile()` 或 `listFiles()` 等方法时，才会真正进行磁盘操作。

## （Java IO）请区分 `File` 路径获取的三个方法：
| 方法 | 返回内容 |
| :--- | :--- |
| `getPath()` | 返回构造方法中**传入的路径**（可能是相对路径）。 |
| `getAbsolutePath()` | 返回**绝对路径**，但不处理路径中的 `.` 或 `..`。 |
| `getCanonicalPath()` | 返回**规范路径**，会自动解析路径中的 `.` 和 `..`，且格式唯一。 |

## （Java IO）如何在代码中实现跨平台的路径分隔符？
---
使用 `File.separator` 静态变量。
* Windows 下其值为 `\`
* Linux/macOS 下其值为 `/`

## 调用 `File.delete()` 删除目录成功的先决条件是什么？
---
**该目录必须为空**。
如果目录下存在任何文件或子目录，`delete()` 方法将返回 `false` 且删除失败。

## （Java IO）`mkdir()` 与 `mkdirs()` 的核心区别是什么？
---
* **`mkdir()`**：仅创建当前层级的目录。如果父目录不存在，则创建失败。
* **`mkdirs()`**：递归创建目录。如果路径中任何父目录不存在，它会**一并创建**。

## （Java IO）如何确保程序产生的临时文件在 JVM 退出时自动清理？
---
1. 使用 `File.createTempFile(prefix, suffix)` 创建临时文件。
2. 调用该对象的 **`f.deleteOnExit()`** 方法。

## （Java IO）`Path` 对象（NIO）相比 `File` 对象的主要优势是什么？
---
1. **路径拼接更方便**：支持 `Paths.get("a", "b", "c")` 这种多参数构造。
2. **操作更现代**：支持 `normalize()`（等同于规范路径）、可以直接进行迭代遍历。
3. **互操作性**：可以通过 `p.toFile()` 和 `f.toPath()` 轻松实现两者转换。

## 在 Java 字符串中表示 Windows 路径 `C:\Windows` 为什么要写成 `"C:\\Windows"`？
---
因为在 Java 字符串中 `\` 是**转义字符**（如 `\n`, `\t`），为了表示一个原始的反斜杠，必须使用 `\\` 进行转义。

## {{c1::Path.normalize()}} 方法的作用是什么？
---
它用于将路径中的冗余元素（如 `.` 和 `..`）移除，返回一个逻辑上的**标准路径**，其功能类似于 `File.getCanonicalPath()`，但返回的是 `Path` 对象。
