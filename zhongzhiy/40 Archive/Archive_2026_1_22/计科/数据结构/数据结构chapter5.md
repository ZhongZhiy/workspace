## 1. 查找基础（必须会的概念）

### 1.1 基本概念

- **查找**：在数据集合中找关键字为 K 的元素；  
    找到返回位置，否则返回失败信息。
    
- **查找表**：被查找元素的集合；  
    若只看逻辑结构，位置=逻辑位序；  
    若考虑存储结构，位置=物理地址。
    
- **关键码（Key）**：能唯一标识元素的数据项/属性。
    
    - 基于关键码查找：结果唯一
        
    - 基于一般属性查找：可能多个结果。
        
- **查找表类型**：
    
    - 静态查找表：查找前后集合不变（无插入/删除）
        
    - 动态查找表：查找过程中集合会变（有插入/删除）。
        

### 1.2 查找算法评价指标

- 空间：辅助空间越少越好
    
- 时间：以“**关键字比较次数**”衡量
    
    - 成功查找：最大比较次数 MSL、平均比较次数 ASL
        
    - 失败查找：也有 MSL、ASL
        
- ASL 计算公式：  
    [  
    ASL=\sum_{i=1}^{n} p_i \cdot c_i  
    ]  
    (p_i)：第 i 个元素被查到的概率；(c_i)：比较次数。

## 2. 静态查找

通常在“线性表”上做（顺序表/链表）。

### 2.1 无序表：顺序查找

- **思想**：从表尾/表头逐个比对关键字。
    
- **哨兵优化**：把 K 放到 Data[0]，保证循环一定停，避免每次判断越界。
    
- **复杂度**：
    
    - 成功/失败平均都为 O(n)。
        

### 2.2 有序表（数组连续存放）：二分查找

- **前提**：关键字有序且顺序存储（数组）。
    
- **思想**：取中间 Kmid 比较，缩小到左半或右半，区间每次减半。
    
- **算法**：left/right/mid 三指针循环直到 left>right。
    
- **复杂度**：O(log n)。
    
- **判定树视角**：
    
    - 判定树层数=比较次数
        
    - 深度≈⌊log2 n⌋+1
        
    - 因此二分查找比较次数不超过判定树深度。

## 3. 二叉搜索树 BST（二叉排序树）

### 3.1 定义（递归性质）

- 任意结点满足：  
    **左子树所有关键字 < 本结点 < 右子树所有关键字**；  
    左右子树也都是 BST。
    
- **中序遍历 BST 得到有序序列**（超级重要考点）。
    

### 3.2 查找

- 从根开始：  
    K=根→成功；K<根→左；K>根→右。
    
- **效率与树高有关**：  
    最好≈O(log n)，最坏退化成链≈O(n)。
    

### 3.3 构造（插入建立）

- 初始空树；每读一个元素按 BST 规则递归插入到合适空位置。
    
- **读入顺序不同 → BST 形态可能不同 → ASL不同**。
    

### 3.4 删除（必考三种情况）

1. **删叶子结点**：直接删，父指针置空。
    
2. **删只有一个孩子的结点**：父指针改为指向其孩子。
    
3. **删有两个孩子的结点**：  
    为保持有序性，用
    
    - 右子树最小值 替代  
        或
        
    - 左子树最大值 替代  
        再递归删除替代结点。

## 4. 平衡二叉树 AVL

### 4.1 为什么要 AVL

- 普通 BST 可能退化成链表，查找变 O(n)。
    
- AVL 通过“保持平衡”把高度控制在 log n 量级。
    

### 4.2 定义与平衡因子

- AVL：一棵 BST，且任意结点左右子树高度差 ≤ 1。
    
- 平衡因子 BF(t)=Hl−Hr  
    在 AVL 中 BF 只能是 **1、0、−1**。
    
- **查找复杂度**：O(log n)。
    

### 4.3 插入导致失衡的 4 种类型（要会判断+会旋转）

失衡结点 BF 变为 +2 或 −2 后分型：

1. **LL 型**：在左孩子的左子树插入 → 右旋
    
2. **LR 型**：在左孩子的右子树插入 → 先左旋再右旋
    
3. **RR 型**：在右孩子的右子树插入 → 左旋
    
4. **RL 型**：在右孩子的左子树插入 → 先右旋再左旋
    

- 旋转目的：**既保持 BST 有序性，又恢复平衡**。
    

### 4.4 进一步的“高级搜索树”（了解级）

- 伸展树：把刚访问结点旋转到根，提高局部性。
    
- B树/B+树：多级存储（磁盘/数据库）用，减少 I/O。
    
- 红黑树：用颜色约束控制高度，提高查找效率。

## 5. 散列（HASH）查找

### 5.1 基本思想

- 目标：**不用比较**，通过函数直接算地址。
    
- 有映射：  
    [  
    H(key)=i,\quad i\in[0,m-1]  
    ]  
    m 为哈希表长度。
    

### 5.2 重要概念

- Hash 函数 H(key)
    
- Hash 地址（由 H 算出的存储位置）
    
- Hash 表 T[0..m−1]（连续空间）
    
- 装填因子 α = 表中元素个数 / 表长
    
- **冲突**：key1≠key2 但 H(key1)=H(key2)  
    冲突的 key 互称**同义词**。
    

### 5.3 Hash 函数构造方法（会列举）

目标：地址分布尽量均匀 + 计算简单。  
常见方法：

1. **除留余数法**（最常用）  
    [  
    H(key)=key \bmod P  
    ]  
    P 为 ≤m 的素数（或不含小于20质因子的合数）。
    
2. 直接定址法
    
3. 数字分析法
    
4. 折叠法
    
5. 平方取中法。
    

### 5.4 冲突处理（重点）

1. **开放定址法（闭散列 / open addressing）**  
    冲突后沿表内探测新地址：  
    [  
    H_i=(H(key)+d_i)\bmod m  
    ]
    
    - 线性探测：(d_i=1,2,\dots,m-1)
        
    - 二次探测：(d_i=\pm1^2,\pm2^2,\dots)
        
2. **再散列（再造哈希）**：换一组哈希函数继续算。
    
3. **链地址法（开散列 / separate chaining）**  
    同义词挂到同一链表（桶）。
    
4. **公共溢出区法**：表外建溢出区专放冲突元素。
    

### 5.5 哈希查找步骤与复杂度

- 查找 k：先算 i=H(k)
    
    - 若 T[i] 空→失败
        
    - 若 T[i]=k→成功
        
    - 否则按冲突策略继续探测/链查。
        
- **性能**：
    
    - 无冲突：O(1)
        
    - 有冲突：取决于 H、冲突处理、装填因子 α。

## 6. 全章一句话对比（记忆点）

- 顺序查找：无序表，O(n)。
    
- 二分查找：有序数组，O(log n)。
    
- BST：动态查找，效率看树高。
    
- AVL：BST + 旋转保持平衡，O(log n)。
    
- Hash：算地址直接定位，平均 O(1)，靠函数与冲突策略。
