## [fd+fzf+xargs]
使用 fd 查找 chezmoi 相关文件, 并且从中找到想打开的 `chezmoi.lua`, 用`nvim`打开这个文件
---
```shell
fd -HI chezmoi | fzf | xargs nvim
```

## [xargs]
并行打开 8 个软件处理, 例如: 打开 8 个窗口查看图片 gemini 相关图片
---
用 imageglass 打开 png 结尾的图片

```shell
fd gemini -e png | xargs -P 8 imageglass
```

## [xargs]
如果管道传输的数据为空, 就不处理
---
`-r` no-run-if-empty

```shell
fd -e cpp gemini | xargs -r nvim 
```

## [xargs]
如果我要多次使用这个参数, 或者这个参数不放在末尾
---
`-I {}` 占位符, 可以使用多次 
```shell
fd -e cpp gemini | xargs -I {} echo "The {} in the {}"
```

## [狄利克雷卷积]

单位函数 $\sigma$ 是什么函数的狄利克雷卷积
---
$$ \sigma = \mu * 1 ⟺ \sigma (n) = \sum_{d | n} \mu(d) $$

## [莫比乌斯反演]

**题目**: 求: $\sum_{i=1}^{n}\sum_{j=1}^{m}[\gcd(i,j)=1] \quad (n < m)$
---
这是数论莫反的根基，我们在上一轮互动中推导过，这里列出最核心的变形逻辑：
1. 超级代换：利用 $\sum_{d|n} \mu(d) = [n=1]$ 的性质，把原式中的 $[\gcd(i,j)=1]$ 替换掉：$$ \sum_{i=1}^{n}\sum_{j=1}^{m} \sum_{d|\gcd(i,j)} \mu(d) $$
2. 符号大大挪移：把枚举 $d$ 提到最外层。因为 $d$ 是 $i, j$ 的公约数，所以 $d$ 最大只能到 $n$：$$ \sum_{d=1}^{n} \mu(d) \sum_{d|i}^{n} \sum_{d|j}^{m} 1 $$
3. 整除简化：在 $1 \sim n$ 中是 $d$ 的倍数的 $i$ 有 $\lfloor \frac{n}{d} \rfloor$ 个。
4. 最终表达式为：$$ \sum_{d=1}^{n}\mu(d)\lfloor \frac{n}{d} \rfloor \lfloor \frac{m}{d} \rfloor $$

# java

## [JPA & Hibernate]

JPA 是什么
---
JPA（Java Persistence API） 是 Java 官方（现在属于 Jakarta 开源社区）制定的一套标准和规范。

它不是一个框架，它甚至不包含能跑的业务代码。

它的里面全是接口（Interface）和注解（Annotation）。比如你前面看到的 @Id、@GeneratedValue、@Transactional，全都是 JPA 规定出来的标签。

## [JPA & Hibernate]

Hibernate 是什么
---

Hibernate 是一个历史悠久、大名鼎鼎的开源 ORM 框架。

它是真正的代码实现。它里面有成千上万行逻辑，负责去连接数据库、解析你的 Java 对象、自动帮你拼接并执行 SQL 语句。

在 JPA 诞生之前，Hibernate 就已经火遍全网了。后来 Java 官方看 Hibernate 的设计太赞了，于是拉着 Hibernate 的创始人一起，参照 Hibernate 的样子，制定了 JPA 规范。

## [Spring boot]

在买票系统中, 售票包含两个关键动作：

1. 在 `ticket_order` 表里插入一条买票记录。

2. 在 `schedule` 表里把剩余座位数（`remaining_seats`）减 1。

思考一个场景： 如果车票记录存成功了，但服务器突然停电，导致座位数没有减。这时候数据库的数据就不一致了。

在Spring boot中应该怎么处理?
---
Spring 老师给出的行业标配解法叫 声明式事务管理，也就是 `@Transactional` 注解：

- `@Transactional` 标签，Spring 就会利用 AOP（面向切面编程） 技术，在方法开始前悄悄帮你开启事务（`START TRANSACTION`）。

- 如果方法顺利执行完，Spring 会帮你提交事务（COMMIT）。

- 如果中途任何一行代码抛出了异常（比如发现没票了），Spring 会立刻让整个过程彻底回滚（`ROLLBACK`），之前存进去的订单和改过的座位通通不算数，数据库恢复原状。

## [Spring boot]

怎么声明 **悲观锁** , 以及悲观锁会把一个普通的 `select` 语句变成什么?
---

在 Java 里的声明非常简单，只需要在你的 `Repository` 接口方法上贴个标签：
```Java
@Lock(LockModeType.PESSIMISTIC_WRITE)
Optional<Schedule> findWithLockById(Long id);
```

当你调用这个方法时，Spring Boot 和 Hibernate 会自动在后台把原本普通的 `SELECT` 语句，翻译成带有 `FOR UPDATE` 的强力 SQL 发给 MySQL：
```SQL
SELECT id, remaining_seats FROM schedule WHERE id = 1 FOR UPDATE;
```
