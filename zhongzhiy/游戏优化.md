# Omarchy 4.0 系统与游戏性能优化记录

**设备基础信息：** Redmi Book Pro 15 2022 (AMD Ryzen 7 6800H + Radeon 680M)

**操作系统：** Omarchy 4.0.0-1 (Wayland / Hyprland)

**核心诉求：** 修复升级后电源模式失效问题，并在不影响日常 Java/Rust 开发环境的前提下，极限优化《永劫无间》等 3D 游戏的运行帧数与稳定性。

  

## 1. 电源管理架构重构

**背景：** Redmi 主板 BIOS 存在 ACPI 代码越界 Bug (`AE_AML_BUFFER_LIMIT`)，导致 Omarchy 4.0 自带的 `power-profiles-daemon` 无法调用内核 `platform_profile` 接口切换电源模式。

**方案：** 弃用主板级控制，改用纯 CPU 调度器 `auto-cpufreq`。

  

- **操作：**
    
      
    
    Bash
    
    ```
    sudo systemctl disable --now power-profiles-daemon
    sudo pacman -Rns power-profiles-daemon
    yay -S auto-cpufreq
    sudo systemctl enable --now auto-cpufreq
    ```
    
- **配置 (`/etc/auto-cpufreq.conf`)：**
    
      
    
    Ini, TOML
    
    ```
    [charger]
    governor = performance
    energy_performance_preference = performance
    turbo = auto
    
    [battery]
    governor = powersave
    energy_performance_preference = power
    turbo = auto
    ```
    

## 2. 虚拟内存 (Swap) 极速化改造

**背景：** 系统原分配了 30GB 的硬盘 Swap，物理内存吃紧时游戏数据写入固态硬盘会导致严重掉帧。

**方案：** 彻底禁用硬盘 Swap，全面启用基于纯内存压缩的 ZRAM。

  

- **配置 ZRAM (`/etc/systemd/zram-generator.conf`)：**
    
      
    
    Ini, TOML
    
    ```
    [zram0]
    zram-size = ram / 2
    compression-algorithm = zstd
    ```
    
- **应用与清理：**
    
      
    
    Bash
    
    ```
    sudo systemctl start systemd-zram-setup@zram0.service
    sudo nvim /etc/fstab  # 注释掉原有硬盘 swap 的挂载行
    sudo swapoff -a       # 热卸载原有 swap
    ```
    

## 3. 内核与调度器级优化

**背景：** 默认内核为通用场景设计，游戏需要更激进的调度以降低输入延迟和 1% Low 掉帧。

**方案：** 安装集成了 BORE (Burst-Oriented Response Enhancer) 调度器的 `linux-zen` 内核作为“游戏专属档位”。

  

- **操作：**
    
      
    
    Bash
    
    ```
    sudo pacman -S linux-zen linux-zen-headers
    ```
    
- **引导说明：** 系统搭载的 `limine-entry-tool` 守护进程已自动将新内核写入 `/boot/limine.conf`，开机时直接从 Limine 菜单选择 `linux-zen` 即可，保留了原版 `linux` 内核用于日常高稳定性开发。
    
      
    

## 4. 显卡驱动与兼容层优化

**背景：** Valve 官方 Proton 偏保守，需开启 DLSS/FSR 和底层 I/O 提权。

  

- **安装 GameMode & MangoHud:**
    
      
    
    Bash
    
    ```
    sudo pacman -S gamemode lib32-gamemode mangohud lib32-mangohud
    ```
    
- **安装 GE-Proton:** 通过 `ProtonUp-Qt` 图形化工具下载了最新版的 `GE-Proton`，并在 Steam 《永劫无间》属性中强制套用。
    
      
    
- **VRAM 策略（重要备忘）：** 未在 BIOS 中强行锁定 4GB UMA Frame Buffer，以保留足够的物理内存给日常 Java Spring/容器开发。游戏时依赖内核的 GART 动态显存分配。
    
      
    

## 5. 屏幕渲染与 Wayland 缩放剥离 (核心大招)

**背景：** 3200x2000 的物理分辨率 + Hyprland 2x 缩放会直接榨干 680M 核显。

**方案：** 引入 Valve 的 Gamescope 嵌套合成器。

  

- **操作：**
    
      
    
    Bash
    
    ```
    sudo pacman -S gamescope lib32-gamescope
    ```
    
- **逻辑：** 为游戏单独创建一个 1920x1200 (16:10) 的虚拟运行环境，并通过 AMD FSR 在底层无损放大至 3200x2000 全屏，彻底解决高分屏和缩放导致的性能暴跌。
    
      
    

## 6. 系统快照与灾备

- **验证状态：** 系统底层已激活 `limine-snapper-sync`，每次 `pacman` 动作会自动生成 Btrfs 快照并注入 Limine 引导菜单。
    
      
    
- **手动快照备份：** 通过 `sudo timeshift --btrfs` 初始化并创建了改装前的手动快照，确保系统随时可回滚。
    
      
    

## 🎯 最终输出：Steam 终极启动项

在 Steam 中为《永劫无间》设定的最终 Launch Options 咒语：

  

Plaintext

```
gamescope -W 3200 -H 2000 -w 1920 -h 1200 -f -U -- gamemoderun mangohud %command%
```

_(注意：每次进入游戏后，必须将游戏内的画面分辨率手动设置为 1920x1200，并开启全屏显示，此参数才能完美闭环。)_

# Omarchy 4.0 硬件底层性能解锁记录 (进阶篇)

**核心诉求：** 突破原厂保守的 33W 功耗墙，解决 R7 6800H 睿频抢夺 Radeon 680M 显卡供电导致的游戏掉帧问题，并实现游戏状态下的全自动切换。

  

## 1. 安装底层通信模块 (解决内存保护报错)

**背景：** Linux 内核的 `STRICT_DEVMEM` 保护机制会阻止 `ryzenadj` 修改硬件寄存器，导致报错 `Unable to get memory access`。

**方案：** 安装专用的 `ryzen_smu` 内核驱动进行合法底层通信。

  

- **操作：**
    
      
    
    Bash
    
    ```
    yay -S ryzen_smu-dkms-git
    sudo modprobe ryzen_smu
    ```
    
- **开机自启配置：**
    
      
    
    Bash
    
    ```
    echo "ryzen_smu" | sudo tee /etc/modules-load.d/ryzen_smu.conf
    ```
    

## 2. 探明原厂硬件限制 (摸底测试)

**分析：** 通过运行 `sudo ryzenadj --info`，测得 Redmi Book Pro 15 2022 的出厂功耗墙极为保守：

  

- 长时功耗墙 (`STAPM LIMIT`): **~33W**
    
      
    
- 短时高负载功耗墙 (`PPT LIMIT SLOW`): **20W**
    
      
    
- _结论：团战卡顿的本质是 20W/33W 的总功耗无法同时满足 CPU 运算和 680M 核显满载。_
    
      
    

## 3. GameMode 全自动“狂暴模式”配置

**背景：** 需要在启动《永劫无间》时自动将功耗墙拉升至 54W，并关闭 CPU 睿频（将供电全数让给 GPU），并在游戏退出后恢复至省电的 33W 办公态。

**方案：** 利用 `sudoers` 免密执行权限，结合 `~/.config/gamemode.ini` 实现无缝切换。

  

- **步骤 A：配置特权免密执行**
    
    运行 `sudo visudo`，在文件末尾添加以下两行（注：`zzy` 为当前用户名）：
    
      
    
    Plaintext
    
    ```
    zzy ALL=(ALL) NOPASSWD: /usr/bin/ryzenadj
    zzy ALL=(ALL) NOPASSWD: /usr/bin/tee
    ```
    
- **步骤 B：编写自动化控制脚本**
    
    编辑 `~/.config/gamemode.ini`，在 `[custom]` 节点配置如下：
    
      
    
    Ini, TOML
    
    ```
    [custom]
    # 【启动游戏时】通知激活，拉升 54W 功耗墙，关闭 CPU 睿频
    start=notify-send -u low -a "GameMode" "GameMode Activated" "54W Unleashed, CPU Boost OFF"
    start=sudo /usr/bin/ryzenadj --stapm-limit=54000 --fast-limit=65000 --slow-limit=54000 --tctl-temp=90
    start=sh -c 'echo 0 | sudo tee /sys/devices/system/cpu/cpufreq/boost'
    
    # 【退出游戏时】通知恢复，退回 33W 办公功耗墙，开启 CPU 睿频
    end=notify-send -u low -a "GameMode" "GameMode Deactivated" "System Normal, CPU Boost ON"
    end=sudo /usr/bin/ryzenadj --stapm-limit=33000 --fast-limit=35000 --slow-limit=20000 --tctl-temp=90
    end=sh -c 'echo 1 | sudo tee /sys/devices/system/cpu/cpufreq/boost'
    ```
    

## 4. 验证与诊断方法

**干跑测试逻辑：** 无需启动大型游戏，通过在终端执行 `gamemoderun sleep 60` 伪造游戏运行 60 秒。

  

- **触发期间验证指令：**
    
      
    - 检查功耗墙是否为 54W: `sudo ryzenadj --info | grep STAPM`
        
          
        
    - 检查睿频是否被禁用: `cat /sys/devices/system/cpu/cpufreq/boost` (应输出 `0`)
        
          
        
- _预期：测试结束或主动中断后，系统应自动恢复至出厂的 33W 功耗及 `boost=1`。_
