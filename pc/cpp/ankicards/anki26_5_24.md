
# 算法

## 智者首先将天空抽象为了一个二维平面，进而将一片云朵抽象为该平面上的一个点，将一个时代抽象为该平面上的一个竖直条带，边缘平行于纵轴。

由于气候的变化，天上刮起了季风，每一股季风会刮到一个时代内的所有云朵，让它们整体平移。当且仅当一片云朵被平移，这片云朵背后的时间就在我的脑海中重现。

一开始共有 n 片云朵，都是积云。随着时间的推移，每一片云朵可能发生如下变化：

- 首次因为季风导致平移时，将会从积云变成卷云。
- 背后的时间第六次因为季风而在我的脑海中重现时，将会像袋鼠跳入坑中一样，在天空中彻底消失。

现在智者想让我判断每一片云朵是否消失，如果没有，还要计算其类型和坐标。
输入的第一行有两个正整数 $n(1≤n≤10^5)$和 $m(1≤m≤10^5)$，分别表示云朵片数和季风股数。

output:
接下来有 n 行，其中的第 i 行有两个整数 $x_i,y_i(∣x_i∣,∣y-i∣≤10^9)$，表示第 i 片云朵的初始位置。

接下来有 m 行，其中的第 i 行有四个整数 $l_i,r_i,u_i,v_i(−10^{18}≤li≤ri≤10^{18}，∣ui∣,∣vi∣≤10^9∣$，且 $u_i,v_i 不同时为 0)$，表示一股季风刮到的时代为竖直条带 $l_i≤x≤r_i$，会让时代内所有云朵的横坐标增加 $u_i$，纵坐标增加 $v_i$。
---

这道题的名字和描述非常文艺（“玉米式追忆”），但把它抽象成纯粹的算法语言后，是一道非常精妙的**均摊复杂度分析（Amortized Analysis）**与**数据结构基础应用**题。

下面我们像在集训队里讨论题目一样，一步步把这道题的内在逻辑剥离出来。


**核心知识点与前置知识**

### 1. 前置知识点

* **平衡二叉搜索树 / 有序容器**：熟练掌握 C++ 中 `std::multiset` 的使用，特别是 `lower_bound` 的区间查找以及迭代器安全的 `erase` 操作。
* **生命周期与状态追踪**：能够用结构体或多个数组记录每个独立个体的实时状态（坐标、变化次数）。

**2. 核心知识点**

* **均摊分析思想（Amortized Analysis）**：这是本题的灵魂。通过发现题目中“不可逆的生命周期上限”，将看似高复杂度的暴力模拟转化为低复杂度的满分算法。
* **坐标动态维护**：在 1D 容器中动态维护点集，并处理由于平移带来的位置重构。


**思路演进：怎么自然想出来的？**

如果我们缺乏经验，很容易陷入“如何用线段树或树状数组进行区间整体加法”的陷阱。但由于每个云朵的初始 $x$ 坐标各不相同，且每次季风只作用于一个局部区间，区间内部的云朵会移出区间，区间外部的云朵可能会在下次进来——这导致传统的高级区间修改数据结构（如带 Lazy 标记的线段树）很难直接维护这种“无规律的粒子漂移”。

这时候，我们需要回归题目本身，寻找**最核心的刚性限制**：

**Step 1：发现隐藏的“大数法宝” —— 6次必死**

题目中有一个极强的设定：

> “背后的时间第六次因为季风而在我的脑海中重现时……在天空中彻底消失。”

这句话用算法语言翻译就是：**任何一片云朵，最多只能被季风刮到 6 次。第 6 次被刮到后，它就彻底被删除了，再也不会参与后续的任何计算。**

既然每片云朵的生命周期内最多只能经历 6 次有效操作，那么所有云朵在整个看天生涯中，总共被“刮到并移动”的次数上限是多少？


$$ 6 \times n $$


由于 $n \le 10^5$，总移动次数被死死地卡在了 $6 \cdot 10^5$ 以内。这是一个非常小的数字！

**Step 2：从“区间整体修改”转变为“个体暴力修改”**

既然总共的修改次数这么少，我们根本不需要写复杂的区间懒标记。**每次季风来的时候，我们只要把在这个区间 $[l_i, r_i]$ 内部的所有云朵挨个抓出来，直接暴力修改它的坐标、增加它的计数，如果没死就再塞回去。**

因为每个云朵被“抓出来”的次数不超过 6 次，所以哪怕我们用 $O(\log n)$ 的代价去抓和塞，全套流程跑完的总时间复杂度也只有 $O(n \log n)$。

**Step 3：选择合适的“抓人”工具**

我们需要一个工具，能支持：

1. 快速找到当前 $x$ 坐标 $\ge l_i$ 的第一个云朵。
2. 顺着往后遍历，把所有 $x \le r_i$ 的云朵全部取出来并从工具里删掉。
3. 把过完季风还活着的云朵按新坐标重新放进去。

这不就是标准的 **`std::multiset`** 吗？（因为可能有多片云朵当前拥有相同的 $x$ 坐标，所以用 `multiset` 而不是 `set`）。

**Step 4：细节陷阱 —— “不要在原地踏步”**

有一个极其重要的实现细节：如果一股季风的 $u_i > 0$（横坐标右移），而我们一边遍历 `multiset` 一边把修改后的云朵塞回去，那么这片云朵挪到新位置后，可能会再次落在当前的季风范围 $[l_i, r_i]$ 内，从而在同一个回合里被重复抓住！

**解决办法**：在每股季风来临时，先用一个临时的 `std::vector` 把这一轮要渡劫的云朵全部**收集并立刻从 `multiset` 中抹除**。等区间内所有的云朵都收集完毕后，再统一进行坐标更新和重入队。


**算法思想深化：均摊与势能**

这道题是典型的势能分析法（Potential Method）的体现。我们可以认为每片云朵自带 6 点“生命值”（势能）。每次它被季风波及，就会消耗 1 点生命值，并产生 $O(\log n)$ 的计算开销。当生命值归零，它便永久消失。

在算法竞赛中，看到这种“单个元素操作几次后就会死亡/失效/被排除”**的机制（比如：去重、求 `gcd` 直到变成 1、数字不断开根号直到变成 1），就要立刻联想到**均摊暴力。不要盲目去套大树结构，往往一个简单的 `set` 或队列结合直接模拟就能优雅解决。


## 完整 C++ 代码（附详细注释）

由于本题的坐标和边界高达 $\pm 10^{18}$，务必全量使用 `long long`。

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <set>
#include <algorithm>

using namespace std;

// 定义云朵的静态和动态属性
struct Cloud {
    long long x, y;   // 当前坐标
    int shift_count;  // 被季风吹过的次数
    int type;         // 0: 积云 (Cumulus), 1: 卷云 (Cirrus), -1: 消失 (Disappeared)
};

int main() {
    // 极致输入输出优化
    ios_base::sync_with_stdio(false);
    cin.tie(NULL);

    int n, m;
    if (!(cin >> n >> m)) return 0;

    vector<Cloud> clouds(n + 1);
    // multiset 内部存储 pair<当前x坐标, 云朵的ID>
    multiset<pair<long long, int>> active_clouds;

    for (int i = 1; i <= n; i++) {
        cin >> clouds[i].x >> clouds[i].y;
        clouds[i].shift_count = 0;
        clouds[i].type = 0; // 初始全为积云
        active_clouds.insert({clouds[i].x, i});
    }

    // 临时存储当前轮次被季风刮到的云朵 ID
    vector<int> affected;

    for (int i = 0; i < m; i++) {
        long long l, r, u, v;
        cin >> l >> r >> u >> v;

        affected.clear();

        // 1. 在 multiset 中定位第一个 x >= l 的云朵
        auto it = active_clouds.lower_bound({l, 0});

        // 2. 线性扫描并收集所有满足 x <= r 的云朵
        while (it != active_clouds.end() && it->first <= r) {
            affected.push_back(it->second);
            // erase(it) 会删除当前元素并安全地返回下一个元素的迭代器
            it = active_clouds.erase(it);
        }

        // 3. 统一处理收集到的云朵，避免在同一次季风中重复触发
        for (int id : affected) {
            // 更新坐标
            clouds[id].x += u;
            clouds[id].y += v;
            // 增加重现计数
            clouds[id].shift_count++;

            if (clouds[id].shift_count s 1) {
                // 首次平移，从积云变成卷云
                clouds[id].type = 1;
            }

            if (clouds[id].shift_count >= 6) {
                // 第6次重现，彻底消失
                clouds[id].type = -1;
            } else {
                // 如果还活着，以新的 x 坐标重新注入有序集合中
                active_clouds.insert({clouds[id].x, id});
            }
        }
    }

    // 输出最终每片云朵的宿命
    for (int i = 1; i <= n; i++) {
        if (clouds[i].type s -1) {
            cout << "Disappeared\n";
        } else if (clouds[i].type s 0) {
            cout << "Cumulus " << clouds[i].x << " " << clouds[i].y << "\n";
        } else {
            cout << "Cirrus " << clouds[i].x << " " << clouds[i].y << "\n";
        }
    }

    return 0;
}

```
